# R8: デフォルト引数での前引数参照が無診断でゼロ値になる

**ステータス:** 未修正（第6ラウンド検出）
**重大度:** High

## 症状（実測: cm 0.17.0、プローブ `.tmp/bughunt6/{modifiers,verify}/`）

デフォルト引数の式が前のパラメータを参照すると、名前解決は通ってしまうが値が黙って0になる。

```cm
import std::io::println;
int f(int a, int b = a) {
    return a * 10 + b;
}
int main() {
    println("f(3)={f(3)}");   // → f(3)=30（b=0。期待は f(3)=33、または診断で拒否）
    return 0;
}
```
実測: jit O0/O2・native O0・js の全経路で`f(3)=30`（rc=0）。`check --strict`もerrors:0。`b = a`が名前解決を通過して値だけ0になる無診断の誤値で、最悪の組み合わせ。

対照: `int x = no_such_var`（デフォルト式に未定義変数）は正しく`error: Undefined variable`になる。**前パラメータ名だけがスコープ解決に成功し、値供給が欠落している**。

## 健全だった点（同ラウンドで確認）

- 部分省略（`f()`/`f(9)`/`f(9,8)`）→ `123/923/983`
- デフォルト式の関数呼び出し（`int f(int x = g())`）→ 正値（定数式限定ではない仕様のようで診断なし）
- メソッド/コンストラクタのデフォルト引数 → 正値

## 論点と方針

C++はデフォルト引数式での前パラメータ参照を禁止する。Cmの取るべき方針は2択:

1. **診断で拒否**（デフォルト式は前パラメータを参照できない）。実装が最も単純で安全。デフォルト引数のスコープ解決から呼び出し前パラメータを除外し、参照時に診断する。
2. **前パラメータ参照を正しく実装**（`f(3)`で`b=3`）。デフォルト引数補完のタイミングで実引数を参照可能にする必要があり、変換適用サイト（Y1〜Y3/Y5でcoerce系を通した箇所）と整合を取る。

無診断でゼロ値になる現状が最悪であり、最小修正は方針1。

## テスト計画

`tests/common/functions/`へ: 前パラメータ参照デフォルトが（方針1なら）診断で拒否される負のテスト、または（方針2なら）`f(3)=33`の全バックエンド値一致。既存default_argsテストの回帰。
