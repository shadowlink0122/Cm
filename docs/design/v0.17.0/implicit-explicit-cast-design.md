# 暗黙変換と明示キャストの設計整理（Z5）

## 概要

「拡大変換は暗黙・縮小/意味変化は明示`as`」という設計意図（チュートリアルvariables.mdは`double→int`を不可と明記）に対し、現実装の`types_compatible`は全数値型を相互互換として受理しており、縮小変換まで暗黙で通る。
さらに暗黙変換の「受理」と「変換命令の挿入」が分離しているため、受理されたのに変換が挿入されず、ビット再解釈のゴミ値やバックエンド分裂になる組み合わせが存在する。
stdlibには本来不要な`as`が多数あり、その一部は壊れた暗黙昇格（Y4）の回避策として書かれている。設計と実装と利用側の三者を揃えるリファクタリングが必要である。

## 現状マトリクス（let初期化文脈の実測）

| 変換 | 受理 | 実行時の値 | 評価 |
|---|---|---|---|
| int→long / short→int / int→double / int→float / float→double | 暗黙OK | 正しい | 設計どおり（拡大） |
| int literal→short/double（適合値） | 暗黙OK | 正しい | 設計どおり（リテラル適合） |
| long→int | 暗黙OK | ビット切り詰め（5000000001→705032705） | **設計違反**（縮小が無診断） |
| **double→int** | 暗黙OK | **ゴミ値・バックエンド分裂**（2.9→jit:-1342177280 / native:858993459） | **設計違反＋変換命令欠落**（fptosi未挿入のビット再解釈） |
| double→float | 暗黙OK | 丸め（正しい） | 設計違反（縮小が無診断、値は正しい） |
| int→short | 暗黙OK | ビット切り詰め（70000→4464） | 設計違反（縮小が無診断） |
| int↔uint | 暗黙OK | ビット再解釈 | 要仕様決定（符号解釈変化） |
| int→char / char→int / int↔bool / char→string | `as`必須 | — | 設計どおり（意味変化の境界は機能している） |
| 変種値→ユニオン | 暗黙OK | 正しい（Y1〜Y3のサイト除く） | 設計どおり |

二項演算の暗黙昇格（`i + d`）は受理されるが変換が挿入されず全経路で壊れる（Y4）。代入文脈のint→floatはB2で修正済みだが、**double→int代入はB2の対象外で未挿入のまま**である（Y4と同族の新規発見）。

## stdlibの`as`利用実態（127箇所）

- `(digit as double)`・`result * 10.0 + (c - 48) as double`（json/mod.cm・console/input.cm）: int→doubleは暗黙で通るため本来不要だが、**`as`を外すと混合二項演算がY4で壊れるため、事実上の回避策**になっている。
- `buf.len() as long`・`DEFAULT_BUF_SIZE as long`（io/stream系）: int→long拡大で本来不要。
- `key as int`（hashmap のジェネリックhash）・`ptr as void*`: 型消去・ポインタ変換で正当。
- 総じて「暗黙で良い拡大」への`as`が相当数あり、Y4修正後に削減可能。逆に言えば現在の`as`散在は暗黙昇格の欠陥を覆い隠しており、テストが通っている理由でもある。

## リファクタリング方針

1. **変換の意味論を1箇所に定義する**: `types_compatible`（受理判定）から数値変換を分離し、「暗黙可（拡大・リテラル適合）／要`as`（縮小・符号解釈変化・意味変化）／不可」の3値を返す`conversion_kind(from, to)`を設ける。受理と変換挿入の判断を同じ表から導く。
2. **縮小変換の段階的エラー化**: long→int・double→int/float・int→short等の縮小を警告（`as`の付与を提案）→`--strict`でエラー→既定エラーの段階導入にする（既存コードの破壊を避けるため、M3 const強制と同じ運用）。
3. **暗黙可の変換は必ず変換命令を挿入する**: 受理サイト（let/代入/引数/return/二項演算オペランド/push・フィールド等）での挿入を期待型API（infer_type_expecting）とY4修正の共通機構に載せ、「受理したのに未変換」の組み合わせを構造的に排除する。double→int（暗黙が残る間はfptosi）・二項演算昇格（Y4）はこの機構で同時に修正する。
4. **仕様の明文化**: cm_grammar.md／CANONICAL_SPEC.mdへ変換表（暗黙可・要as・不可）を記載し、チュートリアルの記述と一致させる。int↔uintの扱い（暗黙かasか）はここで確定する。
5. **stdlibのas削減**: Y4修正後、回避策の`as`（int→double系）を除去し、意図的な`as`（縮小・ポインタ・型消去）だけを残す。

## テスト計画

- regression: 変換表の全セルについて「受理/拒否」と「実行時の値」の両方を検証するマトリクステスト（受理だけ確認して値を確認しないテストが今回の見逃しの原因）。
- errorsスイート: 縮小変換のエラー化後、`int i = d;`等を`.error`テストへ追加。
