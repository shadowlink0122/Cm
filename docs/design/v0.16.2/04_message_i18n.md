# 実装設計: コンパイラメッセージの英語デフォルト化と日本語カタログ（i18n）

## 背景・課題

現在のcm CLIはヘルプ・進捗・エラーの各メッセージで英語と日本語が混在しており不自然である（例: 型エラーは英語、CLIメッセージ・helpは日本語）。
国際的な利用を想定し、デフォルトを英語に統一しつつ、日本語メッセージも選択できるようにする。

## 設計

### メッセージカタログ方式（enum + string のC++側集約管理）

- 全メッセージは `enum class MsgId` + 言語別文字列テーブルでC++側に集約する（データファイルの二重管理を避け、IDのタイプミスをコンパイルエラーにする）
- `src/common/messages/message_list.def` — ID + 英語原文の単一ソース（X-macro）。ここから enum（`message_ids.hpp`）と英語テーブル（`messages_en.hpp`）が同順生成されるため、順序ずれが起こらない
- `src/common/messages/messages_ja.hpp` — 日本語訳（`{MsgId, 訳}` のペア表）。無いIDは英語へフォールバックする
- テンプレートは `{0}` `{1}` ... のプレースホルダで動的値を受け取り、言語ごとの語順の違いに対応する（文字列連結による断片化はしない）
- 取得APIは `i18n::msg(MsgId)`（テンプレート取得）と `i18n::msgf(MsgId, args...)`（プレースホルダ置換）
- メッセージ追加は message_list.def に1行 + messages_ja.hpp に訳を1行。言語追加は messages_<lang>.hpp を作成し i18n.hpp の言語表へ登録する
- `cm help` の本文のみ `src/cli/help_<lang>.txt` のテキストファイルで管理し、CMakeの `configure_file` でビルド時に埋め込む（`{version}` / `{program}` プレースホルダを実行時置換。長文のためenum管理には不向き）

```cpp
// 使用例
std::cerr << i18n::msgf(i18n::MsgId::CliCannotOpenFile, path);
// en: "error: cannot open file: <path>"
// ja: "エラー: ファイルを開けません: <path>"
```

### 言語の決定順序

1. CLIオプション `--lang=en|ja`（最優先）
2. 環境変数 `CM_LANG=en|ja`
3. `.cmconfig.yml` の `language: en|ja`（設計05参照）
4. デフォルト: `en`

### 対象メッセージ

- `cm help` のヘルプ全文（英語版・日本語版の2種類を用意）
- CLI進捗・結果メッセージ（コンパイル完了、テスト結果、インストール案内等）
- 型チェック・構文エラーの日本語部分（「エラー」「警告」「チェック完了」等の枠組み文言）
- lint診断の説明文（L001等のルールメッセージ）
- SVコード生成・階層化・プリプロセッサのエラーメッセージ

デバッグログ（`-d` 出力）は開発者向けのため対象外とし、現状の文言を維持する。

## 段階分割

1. i18n基盤（tr関数・言語決定・カタログ構造）の追加
2. `cm help` の英語化と日本語カタログ化
3. main.cpp のCLIメッセージの英語化とカタログ化
4. 型チェッカー・lint・プリプロセッサ・SVコード生成のメッセージ英語化とカタログ化
5. テスト期待値（日本語メッセージに依存するもの）の更新

## テスト計画

- unit: `tests/unit/` にi18nカタログのテスト（en/ja切替・未登録キーのフォールバック）
- integration: `cm help` / `cm help --lang=ja` の出力検証、`CM_LANG=ja` での主要メッセージ確認
- 既存テストが日本語メッセージ文字列に依存している箇所を英語デフォルトに追従

## 互換性

- 既定言語が日本語から英語に変わるため、メッセージ文字列に依存する外部スクリプトには影響がある（リリースノートに明記）
- 終了コード・出力ファイルの内容は不変
