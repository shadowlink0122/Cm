# v0.16.0 SVバックエンド拡充ロードマップ

作成日: 2026-07-06対象: v0.16.0（SVバックエンドの機能充実をテーマとするマイナーバージョン）

本文書は3つの調査結果をまとめたものである。

1. Verilog/SystemVerilogのうちSVバックエンドが表現できていない構文・未実装機能の棚卸し
2. 合成ツール用ファイル（Gowin .tcl / .cst）のCm統合の設計検討
3. v0.16.0の優先実装計画

---

## 1. Verilog構文ギャップ分析

### 1.1 対応済み（v0.15.1時点の到達点）

module/ポート宣言（input/output/inout・配列ポート）、`always @(posedge/negedge)`・組み合わせ回路（`@(*)`、MIR解析によるラッチ推論）、非同期リセット（複数エッジ感度）、if/case（switch）、三項演算子、whileループ再構成（disable方式）+定数ループ静的展開（generate相当）、enum typedef（明示タグ幅）、localparam（const）、配列と`#[sv::bram/lutram]`、`$readmemh`/initialブロック、連接`{a,b}`/複製`{N{a}}`、即時アサーション、サイズキャスト`N'()`、符号付き演算（`$signed`/`>>>`）、モジュール階層（`//! sv: hierarchy` Stage 2、named port connection）、テストベンチ自動生成、import/exportフラット化、多重クロックドメイン。

### 1.2 未対応構文・機能（優先度分類）

#### A. 合成実務でほぼ必須（v0.16.0の中核候補）

| # | 機能 | 現状 | 備考 |
|---|---|---|---|
| A1✅ | **モジュールパラメータ** `#(parameter WIDTH=8)` | 未実装（missing_features項目2） | パラメタライズドIPの中核。ジェネリック構造体 `Fifo<WIDTH>` からの写像が自然 |
| A2✅ | **階層Stage 3**: 複数モジュールMIR・パラメータ付きインスタンス | Stage 2まで | A1と一体で設計すべき |
| A3✅ | **トライステート**: `'z` 駆動・ハイインピーダンス代入 | inout宣言のみ可、'z が書けない | I2C等の双方向バスに必須。`z` リテラル or `#[sv::tristate]` |
| A4✅ | **ビットスライス構文**: `x[7:4]` / `x[i +: 8]` の読み書き | ユーザー構文なし（内部生成のみ） | Cm側の言語構文追加が必要（range型 or メソッド） |
| A5 | **インスタンス配列 / generate-instance** | 不可 | 定数ループ展開はインスタンス化に非対応 |
| A6 | **デュアルポートBRAM推論**（1W1R/2ポート） | 単純配列のみ | 書き込み/読み出しの2クロック分離パターン認識 |

#### B. 品質・安全性（コンパイラとしての差別化）

| # | 機能 | 現状 | 備考 |
|---|---|---|---|
| B1✅ | **CDC同期化プリミティブ** | なし（項目8） | `#[sv::sync(2)]` で2FF同期生成。クロックドメイン推論と組で警告も |
| B2✅ | **casez / don't care マッチ** | case完全一致のみ | match式のワイルドカードパターン→casez写像 |
| B3✅ | **unique / priority case** | なし | match網羅性検査済みなら `unique case` を安全に出せる |
| B4 | **WIDTH系lint警告の解消** | 抑止中（実デザイン約1,900件） | 幅推論の拡充→`--sv-strict-lint`デフォルト化 |
| B5 | **string長の型化**（24bit固定解消） | 3文字超で自動拡幅のみ | 項目4案1 |
| B6 | **SVA** `assert property` | 即時アサーションのみ | クロック付き時相検証 |

#### C. 対象外と明記するもの（合成外・ニッチ）

`force/release`、`specify`ブロック、UDP、信号強度、`fork/join`、イベント`->`、`real`型ポート、DPI-C、SV interface/modport（Cmのinterfaceとは別物。階層+構造体で代替）、遅延`#10`（テストベンチ生成内でのみ使用）。これらは「サポートしない」とドキュメントで宣言し、検出時は明示エラーにする。

### 1.3 ベンダープリミティブ（PLL等）

`extern struct` によるインスタンス化で原理的には可能だが、パラメータ渡し（A1/A2）がないため実用に達していない。A1完了後に rPLL/OSC 等の実例をチュートリアル化する。

## 2. tcl / .cst ファイルのCm統合検討

### 2.1 現状の実態（CmCPUでの運用）

- **.cst（物理制約）**: `IO_LOC "led_ready" U12;` + `IO_PORT "led_ready" IO_TYPE=LVCMOS33 DRIVE=8;`の羅列。**エントリはCmのポート宣言と1:1対応**しており、ポート名変更のたびに手動同期が必要（現に信号名の不整合バグの温床になっている）
- **.tcl（プロジェクトスクリプト）**: デバイス型番・ソースファイルパス・topモジュール名・合成オプション（`use_ready_as_gpio` 等）・`run all`。**ファイルパスとtop名はcmの出力に依存**しており、これも手動同期

### 2.2 設計案の比較

| 案 | 内容 | 利点 | 欠点 |
|---|---|---|---|
| 案1: 現状維持 | 別ファイルを手書き | 実装コスト0、ツール固有機能を全部使える | ポート名・パス・top名の手動同期が壊れやすい |
| 案2: 完全内包 | ピン・デバイス情報をすべてCm属性化し .cst/.tcl を生成 | 単一情報源、リネーム安全 | ツール固有オプションの網羅は不可能。エスケープハッチ必須 |
| 案3: **ハイブリッド（推奨）** | ポート結線・デバイス宣言はCmに書き、`--emit-constraints` で .cst/.tcl を**生成**。手書きファイルの継続使用も可 | 同期エラー消滅・段階導入可・生成物を出発点に手編集も可能 | 生成と手書きの二重管理をドキュメントで律する必要 |

### 2.3 推奨設計（案3）の具体形

ポートに物理属性を付与（`#[sv::memfile]` と同じ属性系の自然な拡張）:

```cm
//! platform: sv
//! sv: device: GW5AST-LV138PG484AC1/I0 C
//! sv: option: use_ready_as_gpio
//! sv: option: use_done_as_gpio

#[input]
#[sv::pin("T10")]
posedge clk;

#[output]
#[sv::pin("U12", io_type: "LVCMOS33", drive: 8)]
bool led_ready = false;
```

- `cm compile --target=sv --emit-constraints` で `<top>.cst` と `<top>_build.tcl` を併産
  - .cst: `#[sv::pin]` 付きポートから `IO_LOC`/`IO_PORT` 行を生成
  - .tcl: device/optionディレクティブ + 生成SVパス + top名 + `add_file <top>.cst` + `run all`
- **ピン割り当ては定数ではなく属性とする**（値として演算する需要はなく、ポート宣言との物理的な同居が同期エラーを構造的に防ぐため）
- ボード定義の再利用は「ボードファイル」で対応: `//! sv: board: ./boards/tang_console_138k.cm` — ピン名→物理ピンの対応表をconstで持つCmファイルを参照し、`#[sv::pin(board::LED_READY)]` のように使う（第2段階）
- タイミング制約（SDC）は本設計の枠外とし、v0.16では生成対象にしない（クロック定義のみ `//! sv: clock: clk 50MHz` → SDC生成を検討課題として残す）

**個別ファイルとして残すべきもの**: ベンダツールの細かなオプション（電圧・温度グレード、配置制約等）を書き込んだ既存 .tcl/.cst 資産。生成機能はオプトインであり、`--emit-constraints` を使わない限り従来運用に影響しない。

## 3. v0.16.0 実装計画（優先順）

| 優先 | 項目 | 根拠 |
|---|---|---|
| 1 | A1+A2: モジュールパラメータ + 階層Stage 3 | パラメタライズドIPが書けないことが現在最大の表現力制約。ジェネリクス→#(parameter)写像 |
| 2 | 2.3: `#[sv::pin]` + `--emit-constraints`（.cst/.tcl生成） | CmCPU実運用の手動同期バグを構造的に解消。実装コストは小〜中 |
| 3 | A3: トライステート（'z）+ B1: CDC同期プリミティブ | 双方向バス・実基板I/Oの必須要素（missing_features項目8） |
| 4 | A4: ビットスライス構文 | 言語構文の追加を伴うため設計レビュー先行 |
| 5 | B2+B3: casez / unique case | match式資産の写像で比較的低コスト |
| 6 | B4: WIDTH警告解消 → strict-lintデフォルト化 | 継続的改善（v0.15.1で計測基盤済み） |
| 7 | A5/A6/B5/B6 | 上記完了後、需要に応じて |

セクションCの「サポートしない構文」は早期にドキュメント宣言+明示エラー化する（工数極小で期待値管理の効果が大きい）。
