# B3: must{}内の構造体フィールド代入の誤コンパイル

## 対象バグ

| # | 領域 | 概要 | 重大度 | 状態 |
|---|------|------|--------|------|
| B3 | must文 | must{}ブロック内の構造体フィールド代入が別の一時allocaへ書かれ、後続読み出しが0になる誤コンパイル | Critical | 修正済み |

## 再現コード

```cm
struct Rect { int w; int h; int area; }

int main() {
    Rect r = Rect { w: 19, h: 58, area: 0 };
    must { r.area = r.w * r.h; }
    return r.area;  // 期待: 1102 実際: 0
}
```

## 現象

must{}ブロック内でのフィールド代入が変数本体でなく初期化用の別一時allocaへ書かれ、ブロック外の読み出しが初期化時の値を返す。
構文→LLVM IR対訳リファレンスのstructs検証で検出した（must無しなら正常に1102）。

## 根因（確定）

MIR loweringのplace解決はmust内外で同一経路であり、lowering自体は正しいMIR（`[must] _1.2 = ...`）を生成していた。
誤コンパイルの実体はMIR最適化パスにあり、CopyPropagation・ConstantFolding・DSEがno_opt文を「処理スキップ」する際に、その文の書き込み・読み出しを追跡情報の無効化にも反映していなかった。
具体的には `Rect r = Rect{...}` のloweringで `r = copy(_t)`（_tは初期化用一時）が生成され copies[r]=_t が記録されるが、must内のフィールド代入 `[must] r.2 = ...` はプロジェクション付きのためコピー情報が無効化されず、ブロック外の読み出し `r.2` が `_t.2`（初期値0）へ付け替えられていた。

## 修正方針

- no_opt文は「書き換え・削除の対象外」とするが、追跡情報に対しては通常の文と同じ書き込みバリアとして扱う
- CopyPropagation: no_optの代入はプロジェクション付きでもベース変数のコピー情報（当該変数を指すエイリアス含む）を無効化し、デリファレンス書き込みは全コピー情報をクリアする
- ConstantFolding: 同様にno_optの代入でベース変数の定数情報を無効化し、デリファレンス書き込みは全定数情報をクリアする
- DSE: no_opt文内の読み出しを使用として収集し、直前の定義がデッドストア扱いで削除されるのを防ぐ（フィールド・配列要素代入も追跡から外す）

## テスト計画

- tests/common/へmust内でのフィールド代入・配列要素代入・スカラ代入後にブロック外で読み出すケースを追加し、O0とO2以上の両方で検証する
- mustの本来目的（DCE/DSE抑止）が退行しないことを既存mustテストで確認する
