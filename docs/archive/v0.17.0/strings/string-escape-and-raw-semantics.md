# R5: 文字列エスケープの黙殺・raw文字列のエスケープ解釈・補間エスケープ不能

**ステータス:** 修正済み（エスケープ表の実装＋未知エスケープ診断＋raw文字列の非エスケープ化＋`\$`対応。バグ1〜4全件処置）
**重大度:** High（`\x`/`\u`黙殺）/ Medium（raw非raw・補間エスケープ）

## 症状（実測: cm 0.17.0、プローブ `.tmp/bughunt6/syntax2/`）

### バグ1【High】`\x`/`\u`/`\U`・未知エスケープでバックスラッシュが黙って脱落し誤った文字列を生成

`src/internal/syntax/lexer/lexer.cpp`の`scan_escape_char()`は`\n \t \r \\ \" \' \0`のみ対応。default節が後続文字をそのまま返すため、未知エスケープはバックスラッシュだけ黙って消える。

| 入力 | 期待 | 実出力（jit O0/O2・native O2・wasm・js 全一致） |
|---|---|---|
| `"\x41"` | `A`（len=1） | `x41`（len=3） |
| `"é"` | `é` | `u00e9`（len=5） |
| `"\U0001F600"` | 😀 | `U0001F600`（len=9） |
| `"\q"` | 診断 | `q`（無診断、--strictでもerrors:0） |

`--strict`でも一切診断されない黙殺。パス文字列・バイナリデータ・テスト期待値が静かに壊れる。UTF-8直書き（`"é"`）は`len()`=1/`byte_len()`=2と正しく整合しているため、`\x`系エスケープ経路だけの欠落。

### バグ2【Medium】文字列とcharリテラルでエスケープ挙動が不一致

`"\x41"`は黙って受理される（誤値）が、`'\x41'`（charリテラル）は構文エラー`Expected ';'`（rc=1）。同じエスケープが文字列とcharで黙殺/エラーに分裂。

### バグ3【Medium】raw文字列（バッククォート）がrawでない

Cmのraw文字列は`r"..."`ではなくバッククォート`` `...` ``（`r"..."`/`r#"..."#`は構文エラーで拒否）。しかし`scan_raw_string()`が`\`で`scan_escape_char()`を呼ぶため、`` `C:\path\n` ``の`\n`が実改行になり、未知エスケープ`\p`はバックスラッシュが脱落する。実測: `` `C:\path\n` ``→`C:path`+実改行（len=7、期待は9文字リテラル）。全経路一致。raw文字列の「エスケープ無効」という語義に反する。

### バグ4【Medium】補間のバックスラッシュエスケープが不能

`"\${x}"`はリテラル`${x}`を出すべきところ補間される（→値）。`"$\{x}"`では`$`が黙って消失。通常文字列でリテラル`${x}`を得る自然な手段がなく、裏技`"$$\{x}"`のみ。`\{`は正しくエスケープされるため`$`側の扱いだけ欠落。全経路一致（レキサ段の問題）。

## 修正方針

- `scan_escape_char()`へ`\xHH`/`\uHHHH`/`\UHHHHHHHH`のデコードを実装（UTF-8エンコードして格納）。未知エスケープは診断で拒否（黙って`\`脱落を廃止）。文字列とcharで同一のエスケープ表を共用する（B6のcharリテラル構文エラーも解消）。
- raw文字列（バッククォート）は`\`をエスケープ処理せずリテラルとして格納する（`scan_raw_string`から`scan_escape_char`呼び出しを外す）。補間`${}`のみ特別扱いを維持。
- 補間の`\$`をリテラル`$`のエスケープとして認識する。

## テスト計画

`tests/common/formatting/`（またはstrings）へ: `\x`/`\u`/`\U`の正しいデコードと`len()`/`byte_len()`整合・未知エスケープの診断・raw文字列のバックスラッシュ保持・`\${x}`のリテラル出力を全バックエンド一致で。charリテラルの`'\x41'`受理。

## 実装記録

- **バグ1（`\x`/`\u`/`\U`・未知エスケープの黙殺）**: レクサの`scan_escape_char()`を`scan_escape_sequence()`（文字列返し）へ置換し、`\xHH`（1バイト）・`\uHHHH`/`\UHHHHHHHH`（UnicodeコードポイントのUTF-8エンコード。サロゲート・0x10FFFF超は不正）をデコードするようにした。仕様書`cm_grammar.md`のescape_sequenceは元々これらを含んでおり、実装が欠けていた仕様乖離の解消でもある。C標準の`\b`/`\f`/`\v`/`\a`も追加（stdlibの`std::json`が`"\b"`/`"\f"`をバックスペース/フォームフィードのつもりで使っており、旧レクサでは文字`b`/`f`に化ける潜在バグだったのを同時に治した）。未知エスケープはi18n診断（対応一覧つき）で拒否する。診断の伝搬は、レクサがメッセージ付き`TokenKind::Error`トークンを発行→パーサが`parse()`冒頭で診断へ変換しトークン列から除去する方式（レクサ・パーサ間の新チャネル不要で位置情報つき）。
- **バグ2（charリテラルとの不一致）**: `scan_char`が同じ`scan_escape_sequence()`を共用し、`'\x41'`が受理される。複数バイトへデコードされるエスケープ（`'\u00e9'`等）は専用診断で拒否（1バイトのcharに収まらないため）。
- **バグ3（raw文字列がrawでない）**: `scan_raw_string`からエスケープ処理を全廃し、バックスラッシュをリテラル保持する。唯一の例外はデリミタのエスケープ`` \` ``（バッククォート自体の埋め込み手段。既存テストbacktick_stringの挙動も維持）。`${}`補間は従来どおり有効で、プレースホルダ内のコードもそのまま保持し式解釈は後段に委ねる。
- **バグ4（`\${x}`不能）**: `scan_string`が`\$`を認識し、直後の`{...}`グループ全体を波括弧二重化でリテラル化する（格納形は`${{x}}`）。MIRの`extract_named_placeholders`が`${{`のとき`$`を落としていた問題も修正し（従来は`\${x}`→`{x}`と`$`が消えていた）、`"\${x}"`がリテラル`${x}`を出力する。デコード結果が波括弧になる`\x7B`/`\x7D`も二重化して補間誤認を防止。
- **仕様書**: `cm_grammar.md`のraw_string_literalを実態（バッククォート・`` \` ``のみエスケープ）へ修正し（旧記述の`r"..."`/`r#"..."#`は受理されない誤り）、escape_sequenceへ`\0` `\$` `\{` `\}`を追記。
- **VSCode拡張**: ESCAPE_RULEを「対応エスケープ=エスケープ色・未知の`\.`=不正色（診断と整合）」の2段へ、charリテラルの複数文字エスケープ対応、raw文字列の`` \` ``エスケープ着色を追加し、`npm run build:grammar`で再生成（トークナイズテスト42件PASS）。
- **テスト**: `tests/common/formatting/escape_sequences.cm`（\x/\u/\Uデコードとlen/byte_len整合・\b\f\v・char共用・raw保持・`` \` ``・`\${x}`リテラル、全バックエンド一致）、`tests/common/errors/`へ未知エスケープとcharマルチバイトの診断2本、i18n en/ja 2ケース。unit/regression/interpreter/llvm/wasm/js/ts/sv/libs/cm-testの全スイートPASS。lexer_testターゲットへCM_I18N_SOURCESをリンク追加。
- **チュートリアル**: `advanced/strings.md`（ja/en）へエスケープ表とraw文字列の節を新設、`basics/string-interpolation.md`（ja/en）へ`\$`エスケープを追記。
- **残課題**: 通常文字列の`"$\{x}"`表記（`$`+個別波括弧エスケープ）の挙動は`\${x}`の正式サポートにより非推奨経路として残置。補間で挿入した実行時値の波括弧再スキャン（R24）は別件。
