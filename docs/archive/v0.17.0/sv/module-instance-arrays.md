# SV-N5: モジュールインスタンス配列・位置ベースポート接続

**分類:** 新機能（構造）
**優先度:** Medium
**ステータス:** 実装済み（v0.17.0）

## 現状（実測: cm 2026-08-08ビルド）

- サブモジュールのインスタンス化は「exportされたIO構造体」経由で**単一インスタンス**のみ生成できる（`analyze.cpp:353`が単一インスタンス名前提）。
- **インスタンス配列**（同一サブモジュールをN個並べる `sub u_sub [N-1:0] (...);`）は生成できない。
- ポート接続は常に**名前付き**（`.clk(clk), .din(sig)`）のみで、**位置ベース接続**（`sub u(clk, din, dout)`）は非対応（`analyze.cpp:315,338`）。

N個の同一処理要素（PE配列・並列レーン・多チャンネル）を並べる設計が、ループでインスタンス名を変えて書けず表現できない。

## 提案

1. **インスタンス配列**: サブモジュールIO構造体の配列（`SubIO[N] lanes;`のような表現）から、SVのインスタンス配列 `sub u_lanes [0:N-1] ( .clk(clk), .din(din), .dout(dout) );` を出力する。各ポートの接続はベクタ結線（配列信号の対応スライス）で解決する。SV-N4（generate-for）内での反復インスタンス化とどちらを正とするか設計する（generate-forの方が接続の自由度が高い。インスタンス配列は等幅一括結線向け）。
2. **位置ベースポート接続**（任意・低優先）: 名前付き接続が既定で堅牢なため、位置ベースは必須ではない。外部IP（extern struct）でポート名がSV側と一致しない場合の回避策として検討に留める。

## 実装方針

- インスタンス生成経路（`analyze.cpp:249-371`）を、IO構造体が配列（または`#[sv::count(N)]`のような反復属性）を持つとき、インスタンス配列宣言＋ベクタ結線を出力するよう拡張する。
- ポート信号の幅整合（N個ぶんのベクタ or 個別信号）を型解決で検査し、不整合はSV007で停止する。
- generate-for（SV-N4）と機能重複するため、まずはgenerate-for内インスタンス化を優先実装し、インスタンス配列は等幅一括結線の糖衣として後続で追加してもよい（README優先度はMedium）。

## テスト計画

`tests/sv/hierarchy/` へ: N個の同一サブモジュール（例: 1ビットPEをN個並べた加算器/並列XORレーン）がインスタンス配列またはgenerate-forで生成され、iverilogで各レーンの独立動作を値検証。単一インスタンス（既存`hier_top.cm`）が回帰しないことを確認。

## 実装記録（2026-08-11）

提案1（インスタンス配列）を`#[sv::instance_array(N)]`属性で実装した。

- **表現**: 既存の単一インスタンス構文（exportされたIO構造体のグローバル変数+structリテラル結線）へ属性を付ける形とし、型システムの変更なしで実現した。Nはリテラルまたは`#[sv::parameter]`のパラメータ名。
  ```cm
  #[sv::instance_array(2)]
  pe_xor::PeXorIo lanes = pe_xor::PeXorIo { a: pa, b: pb, r: pr };
  ```
- **出力**: generate-for（`genvar __gi_lanes; generate for (...) begin : lanes_gen ... end endgenerate`）として出力する。設計判断のとおりgenerate-for内インスタンス化を正とした（インスタンス配列構文`u [N-1:0]`でなくgenerate-forの方が結線の自由度が高い）。
- **結線規則**: 結線先が配列信号（非bit要素のモジュールスコープ配列）ならgenvar添字`[__gi_<name>]`で各レーンへ分配し、スカラ信号はそのまま全レーンへブロードキャストする（等幅一括結線）。
- **検証**: `tests/sv/hierarchy/inst_array_top.cm`+`pe_xor.cm`（2レーンXOR PEの分配・ブロードキャスト・レーン独立動作のシミュレーション値検証SIM_OK・verilator lint通過）。SVスイート全数PASS。
- **位置ベースポート接続（提案2）の見送り**: 名前付き接続が既定で堅牢であり、文書の検討どおり必須でないため見送りとする（外部IPのポート名不一致は`#[sv::module_name]`と同様の属性対応を需要発生時に検討）。
