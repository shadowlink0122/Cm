# ジェネリック構造体リテラルの構築不能

## 概要

ジェネリック構造体を構造体リテラルで構築する手段が存在しない。
明示型引数付きリテラル（`Box<int>{v: 7}`）は構文エラー、型引数なしリテラル（`Box{v: 7}`）と無名リテラル（`{v: 7}`）は宣言型からの型推論が行われず型不一致エラーになる。
既存テストは全て「宣言＋フィールド個別代入」（`Pair<int> p; p.first = 100;`）で回避しており、リテラル構文の網羅検証から漏れていた。

## 再現コード

```cm
struct Box<T> { T v; }
struct Pair<A, B> { A first; B second; }

int main() {
    Box<int> a = Box<int>{v: 7};                          // 構文エラー: Expected expression（'<'以降が式として解析される）
    Box<int> b = Box{v: 7};                               // 型エラー: expected 'Box<int>', got 'Box'
    Pair<int, string> p = {first: 7, second: "seven"};    // 型エラー: expected 'Pair<int, string>', got 'Pair'
    return 0;
}
```

## 現象

| 記法 | 結果 |
|---|---|
| `Box<int>{v: 7}` | 構文エラー（`Box < int > {v: 7}`の比較式として誤解析） |
| `Box{v: 7}` | 型検査エラー（specializationへの推論なし） |
| `{v: 7}`（無名） | 型検査エラー（宣言型`Box<int>`との照合なし） |
| `Pair<int, string> p; p.first = 7;` | 動作する（現状の唯一の構築手段） |

const宣言では無名リテラル（`const Item item = {value: 42};`）が非ジェネリック構造体で動作するため、ジェネリックでの非対応は一貫性を欠く。

## 根因候補

式位置の`識別子<`はパーサが常に比較演算子として解析し、構造体リテラルの型名部分に型引数リストを受理する経路がない（型位置の`Box<int>`は5a725e0でスライス型引数対応済みの`parse_type`が処理するが、式のリテラル頭は別経路）。
型引数なしリテラルは`lower_struct_literal`が非ジェネリックの構造体表を名前で引くため、`Box`という未特殊化名のまま型が付き、宣言型`Box<int>`との照合・推論が行われない。

## 修正方針

2段構えで対応する。
第1段（推論・小さい修正）: 構造体リテラルの型検査で、期待型（宣言・代入・引数・returnの文脈型）がジェネリック特殊化のとき、リテラルの裸名が基底名と一致すれば期待型の特殊化として解決する（`Box{v: 7}`と無名`{...}`が動くようになる）。
第2段（明示構文）: 式位置の`識別子<型引数列>{`を先読みで構造体リテラルとして受理する（`<`の後に型が続き`>`と`{`で閉じる場合のみリテラル解析へ分岐し、比較式との曖昧性はバックトラックで解決する）。
第1段だけでも実用上の構築手段が揃うため、第2段はパーサの曖昧性リスクを評価してから導入する。

## テスト計画

- 単一型引数・複数型引数・ネスト特殊化（`Box<Pair<int, string>>`）のリテラル構築を宣言・代入・関数引数・returnの4文脈で検証する
- 明示型引数構文を導入する場合は、比較式（`a < b > c`のような曖昧列）が従来どおり解析されることの回帰を追加する
- 全バックエンドスイートで実行し、モノモーフ化（C7/C8/C9のtypekey）との整合を確認する

## 解決記録（第1段実装済み、明示構文は将来）

第1段（期待型推論）を実装した。
変数宣言の型検査（stmt.cpp）で、宣言型がジェネリック特殊化（type_argsあり）かつ初期化式が構造体リテラルで裸名が基底名と一致（または無名）の場合、リテラルへ宣言型を採用して型不一致を解消する。
`Box<int> b = Box{v: 7}` / `Pair<int, string> p = Pair{...}` / 無名`= {...}`の3形態が構築可能になった。
第2段（明示型引数構文`Box<int>{...}`）は式位置の`<`の比較演算子との曖昧性解決（バックトラック）が必要なため、将来課題として残す（回避形が揃ったため実用上の支障はない）。
回帰テスト tests/common/generics/struct_literal_inference.cm をjit/native/js/wasmで検証した。
