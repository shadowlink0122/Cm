# 多次元配列の低次元部分配列返却（宣言パース・次元検査・要素コピー）

## 要求

`int[3][3][3] a;` のような多次元配列・スライスから、`int[3] b = a[2][1];` のように低次元の部分配列を取り出せること。
任意の要素型（プリミティブ・string・構造体・ジェネリック）の配列・スライスに対応し、`auto b = a[2][1];` の推論も働くこと。

## 型宣言の意味論（調査で確定）

配列サフィックスは左から積む: `int[2][3]` は「`int[2]` が3個」であり、`m[i]`（iは0..2）は `int[2]` を返す。
LLVM上の表現は `[3 x [2 x i32]]` で、既存のフラット化GEP・多次元リテラル・書き込み経路はこの解釈で一貫している。

## 実測と実装（2026-08-05）

### もともと動作していたもの

- 正方・非正方の組み込み型多次元配列（`int[3][3][3]`・`int[2][3]`・`double[3][2]`・`long[3][2]`等）の正しい型付けでの部分取り出し・`auto`推論・値セマンティクス（コピー）・関数引数/戻り値。
- `string[2][2]` 等の組み込み型キーワードの多次元、スライスofスライス（`int[][]`〜`int[][][]`）の任意深さの部分取り出しと`auto`。

### 実装1: ユーザー定義型・ジェネリック型の多次元宣言パース

`Point[2][2] grid;` / `Box<int>[2][2] g;` が「Expected ';'」になっていた（`int[2][2]`は型キーワード経路のため通る）。
文頭の宣言判別（parser_stmt.cpp）が `Ident [N]` サフィックスを1個しか先読みせず、2個目の `[` で添字式と誤判別していた。
判別の配列サフィックス読みを「整数リテラルまたは空のブラケット連鎖」のループへ拡張した（ジェネリック分岐 `Type<T>[N]` も同様）。
添字が整数リテラル以外（`arr[i]`）は型サフィックスとみなさないため、変数への添字式との曖昧性は生じない。

### 実装2: 固定長配列同士の要素数不一致を型エラー化

`int[2][3] m; int[3] wrong = m[1];`（`m[1]`の実体は`int[2]`）が無診断で受理され、行コピーがゴミ値になっていた。
types_compatibleの配列同士の比較が無条件trueだったため、「両者が固定長で要素数が異なる」場合をfalseにした（`Type mismatch in variable declaration 'wrong': expected 'int[3]', got 'int[2]'`）。
空リテラル（要素数0）による初期化・固定長↔スライス（どちらかが未サイズ）の変換経路は従来どおり許容する。
要素型の厳格比較はジェネリック互換（`T[]`引数等）への影響が大きいため従来のまま据え置いた（将来課題）。

### 実装3: スライスof固定長配列の要素コピー

`int[2][] grid; int[2] got = grid[0];` がゴミ値になっていた（直接読み`grid[0][0]`は正しい）。
単一添字のスライス読み（expr/access.cpp）が「要素型がArray」を一律`cm_slice_get_subslice`（インラインスライスヘッダ用）へ倒しており、Y6でインラインblob格納に統一された固定長配列要素では返却ポインタをデリファレンスせずスロット自体を読んでいた。
固定長配列要素は構造体・ユニオンと同じ`cm_slice_get_element_ptr`+デリファレンスコピーへ分岐させた（`auto`推論も併せて動作）。

### 実装4: jsバックエンドの固定長配列の値セマンティクス

jsで`int[3] x = y;`・`int[3] b = a[1];`（部分取り出し）が参照共有になり、`b[0]=99`が元配列へ波及してLLVM系（コピー）と分裂していた（1次元を含む既存の分裂で、H3の構造体クローンが配列に未適用だった）。
emitOperandのCopyで、Index/Deref射影を型で辿った結果が固定長配列（array_size付き）の場合に`__cm_clone`を挿入するようにした。
スライス（未サイズArray）は参照セマンティクスのためクローンしない。Field射影経由は従来挙動を維持する（対象を限定した段階導入）。

## 回帰テスト

- `tests/common/arrays/multidim_partial_extract.cm`: 正方/非正方×{int, double, long, string, 構造体}×{2D, 3D}×{行コピー, auto, 関数境界, 値セマンティクス}と、スライスofスライス・スライスof固定長配列の要素コピー（jit/native/wasm/js/tsの出力一致）。
- `tests/common/errors/multidim_dim_mismatch.cm`: 要素数不一致の行コピーが型エラーになることを固定。

## 将来課題

- 配列同士の要素型の厳格比較（`int[3] = string[3]`等は現在も素通り。ジェネリック互換`T[]`の判定整理と併せて段階導入する）。
- js固定長配列クローンのField射影経由（構造体フィールド内の固定長配列の取り出し）への拡張。
