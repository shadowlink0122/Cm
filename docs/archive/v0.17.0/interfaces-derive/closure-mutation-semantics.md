# R4: クロージャの外側変数書き込みが黙殺・構造体キャプチャがjsだけ伝播

**ステータス:** 修正済み（方針1=書き込み診断拒否を採用）
**重大度:** High

## 症状（実測: cm 0.17.0、プローブ `.tmp/bughunt6/{syntax2,verify}/`）

### バグ1【High】クロージャからの外側変数への代入が全経路で黙って棄却される

```cm
import std::io::println;
int main() {
    int x = 1;
    const void*() f = () => { x = 42; };
    f();
    println("after call: {x}");   // → after call: 1（期待42）
    return 0;
}
```
実測: jit O0/O2・native O0〜O3・wasm・js の全経路で`after call: 1`（rc=0）。`check`/`--strict`も0件。一方、読み取りは参照的で、キャプチャ後に外側で値を変えてから呼ぶと最新値が読める。つまり**「読みは最新値・書きは無効」の非対称**で、書き込み棄却に警告すら出ない。ユーザーの状態更新が黙殺される。

### バグ2【High】構造体のキャプチャ書き込みがjsバックエンドだけ伝播する

```cm
Point p = {x: 10, y: 20};
const void*() setter = () => { p.x = 100; };
setter();
println("p.x = {p.x}");
```
実測: jit/native/wasm → `p.x = 10`、**js → `p.x = 100`**（rc=0）。読み取り（`p.x + p.y`→30）は全経路一致。jsは構造体をJSオブジェクト参照で捕捉するため書き込みが伝播し、他バックエンドはコピーを捕捉する。観測可能な値がバックエンドで分岐する黙殺バグ。

### 健全だった点

キャプチャ付きクロージャのスライスpush（`fs.push(() => i)`）はV5〜V7で導入した診断`Cannot push a capturing closure into a slice...`で正しく拒否される。参照キャプチャ構文`[&x]`は未実装（R15参照）。

## 論点と方針

Cmのクロージャキャプチャは「値キャプチャ（コピー）」が正準で、V5〜V7でキャプチャ付きクロージャのユーザー関数への引き渡しは診断エラー化された。しかし**同一関数内で生成・呼び出すクロージャからの外側変数への代入**は診断対象外のまま黙殺されている。取るべき方針は2択:

1. **書き込みを診断で拒否**（値キャプチャは読み取り専用と明確化）。V5〜V7の延長線で一貫。バグ2のjs分岐も同時に解消（診断で拒否されるため）。
2. **参照キャプチャ`[&x]`を実装して書き込みを可能にする**（R15の未実装構文と併せて）。より大きな機能追加。

最小の一貫性回復は方針1。バグ2のバックエンド分岐は「値キャプチャなのにjsだけ参照」という実装差なので、いずれの方針でも全バックエンドの捕捉戦略を揃える必要がある。

## テスト計画

方針決定後、`tests/common/lambda/`（またはclosures）へ: 外側変数への代入の扱い（診断 or 参照伝播）が全バックエンド一致・構造体キャプチャ書き込みのバックエンド一致の回帰。

## 実装記録

方針1（値キャプチャは読み取り専用と明確化し、書き込みを診断で拒否）を採用した。V5〜V7の「キャプチャ付きクロージャの引き渡し診断」と同じ路線で、動いたことのない書き込みを診断化するため非破壊。

- **checker（`src/internal/types/checking/expr/lambda.cpp`）**: `infer_lambda`のキャプチャ解析に書き込み検出を追加。代入・複合代入（`ast::is_assign_op`を`expr.hpp`へ新設）・前置/後置インクリメント/デクリメントの対象式から基底識別子を求め（メンバ`p.x`・添字`xs[i]`チェーンは剥がす）、キャプチャ確定後にキャプチャ集合と突き合わせて`TcCannotAssignCapturedVar`（i18n、回避策としてポインタキャプチャを案内）でエラーにする。
- **デリファレンス経由は対象外**: `*px = v`はポインタ値のコピーが元の変数を指したままで書き込みが実際に伝播するため許可（全バックエンドで42伝播を実測）。チュートリアルでも公式の回避策として案内する。
- **識別子収集の網羅拡張**: 従来の文ウォーカーはfor-in・ブロック・switch・defer・mustブロックを辿っておらず、これらの中だけで使う外側変数がキャプチャ漏れしていた。書き込み検出と同時に走査対象へ追加した。
- **グローバル変数への書き込みも診断対象**: 実測でクロージャ内のグローバル代入も全バックエンドで黙殺されており（スコープ解決がグローバルもキャプチャ扱いにするため）、実態に合わせて診断する。クロージャからのグローバル直接アクセス（参照渡し化）は将来課題。
- **バグ2（構造体キャプチャのjs分岐）**: メンバ書き込みが診断で拒否されるため、バックエンド分岐ごと消滅。
- **テスト**: `tests/common/errors/closure_capture_assign.cm`（直接代入）・`closure_capture_member_assign.cm`（メンバ書き込み）、`tests/common/lambda/closure_ptr_capture_write.cm`（ポインタ回避策が全バックエンドで動作）、i18n `r4-capture-assign-{en,ja}`。interpreter/llvm/wasm/js/sv/unit/regression/libs/cm-test全スイートPASS。
- **チュートリアル**: `docs/tutorials/{ja,en}/advanced/lambda.md`へ「キャプチャは値コピー（読み取り専用）」節を新設し、診断とポインタ回避策を明文化。
- **既知の別件（本修正の範囲外）**: 文ボディのラムダで戻り値型推論がreturn式を本体検査より先に推論するため、ラムダ内ローカル変数を参照するreturnが「Undefined variable」になる既存の制約を実測で確認した（キャプチャ書き込みとは無関係の推論順序の問題）。参照キャプチャ`[&x]`構文はR13/R15系の未実装構文として残置。
