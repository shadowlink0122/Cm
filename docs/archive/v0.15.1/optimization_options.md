# ユーザ制御可能な最適化オプション

作成日: 2026-07-05対象バージョン: v0.15.1

`-O0`〜`-O3` の一括レベル指定とは独立に、個別の最適化をコマンドラインから明示的に制御するための仕組み。

## 設計

```
CLI (--funroll-loops=N 等)
  → cm::cli::Options（src/cli/options.hpp）
  → mir::opt::MirOptimizationOptions（src/mir/passes/core/manager.hpp）
  → create_standard_passes() でパスの追加・パラメータ化
```

- **`MirOptimizationOptions`** がユーザ指定フラグの集約点。新しい最適化フラグを追加する手順:
  1. `cli::Options` にフィールドとパース処理（`src/cli/options.cpp`）を追加
  2. `MirOptimizationOptions` に対応フィールドを追加
  3. `create_standard_passes()` でフラグに応じてパスを追加/パラメータ化
  4. `main.cpp` の `run_optimization_passes` 呼び出しで値を転記
- ユーザ指定パスは `-O0` でも有効（明示指定はレベルに優先する）。
- SVターゲットは従来どおり独自パイプライン（MIR最適化スキップ+SV専用パス）。

## 実装済みオプション

### `--funroll-loops[=N]` — 定数ループの静的展開

初期値・境界・増分がすべて定数のループを MIR レベルで直列展開し、ループ判定・分岐のオーバーヘッドを除去する。`N` は展開する最大イテレーション数（デフォルト64、上限1024）。それを超えるループは展開されない（外側の大きなループは残し、内側の小さな定数ループだけが展開される、という使い方を想定）。

実装はSVバックエンドの `ConstantLoopUnroll` パス（`src/mir/passes/loop/const_unroll.cpp`）を共用し、`create_standard_passes()` の先頭（SCCP/定数畳み込みより前）に挿入する。

**ベンチマーク**（外側300万回 × 内側16回のXOR集約、Apple Silicon）:

| バックエンド | 通常 (-O2) | -O2 --funroll-loops | 効果 |
|---|---|---|---|
| JS (node) | 0.38s | 0.10s | **約3.6倍** |
| JIT / LLVM native | 差なし | 差なし | LLVM自身がループ最適化を行うため |

**JSバックエンドで特に有効**（JS出力には独自のループ最適化がないため）。LLVM系バックエンドではLLVMのループ最適化と重複するため効果は限定的だが、`-O0`/`-O1` での実行時性能改善には寄与しうる。

### 適用条件（ConstantLoopUnroll の対象）

- 比較 `Lt/Le/Gt/Ge/Ne` + 定数境界 + 定数ステップの単一誘導変数
- 誘導変数のアドレス取得・多重代入・`must` ブロック含有ループは対象外
- `while(true)+break` や動的境界のループは展開されない（従来どおり）
- 展開後の総ステートメント数上限: 50,000（コードサイズ暴走防止）

## 付随修正: 無限ループ誤検出の撤去

LLVMコード生成の `BlockMonitor` にあった「周期2〜10の命令パターンを無限ループとして例外送出する」ヒューリスティックは、ループ展開後の正当な反復コード（および手書きの繰り返しコード）を誤検出するため撤去した。暴走対策は命令数上限（ブロックあたり10万命令 / 同一命令1000連続）が引き続き担う。

## 今後の候補フラグ

| フラグ案 | 内容 |
|---|---|
| `--finline-threshold=N` | 関数インライン化の闾値制御 |
| `--fno-licm` / `--fno-gvn` | 個別パスの無効化（デバッグ用） |
| `--funroll-all` | 展開上限をSV相当（1024）まで引き上げ |
