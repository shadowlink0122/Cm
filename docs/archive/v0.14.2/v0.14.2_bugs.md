# Cm v0.14.2 バグ修正 — Cosmo Linux 開発で発見された問題

> 対象: Cm v0.14.1 → v0.14.2
> 発見環境: Cosmo Linux カーネル開発 (`--target=baremetal-x86`)
> 日付: 2026-03-01

## 概要

Cosmo Linux (Cm言語で記述するLinuxカーネル) の開発中に、
Cmコンパイラの以下のバグ/問題を発見した。

| # | タイトル | 重要度 | 状態 |
|---|---------|--------|------|
| BUG-1 | ASM含む関数の過剰volatile生成 | 高 | **修正完了** |
| BUG-2 | `string` モジュール名の予約語衝突 | 中 | **修正完了** |

## BUG-1: ASM文を含む関数の過剰volatile生成

### 症状

`__asm__` を含む関数で、全ローカル変数が `volatile` 属性付きの
`alloca → store → load` チェーンに変換される。

`outb(ushort port, utiny value)` を呼び出すと、QEMU上のシリアルポートに
正しくデータが書き込まれない。`outb(ulong port, ulong value)` に変更すると
正常動作する。

### LLVM IR比較

```llvm
; 小型引数版 — 6つのalloca + 多数のvolatile store/load
define void @outb(i16 %arg0, i8 %arg1) #0 {
  %local_3 = alloca i64, align 8
  %local_4 = alloca i16, align 2
  %local_5 = alloca i64, align 8      ; キャスト中間変数
  %local_6 = alloca i64, align 8      ; キャスト中間変数
  %local_7 = alloca i8, align 1
  %local_8 = alloca i64, align 8      ; キャスト中間変数
  store volatile i16 %arg0, ptr %local_4  ; 全てvolatile
  ; ... 合計12回のvolatile store/load ...
}

; ulong版 — alloca不要、直接レジスタ渡し
define void @outb_ulong(i64 %arg0, i64 %arg1) #0 {
  call void asm sideeffect "..." (i64 %arg1, i64 %arg0)
}
```

### x86-64 オブジェクトコード比較

```asm
; outb(ushort, utiny) — 0x43バイト、13回のメモリ操作
0000: mov    %di,-0x22(%rsp)
0005: movzwl -0x22(%rsp),%eax
000a: mov    %rax,-0x10(%rsp)   ; 冗長
000f: mov    -0x10(%rsp),%rax   ; 冗長
0014: mov    %rax,-0x8(%rsp)    ; 冗長
; ... (計13回のmov to/from stack)
003c: mov    %rcx,%rax
003f: mov    %rsi,%rdx
0042: out    %al,(%dx)

; outb_ulong(ulong, ulong) — 0x4バイト、0回のメモリ操作
0050: mov    %rsi,%rax
0053: mov    %rdi,%rdx
0056: out    %al,(%dx)
```

### 根本原因

`mir_to_llvm.cpp` の変数生成で、ASM文（`__asm__`）を含む関数内の
全ローカル変数に `volatile` 属性を付与している。

これは本来ASM operand (`${r:var}`, `${=r:var}`) の読み取り/書き込み
をLLVMの最適化パスが除去しないための対策だが、
結果として以下の問題が発生:

1. **`as ulong` キャスト中間変数もvolatile化** され、
   `alloca → volatile store → volatile load → zext → alloca → volatile store`
   の冗長チェーンが生成される
2. **コードサイズの爆発**: `outb(i16, i8)` は13回のメモリ操作に対し、
   `outb(i64, i64)` は0回
3. **baremetal環境での副作用**: `-sse,-sse2,-mmx` + `noinline` の条件下で、
   volatile操作がスタックフレームを膨張させ、初期スタックを圧迫

### 修正方針

ASM operandで直接参照される変数のみvolatileにし、
キャスト中間変数のvolatile属性を除去する。

具体的な変更箇所:
- `src/codegen/llvm/core/mir_to_llvm.cpp` の変数生成ロジック
- ASM文の解析で参照変数を追跡し、参照外のローカル変数はvolatile除去

## BUG-2: `string` モジュール名がプリプロセッサで衝突

### 症状

```cm
import ../lib/string;   // → パースエラー
```

`string.cm` をインポートすると、プリプロセッサが:
```cm
namespace string { ... }
```
として展開し、`string` がCm言語の組み込み型名と衝突する。

### 影響

- `string` という名前のモジュールファイルが使用不可
- Cosmo Linuxでは `kstring.cm` にリネームして回避

### 根本原因

`src/preprocessor/import_preprocessor.cpp` でモジュール名（ファイル名ベース）
がそのまま `namespace` 名に使われる。予約語チェックがない。

### 修正方針

1. `parse_namespace()`: 型キーワード（`string`, `int`, `bool`等）をnamespace名として受け入れるように拡張
2. `parse_primary()`: 型キーワード + `::` のパターンを名前空間修飾子として式パーサで処理
