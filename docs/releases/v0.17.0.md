# Cm v0.17.0 リリースノート

**前バージョン:** v0.16.2

各項目は「何が問題だったか→どうなったか」の要約です。
真因分析・設計判断・実装の詳細は `docs/archive/v0.17.0/` の各設計文書（索引: [design-README.md](../archive/v0.17.0/design-README.md) / [refactoring-README.md](../archive/v0.17.0/refactoring-README.md)）に記録しています。

## 🎯 ハイライト

- **TypeScript出力（`--target=ts`）とCm完結のWeb開発**: 型注釈付きTS出力・npm/Node連携・HTMLビルダー（`web::html`）でフルスタック開発ができるようになった。
- **js/tsのlong/ulongをBigInt化**: 2^53超の64bit値が全バックエンドで精度一致するようになった。
- **標準ライブラリの拡充**: TreeMap・JSONパーサ・StringBuilder・OS連携モジュール（env/process/path/bytes/fs/args）を追加した。
- **文字列基盤の刷新**: `len()`のUTF-8コードポイント化・O(1)バイト長・埋め込みNUL対応・連結の単一バッファ化。
- **メモリ管理の完結**: コンパイラ一時・ループ内RAII・文字列再代入・wasmアロケータまで、リークしていた全系統を解放するようになった。
- **モジュールシステムの構造化**: importのテキストインライン展開を廃止し、モジュールグラフ+AST駆動の選択的包含へ全面移行した。
- **品質検証の全件対応**: 大規模監査57所見+網羅検証61件（構文36・調査シリーズ25）で検出した誤コンパイル・クラッシュ・バックエンド分裂をすべて修正した。
- **コンパイラ基盤の大規模内部再編**: 設計文書10本超の構造的リファクタリングを完遂した。

## 💥 破壊的変更・移行が必要な変更

- **文字列`len()`がUTF-8コードポイント数になった**: バイト数は`byte_len()`へ。`substring`/`slice`/`indexOf`の添字もコードポイント単位。
- **HashMap/TreeMapの`get`が`Option<V>`を返す**: `m.get_or(k, 0)`または`m.get(k).unwrap_or(0)`へ移行する（旧getは不在キーで未初期化値を返す危険な契約だった）。
- **std独自の`CmResult`を撤去**: 組み込み`Result`/`Option`+`?`の1系統へ統合した。
- **非exportシンボルの選択importがエラーになった**: 取り込むには定義へ`export`を付ける。
- **数値→stringの`as`キャストを拒否**: 従来はバックエンドごとに挙動が分裂していた（補間や`toString`を使う）。
- **enumの複数ペイロード宣言（`R(int, int)`）をエラー化**: 構造体で包む回避策を診断が案内する。
- **js/tsの構造体関数引数が値渡しになった**: LLVM系と意味論を統一した（implメソッドのselfは参照渡しを維持）。
- **キャプチャ付きクロージャのユーザー関数への引き渡しはエラー**: 従来はゴミ値・未解決シンボルの黙殺だった（ローカル束縛+直接呼び出し・組み込み高階関数は従来どおり）。
- **集約（配列・構造体）の`println`直接整形はエラー**: 従来はクラッシュ・空出力・JSのみ動作の3分裂だった。`{p.debug()}`（derive(Debug)）が全バックエンド一致の整形手段。
- **構造体・文字列要素の配列高階関数はnative/jit/wasmでエラー**: 従来は型検査を通過後に無診断の誤値・クラッシュだった（js/tsは従来どおり動作。スカラ要素は全幅で正しく動作するようになった）。
- **マングリング名の衝突がコンパイルエラーになった**: 従来は同名縮退で片方が黙って上書きされていた。

## 🚀 言語・構文

- **ユニオン型引数のderive**: `Box<IU>`（`typedef IU = int | string`）のEq deriveが使えるようになった（従来は診断で拒否）。
- **`var`キーワード**: `var x = 42;`が`auto`の別名として使える。
- **`assert_eq`/`assert_ne`**: 失敗時に期待値・実測値を表示するアサートを`std::debug`へ追加した。
- **`std::env::args()`**: コマンドライン引数を取得できる（`cm run file.cm -- <args...>`対応）。
- **演算子インターフェースのimpl形**: `impl Vec2 for Add { operator Vec2 +(...) }`が10演算子（Add〜Shr）で書けるようになった（従来は内部エラー）。
- **enumのinherent implメソッド**: `impl Color { string name() {...} }`が値enum・ペイロード付きenumの両方で動くようになった（従来は呼び出しでUnknown method）。
- **implメソッドの`export`修飾子**: パースエラーで使えなかった`export int getx()`形を正式受理し、これに依存していた`native::sync`/`native::io`の高レベルAPI（Mutex/RwLock/Atomic/Channel/ストリーム）が初めて動くようになった。
- **ジェネリック構造体の明示型引数付き構築**: `Box<int>{v: 7}`が書けるようになった（従来は構文エラー）。
- **配列サイズのコンパイル時定数式**: `int[N + 1]`・`int[sizeof(int)]`・`int[(1+2)*3]`が書けるようになった。
- **括弧付き型の宣言**: `(int) k = 5;`・`(int | string) u = 42;`が宣言として認識されるようになった。
- **文字列の`for-in`反復**: `for (char ch in s)`が使えるようになった（バイト単位・`s[i]`と同値）。
- **raw文字列のdedentを開始行基準へ**: バッククォート文字列のインデント剥ぎがコード字下げだけを剥がすようになり、内容の意図的な先頭空白が保持される。
- **文字列エスケープの完備**: `\xHH`/`\uHHHH`/`\UHHHHHHHH`/`\a`等が実装され（従来はバックスラッシュが黙って脱落）、未知エスケープはコンパイルエラーになった。raw文字列はエスケープを解釈しなくなった。
- **数値リテラルの桁区切り**: `1_000`・`0xFF_FF`が書けるようになった。
- **多段相対import**: `import ../../modules/x`が書けるようになった（従来は一段の`../`まで）。
- **シフト量の仕様確定**: `1 << 32`が「型幅でmod」として全バックエンド・全最適化レベルで一致する。
- **可視性の確定**: privateフィールドの外部アクセスは診断で拒否され、可視性は構造体単位（C++のprivate相当）。
- **ジェネリックのインスタンス化診断**: 型引数の個数不一致・未定義型引数がエラーになり、境界未宣言の演算子使用が警告される。

## 📚 標準ライブラリ

- **`std::collections::TreeMap<K, V>`**: AVL木の順序付き連想コンテナを追加した。
- **HashMapの容量自動拡張**: 初期容量16を超えるinsertが黙って喪失していたのを、自動resizeで解消した。
- **`std::json`**: JSONパーサ・直列化を追加し、固定容量超えの無限ループ・甘い受理・`\uXXXX`未デコードも解消した。
- **`std::strings::StringBuilder`**: ループ連結のO(n²)を償却O(1)追記で解消した。`split`/`lines`/`from_bytes`も追加。
- **OS連携モジュール**: `std::env`・`std::process`・`std::path`・`std::bytes`・`std::fs`拡張（バイナリ安全I/O）を追加した。
- **stdlibの出荷不良を修理**: importするだけで壊れていた`std::iter`・アロケータを素通しするコレクション・到達不能だった`std.core.async`（`std.core.time`へ改名）等を修理し、libs全30モジュールのimportゲートをCIへ常設した。
- **ioのパース関数をOption返しへ**: `parse_int`等が失敗を0で握り潰さず`None`を返す。
- **アロケータ差し替え**: `std::mem::set_allocator_fns`で`std::mem`経由の全確保に反映される。

## 🧵 文字列

- **`len()`をコードポイント数へ統一**: native=バイト・js=UTF-16の意味分裂を解消し、`byte_len()`・`codepoint_at()`・`chars()`・`byte_at()`を追加した。
- **`charAt()`/`at()`もコードポイント添字へ**: `len()`との単位不一致で非ASCII文字列の走査が全滅していたのを解消した。
- **長さヘッダ付き文字列（SDS方式）**: `byte_len()`がO(1)になり、埋め込みNULを保持し、FFIへはNUL終端char*のまま渡せる。
- **連結チェーンの単一バッファ化**: `a + b + c + d`が1回の確保になり、再代入ループが約2倍高速化した。
- **補間・書式指定子の全バックエンド統一**: 幅・ゼロ埋め・科学記法がnative系で無視される3経路分裂を、C/printf互換の正準仕様で統一した。
- **補間の再スキャン破壊を解消**: Debug出力等の波括弧を含む実行時値を補間すると以降のプレースホルダが総崩れになる問題を修正した。

## 🗂 モジュールシステム

- **構造化importへの全面移行**: テキストインライン展開（約2,800行）を削除し、選択import・エイリアス・namespace・階層再export・ワイルドカードを型・AST情報で解決するようになった。
- **同名シンボルの多重importを診断エラー化**: 先勝ちの黙殺をやめ、エイリアスか修飾名を案内する。
- **非export関数のカプセル化を強制**: 選択importはエラー、内部ヘルパーは`__cm_priv_`遮断で外から見えない。
- **改名の文字列内容破壊を修正**: モジュール取り込み時のヘルパー改名が文字列リテラルの中身まで書き換えていたのを、トークン精密な改名で解消した。

## 🧠 型システム・型検査

- **`typeof(式)`の静的解決**: `x as typeof(y)`・`typeof(j) k = i;`・`sizeof(typeof(x))`が全バックエンドで正しく解決される（従来は未解決スタブ・パースエラー・常に8）。
- **配列リテラル要素の型検査**: `int[3] a = [1, "hello", 3]`が無診断で通りゴミ値になっていたのを、要素ごとの検査で拒否する（多次元も再帰検査）。
- **ジェネリック特殊化の型同一性を構造化**: フラット名の再パースを廃止し、ネスト型引数（`Pair<Box<int>, Box<string>>`）のフィールド読み書き・string誤読・sizeof誤値を解消した。
- **集約に入るインターフェイス値**: 構造体フィールド・配列・スライスへの格納でfat pointerが正しく構築され、ポリモーフィックコレクションが使えるようになった。
- **インターフェース戻り値のダングリング解消**: `Shape make()`の戻り値がスタックを指したまま返る問題をヒープboxing化で修正した（O2でゴミ値・wasmで誤値だった）。
- **ポインタ・配列引数からの型パラメータ推論**: `<T> void swap(T* a, T* b)`・`<T> T first(T[] xs)`がSIGSEGVせず推論されるようになった。
- **for-inイテレータプロトコルの検査**: `iter()`/`has_next()`/`next()`の欠如・型違いが分かりやすい診断になった（従来はリンクエラーや的外れな型エラー）。
- **確定代入・return網羅の検査**: 分岐を跨ぐ未初期化使用とreturn漏れが警告され、`--strict`でエラーになる。
- **数値変換の境界を確定**: 拡大=暗黙・縮小/符号変化=警告+`as`誘導（`--strict`でエラー）を全文脈（let・代入・return・引数・配列要素・フィールド）で一律化した。適合リテラルと`uint/usize→int`は免除。
- **混合数値演算の暗黙昇格**: `double a = d + i;`がLLVM検証エラー・SIGBUSになる問題を、checker段の昇格Cast挿入で修正した。
- **型検査の黙殺穴を封鎖**: 未定義型の変数宣言・型不一致マクロ・スライスpush引数の型不一致・ユニオンの非変種`as`・ループ外break/continueが診断されるようになった。

## 🧹 メモリ管理

- **コンパイラ一時のdropパス**: 文字列一時・スライス中間・三項/条件腕の一時・再代入の旧バッファを全最適化レベルで解放するようになった（一時連結100万回ループでRSS 97.8MB→1.4MB）。
- **ループ本体のRAII**: while/for本体・break/continue経路でデストラクタが毎周期実行される。
- **wasmアロケータの解放対応**: 単調バンプをフリーリスト+`memory.grow`へ置き換え、`free`/`realloc`が実際にメモリを返却・再利用する。
- **move後使用の診断強化**: フィールド経由move・補間内のmove後使用を検出する。

## ⚡ コンパイル時間・生成物サイズ

- **大構造体のsret/memcpy化**: `int[16384]`フィールド構造体の戻り値がO2で60秒超→0.6秒になった。
- **モジュール別キャッシュと並列コード生成（実験的）**: `CM_MODULE_CODEGEN=1`でウォームビルドが全コード生成をスキップする。
- **コード生成タイムアウトのプロセス分離**: 暴走LLVMをfork+SIGKILLで確実に回収する。
- **ジェネリック特殊化の同一コード折り畳み**: O2以上で重複する特殊化本体をマージする。
- **構造体配列フィールドのアクセス爆発を解消**: 要素読み出しの配列全体コピーをやめ、コンパイル時間が配列サイズに依存しなくなった。

## 🌐 JS/TS・Web開発

- **TypeScriptバックエンド**: 型注釈付きTS出力（structは`export interface`）が`tsc --noEmit`を型エラーなく通る。
- **long/ulongのBigInt化**: 精度・ラップ・除算・比較をLLVM系と一致させた。
- **npmパッケージ連携の正式化**: `use "パッケージ名" { 宣言 }`で構造体・関数ポインタ・ラムダが渡り、this束縛も保持される。
- **`web::html`ライブラリ**: 自動エスケープ付きHTMLビルダーで、vendor JSゼロのフルスタックexampleを整備した。
- **関数ポインタ式の直接呼び出し**: `fs[0](args)`・`getf()(args)`がjs/tsで動くようになった（native系は明確な診断で停止）。

## 🧰 エディタ支援（VSCode拡張）

- **ホバーと定義ジャンプ**: 関数・構造体・enum・implメソッド等のシグネチャ表示・F12ジャンプ・アウトライン・ワークスペース検索に対応した。
- **LSPサーバ化**: 標準のLanguage Server Protocol構成+自己完結バンドルで、同梱漏れによる機能無効化を構造的に防ぐ。
- **定義候補の絞り込み**: 呼び出し文脈とファイル到達性で同名シンボルの候補を減らす。
- **v0.17.0構文への追従**: SVA組み込み・`\a`エスケープ・演算子宣言の定義ジャンプ・impl対象型の解決方向を修正した。

## 🎯 バックエンド統一・数値意味論

- **double出力とfloat→intキャストの統一**: 最短round-trip表示と飽和変換（`1e20 as int`=`2147483647`）で3分裂を解消した。
- **整数拡張の符号規則を統一**: `ushort(60000) + 1`等の拡張が「オペランド自身の符号」基準で全バックエンド一致する。
- **jsの整数キャスト・ビット演算のラップ統一**: `-1 as uint`等がLLVM系の2の補数ラップと一致する。
- **スライス境界チェックの統一**: `--sanitize=bounds`がスライスにも効き、同一メッセージ・終了コードでトラップする。

## 🔌 SVバックエンド

- **リダクション演算子**: `reduce_and`/`reduce_or`/`reduce_xor`等6種を追加した（SVはnative演算子・実行系は脱糖で全バックエンド一致）。
- **ビットスライスのnative part-select**: `x[hi:lo]`・`x[base +: w]`・下降方向`-:`で出力されるようになった（従来はshift+mask）。
- **don't-care matchのnative casez**: `0b1?00`等のパターンが`casez`（`unique`/`priority`自動選択）で出力される。`#[sv::priority]`/`#[sv::unique0]`属性も追加。
- **並行アサーション（SVA）**: `sv_assert_property(clk, 性質)`と時相演算子（`implies`/`rose`/`fell`/`past`等）で時相的性質を検証できるようになった。
- **モジュールインスタンス配列**: `#[sv::instance_array(N)]`でgenerate-forによるNレーン並列インスタンス化ができる。
- **packed union**: `#[sv::packed_union]`で同一ビット領域の複数ビュー再解釈ができる（幅不一致はコンパイル時エラー）。
- **パラメータ境界ループの合成可能化**: `#[sv::parameter]`境界のループがwhile（合成不能）でなくfor文で出力される。
- **パラメータ幅メモリ配列**: `bit[WIDTH][DEPTH]`が正しいメモリ宣言と直接添字で出力される。
- **$readmemb対応**: `#[sv::memfile("f.bin", radix: bin)]`で2進メモリファイルを読み込める。
- **SVテストの期待値検証を実効化**: `//! test:`の期待値が一切アサートされず常にPASSしていたのを、`!==`比較+`$fatal`（x安全）で実際に検証するようにした。
- **不正SV生成の診断化**: 属性タイポ・inputポートへの代入・エッジ指定なしalways_ff・幅0/桁あふれリテラルがコンパイル時診断で止まる。
- **import先モジュールのSV方言解析**: `--target=sv`でimport先も自動的にSV方言で解析され、`#[sv::memfile]`用の初期化子なし宣言等が通るようになった。
- **module形importの名前空間フラット化**: `core::pc`等の修飾名が生成SVに漏れてVerilator/iverilogが弾く問題を修正した。
- **派生定数のREALCVT解消**: 整数宣言へのfloat式（`CLK_FREQ * 0.02`）が`$rtoi()`付きで出力され、Verilator警告が出なくなった。
- **関数本体の定数float式**: `uint s = LIMIT * 0.5;`が整数へ畳み込まれSV004にならなくなった（実行時float値は従来どおり拒否）。

## 🐛 バグ修正

各項目は要約のみ。症状の詳細・真因は設計文書を参照。

**ユニオン**
- ユニオンの等値比較が誤値だった（native/jit=タグのみ比較・js=参照比較）→ タグ+ペイロード比較へ脱糖し全バックエンド一致。
- スライス変種の構築が実体化されずゴミ値・null変種の構築が誤タグだった → 変換ドライバの判定修正で解消。
- `is`と`as`がGVNで混同されペイロードを誤読するミスコンパイル → 最適化キーへ検査フラグを追加。
- typedef経由のユニオン引数・変種`as`が偽陽性で拒否されていた → typedef実体解決の一元化で受理。

**ジェネリック・derive**
- 総称derive特殊化のスライス比較が環境依存SIGSEGV → フィールド型置換と内容比較への書き換えで修正。
- ジェネリック構造体の演算子impl（Eq/Ord）が特殊化されず`<`が誤値 → 特殊化の種蒔きで全バックエンド一致。
- ジェネリック構造体のClone/Hash/Debug/Displayが無言no-op・値enumフィールドのderive失敗 → メソッド表配線とint意味論対応で動作化。
- ネストしたジェネリック型引数のstringフィールド読みが無言死 → 特殊化キー曖昧性と型上書きの2真因を修正。
- `sizeof(Pair<char, int>)`等の特殊化sizeofが誤値 → 実レイアウト計算へ一本化。

**文字列・補間**
- 補間プレースホルダの受理がホワイトリスト方式で`{2 + 3}`・`{[1,2,3].len()}`・`{_count}`等がリテラル出力 → 本物の式パーサへ統一。
- 変数添字`{arr[i]}`が常に先頭要素・メソッドチェーンの誤値 → 脱糖の走査漏れを修正。
- 三項演算子の`:`が書式指定子と誤認され`{c ? a : b}`が壊れる → 三項保留カウンタで解消。

**構文・診断**
- `#endif`が非認識で後続コードが黙って消える → 別名認識+閉じ忘れ診断。
- 属性タイポ（`#[tset]`）でテストが実行されないまま緑 → 属性検証レジストリで警告/エラー化。
- デフォルト引数の前パラメータ参照が黙って0 → コンパイルエラー化。
- クロージャのキャプチャ変数書き込みが黙って無効 → 値キャプチャ=読み取り専用と明確化しエラー化（変更はポインタキャプチャ経由）。
- matchの負数パターンが書けない・網羅matchにreturn漏れ誤検知 → 両方修正。
- 構文エラーに行番号がなく「imported module」と誤表記 → 位置情報+該当行+キャレット表示へ。
- 未実装構文9項目（参照型`T&`・演算子`[]`オーバーロード等）が誤誘導エラー → 専用診断or実装（桁区切り）or文法書追従で整合。

**バックエンド**
- baremetal-armが最小プログラムもコンパイル不能 → 起動コードの型・意味バグを修正しCIゲート追加。
- フリースタンディング制約のすり抜け（文字列連結・関数ポインタ経由呼び出し）→ ブロックリストと間接呼び出し検査で封止。
- wasmで native専用FFIが実行時破綻 → コンパイル時のundefined symbolエラーへ。
- TS出力のlong/ulongフィールド代入がtscを通らない → BigIntリテラル化。
- スレッド`join()`の戻り値上位32bitが欠落 → `long`化。
- AVX-512マスク環境での断続的SIGILL → CPU機能の明示否定で抑止。
- O0での浮動小数`%`がリンクエラー → `-lm`常時付与とwasm剰余実装。

**配列・スライス**
- 配列高階関数（map/filter/reduce等）が非int要素でゴミ値・クラッシュ → 要素型ディスパッチの全幅化（80関数追加）で全スカラ幅が動作。
- 配列検索（indexOf/includes）が要素型を無視し分裂 → 要素型サフィックス選択へ。
- スライスof固定長配列（`T[N][]`）の格納表現不一致でゴミ値 → blob格納へ仕様確定し統一。
- 固定長配列→スライス引数が生ポインタで渡りゴミ値 → ヒープ実体化の暗黙変換を追加。
- 構造体フィールドの配列サイズにconst名を使うとレイアウト崩壊 → フィールドでも解決するよう修正。
- 多次元配列の部分取り出し・要素数不一致の無診断受理 → パースと検査を修正。

**その他**
- `sizeof(a[0])`が0を返す・`sizeof(p.x)`等がパースエラー → 型/式の判定を正しく分離。
- `(int | string)`が型位置で使えない・`Foo<int | string>`が失敗 → 型文法を正準パーサへ集約。
- グローバル変数の非定数初期化子が`cm test`で実行されない → #[test]エントリにも初期化を注入。
- `cm run`の中間JSがシステムtempに固定名で衝突 → `.tmp/`配下へ統一。
- 修飾子の黙殺（`inline`無効果・`constexpr`誤エラー・`volatile`パース不能）→ inlineは実伝搬、他は専用診断。
