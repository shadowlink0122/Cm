# Cm v0.17.0 リリースノート（開発中）

**前バージョン:** v0.16.2

## 🎯 ハイライト

- **TypeScript出力（`--target=ts`）とCm完結のWeb開発**: 型注釈付きTSを第一級サポートし、npm/Node連携・HTMLビルダー（`web::html`）・vendor JSゼロのフルスタックexampleを整備した。
- **js/tsのlong/ulongをBigInt化（H5）**: 2^53超の64bit値が全バックエンドで精度一致するようになった。
- **標準ライブラリの拡充**: TreeMap・JSONパーサ・StringBuilder・OS連携モジュール（env/process/path/bytes/fs/args）を追加した。
- **文字列基盤の刷新（H9全5段）**: `len()`のUTF-8コードポイント化・O(1)バイト長・埋め込みNUL対応・連結チェーンの単一バッファ化。
- **メモリ管理の完結（C12/C13）**: コンパイラ一時・ループ内RAII・文字列再代入・wasmアロケータまで、リークしていた全系統を解放するようになった。
- **モジュールシステムの構造化**: importのテキストインライン展開を廃止し、ファイル単位パースのモジュールグラフ+AST駆動の選択的包含へ全面移行した。
- **大規模開発ボトルネック監査（57所見）と構文網羅検証（36件）の全件対応**: 一連の検証で検出した誤コンパイル・クラッシュ・バックエンド分裂をすべて修正した。
- **コンパイラ基盤の大規模内部再編**: 層依存規律・診断エンジン・ランタイムレジストリ・型付きHIR・型駆動モノモーフ化など、設計文書10本超の構造的リファクタリングを完遂した。

実装の詳細・設計判断は `docs/archive/v0.17.0/` の各設計文書に記録している。

## 💥 破壊的変更・移行が必要な変更

- **文字列`len()`がUTF-8コードポイント数になった**: バイト数が必要な箇所は`byte_len()`へ移行する（ASCIIのみの文字列は挙動不変）。`substring`/`slice`/`indexOf`の添字もコードポイント単位へ統一した。
- **HashMap/TreeMapの`get`が`Option<V>`を返す**: 従来の`int v = m.get(k);`は`m.get_or(k, 0)`または`m.get(k).unwrap_or(0)`へ移行する（旧getは不在キーで未初期化メモリ等を返す危険な契約だったため）。
- **std独自の`CmResult`を撤去（M17）**: 組み込み`Result`/`Option`+`?`の1系統へ統合した。
- **非exportシンボルの選択importがエラーになった（H7）**: `import mod::{fn}`で非export関数は取り込めない（定義に`export`を付けるかexportリストへ追加する）。
- **マングリング名の衝突がコンパイルエラーになった（C16)**: 従来は同名縮退で片方が黙って上書きされていたため、実質的な破壊的変更ではない。
- **数値→stringの`as`キャストを型検査で拒否（C10）**: 従来はバックエンドによりSIGSEGV・空文字・正常と5分裂していた。
- **enumの複数ペイロード宣言（`R(int, int)`）を診断付きエラー化（N6)**: 設計上単一ペイロードのため（構造体で包む回避策を案内する）。
- **js/tsの構造体関数引数が値渡しになった（H3)**: LLVM系と意味論を統一した（implメソッドのself等は参照渡しを維持）。
- **キャプチャ付きクロージャのユーザー関数への引き渡しは診断付きエラー（V5〜V7)**: 従来はゴミ値・未解決シンボルの黙殺だった（ローカル束縛+直接呼び出し・組み込み高階関数は従来どおり動作）。

## 🚀 言語・構文

- **`var`を`auto`の別名キーワードに追加（L3)**: `var x = 42;`が型推論として動く。
- **`assert_eq`/`assert_ne`を`std::debug`へ追加（L6)**: 失敗時に期待値・実測値を表示して異常終了する（`<T: Eq>`ジェネリック）。
- **`std::env::args()`でコマンドライン引数を取得**: `cm run file.cm -- <args...>`にも対応した（`int main()`の言語仕様は不変）。
- **シフト量の仕様を「型幅でmod」に確定（V8)**: `1 << 32`が全バックエンド・全最適化レベルで一致する。
- **privateフィールド・メソッドの可視性を確定（X2/X6)**: 外部からのprivateフィールドアクセスは診断付きで拒否され、可視性は構造体単位（C++のprivate相当）。
- **ジェネリックのインスタンス化診断（H15/L8)**: 型引数なし使用・未定義型引数・明示型引数の個数不一致をエラー化し、境界未宣言の比較演算子使用を警告する。
- **算術・ビット演算子インターフェースのimpl形（Q4)**: `impl Vec2 for Add { operator Vec2 +(Vec2 other) {...} }`のインターフェース指定形が使えるようになった（Add/Sub/Mul/Div/Mod/BitAnd/BitOr/BitXor/Shl/Shrの10種をEq/Ordと同様に組み込み宣言。従来は「internal error: 'Add' is not a declared interface」）。あわせて未宣言インターフェースへのimpl・重複impl・重複メソッドの内部エラー漏れを通常診断へ置換した。`<T: Add>`境界の総称本体内算術は未対応（`<T: Ord>`比較は使用可能）。設計文書: [arith-operator-interface-decl.md](../archive/v0.17.0/interfaces-derive/arith-operator-interface-decl.md)
- **enumのinherent implメソッド（Q5)**: `impl Color { string name() { return match (self) {...}; } }`が値enum・ペイロード付きenumの両方で動作するようになった（従来はimpl宣言が黙って受理され、呼び出しで「Unknown method 'name' for type 'int'」になっていた）。値enumのint解決でenum名を型のnameへ保持する方式でメソッド解決・マングリングを通し、selfの渡し規約を確定した（値enum=int値渡し・メソッド内のself再代入はコピーに閉じる値意味論、ペイロード付き=構造体ポインタ渡し）。設計文書: [enum-inherent-impl-methods.md](../archive/v0.17.0/enums-unions/enum-inherent-impl-methods.md)
- **implメソッドの`export`修飾子を受理（R22)**: `impl Pt { export int getx() {...} }`が`Expected type`のパースエラーで停止し、この構文を使う`native::sync`の高レベルOOP API（`Mutex<T>`/`RwLock<T>`/`AtomicInt`/`Channel`）と`native::io`のストリームAPIが一度もimportできない死んだコードになっていた。`export`をメソッドの既定可視性（公開）の明示として正式に受理し（`export`と`private`の併用は専用診断）、文法書へmethod_modifierを明文化した。あわせて併発バグ2段——静的ジェネリック呼び出し`Mutex<int>::new(v)`のcheckerパラメータ型未置換（「expected T, got int」誤診断）と、HIR loweringの名前未変換で**callが黙って消えゼロ値になる無言誤動作**——を修正し、特殊化静的メソッドが正しく呼ばれるようになった。native::sync/ioの未コンパイル起因バグ（ポインタフィールドへの`.`アクセス・式位置のジェネリック構造体リテラル・AtomicBoolのboolフィールドへの4バイトアトミック書き込み・ドット形enum構築・実文法と異なるmatch・再export名不一致）も修理し、Mutex/RwLock/Atomic/Once/Channelの全構造体APIとStdout/BufWriter/Stdinストリームを実行検証した。ジェネリックenumのimplメソッドと境界付きブランケットimpl（`impl<R : Reader> R`）は言語未対応と判明したため正直な診断を維持して見送り（設計文書へ記録）。libsのimportゲートは既知失敗リストが空になり全30モジュール検証になった。設計文書: [export-on-impl-method-parse-error.md](../archive/v0.17.0/syntax-parse/export-on-impl-method-parse-error.md)
- **文字列補間のネスト誤パースを修正（L2)**: プレースホルダ内の構造体リテラル波括弧・引用符を正しく扱う。
- **縮小キャストの切り捨て警告（M4)**・**パーサの固定上限撤廃（M5)**。

## 📚 標準ライブラリ

- **`std::collections::TreeMap<K, V>`**: AVL木の順序付き連想コンテナ（探索・挿入O(log n)）。ノードアリーナ方式で全バックエンド同一動作、容量は自動拡張する。
- **HashMapの容量自動拡張（Q7)**: 従来はresize未実装で初期容量16を超えるinsertが黙って喪失していた（`get`がNone・データ喪失）。負荷率50%で容量を2倍へ拡張し全エントリを再ハッシュする`grow()`を実装した。設計文書: [hashmap-resize-loses-entries.md](../archive/v0.17.0/stdlib-runtime/hashmap-resize-loses-entries.md)
- **`std::json`**: 純粋Cm実装のJSONパーサ・アクセサ・直列化（アリーナ方式・全バックエンド同一動作）。
- **`std::json`の堅牢化（R1)**: ノードアリーナをTreeMapと同方式のパラレル動的スライスへ置き換え、旧固定容量1024を2ノード超えるJSONで`json_parse`が無限ループする問題（`append_child`の自己サイクル・実質DoS）を構造的に解消した（ノード数の上限も撤廃）。あわせて末尾ゴミ（`{"a":1}xyz`）・複数値（`1 2`）・数字を伴わない`-`の甘い受理を拒否し、`\uXXXX`エスケープをサロゲートペア込みでUTF-8へ実デコードする（従来は文字`u`+生4桁へ化けるデータ破壊。不正エスケープ・不正16進・対を成さないサロゲートは`-1`）。jsバックエンドの非ASCII表示は文字列モデル分裂（R2・未修正）に帰属する既知制約。設計文書: [json-parser-robustness.md](../archive/v0.17.0/stdlib-runtime/json-parser-robustness.md)
- **stdlibの出荷不良を修理し、libs全モジュールのimportゲートを常設（R9)**: 出荷されているstdlibが自身のエラーで壊れている系統をまとめて修理した。`std::iter`は`range`の3重オーバーロード（自由関数オーバーロード未サポート）と`IntArrayIterator.next`のデリファレンス欠落で`import std::iter::*`が常時失敗していた——`range(start, end, step = 1)`+`range_to(end)`へ整理して修正し、`Range::iter()`を追加して`for (int x in range(1, 4))`のfor-in反復にも対応した。Vector/HashMap/Queueは生malloc直呼びで`set_allocator_fns`のカスタムアロケータを素通ししていた——`std::mem`経由へ置換した。`std::io`ファサードの入力API再export（`export import std.io.console.input::{...}`）はmodule graphの選択的再export辺が一律素通しで解決不能だった——組み込みI/O名（print/println等。Cm定義の取り込みで組み込み書式処理を影置換しないため）のみ素通しし、実Cm関数は辿るよう修正した。ゲート整備の掃引で同類の出荷不良4件も発見・修正: `std::core`のusize/isize typedef（予約語化済みで衝突）と`abs`4重オーバーロード（ジェネリック1本へ。std::mathも同様）、`std.core.async`（asyncが予約語でimport文が書けず全API到達不能→`std.core.time`へ改名し、未リンクだったcm_now_msランタイムをruntime_time.cとしてコアランタイムへ包含）、`native::math`のfloatリテラル接尾辞`3.14f`（未実装構文でパース不能→`as float`へ。sin/sqrt等11組のfloat版オーバーロードは`sin_f`等へ改名）、`std::mem`のmoduleヘッダ不一致。再発防止として`make test-libs`へlibs全mod.cmのimportゲート（27モジュール検証。R22で壊れているnative/io・native/syncは既知失敗として明示SKIP）を常設した。設計文書: [stdlib-shipping-defects.md](../archive/v0.17.0/stdlib-runtime/stdlib-shipping-defects.md)
- **`std::strings::StringBuilder`（H9)**: 償却O(1)追記でループ連結のO(n²)を解消する。`split`/`lines`/`from_bytes`も追加した。
- **OS連携モジュール（セルフホスト準備）**: `std::env`（get/set/args/current_exe）・`std::process`（run/output）・`std::path`・`std::bytes`（エンディアン指定バイト詰め）・`std::fs`拡張（create_dir/read_dir/read_bytes/write_bytes。バイナリ安全I/O）。CLIツールの一巡を`examples/07_selfhost_drill/`でCI検証する。
- **ioのパース関数をOption返しへ（M17)**: `parse_int`等が失敗を0で握り潰さず`None`を返す。
- **アロケータ差し替えのCm到達可能化（M14)**: `std::mem::set_allocator_fns`/`reset_allocator`で`std::mem`経由の全確保に反映される。
- **libsの単体テスト基盤**: lib同梱の`*_test.cm`（`#[test]`）と`make test-libs`ランナーを整備した。

## 🧠 型システム・型検査

- **ジェネリック特殊化の型同一性を構造化（C7/C8/C9)**: フラット名の再パースを排除し`hir::Type`ツリーを唯一の真実にした。ネスト型引数のフィールド読み書き・ユーザー定義`Box__int`との共存・`T[N]`フィールドのstrideが正しくなった。可逆型キーの`typekey`モジュールを追加した。
- **型付きHIRの単一情報源化**: 「型検査後のHIRは全式が非null・非error型」の不変条件を型監査ウォーカー+regression常時検証で確立し、checkerが走査しない式（演算子impl本体・for-in脱糖・switchパターン・ジェネリックメソッド引数等）の6クラスを上流修正した。設計文書: [typed-hir-single-source.md](../archive/v0.17.0/type-system/typed-hir-single-source.md)
- **集約に入るインターフェイス値（H1/H2)**: 構造体フィールド・配列・スライスへの格納でfat pointerが正しく構築され、ポリモーフィックコレクションが使えるようになった。
- **インターフェース戻り値のペイロードboxing（Q3)**: `Shape make() { return Rect{...}; }`のfat pointerが呼び出し先スタックを指したまま返りダングリングになっていた（O0のみ偶然動作・O2でゴミ値・wasmで誤値）。upcast時のペイロードをヒープboxing化して全経路を修正し、jsの転送引数の再ラップ（vtable未定義参照）も解消した。設計文書: [interface-return-fat-pointer.md](../archive/v0.17.0/interfaces-derive/interface-return-fat-pointer.md)
- **ネストしたジェネリック型引数のstringフィールド読みが無言死（Q2)**: `Pair<Box<int>, Box<string>>`のstring側フィールド読みでrc=0のまま無言終了していた（全バックエンド・checker無診断）。真因は2系統で、特殊化シンボルキーの曖昧フラット名（`Pair__Box__int__Box__string`の誤逆算でフィールドがint 4バイトにレイアウトされる）を複数引数基底×特殊化引数のとき`$`エンコードへ退避し、内側リテラルの型注釈がフィールド宣言型のジェネリックパラメータ名`A`で上書きされ裸の`Box`のままlowerされる問題（stringポインタの指す先を4バイト整数として書き込む）をchecker伝播の上書き抑止+実引数置換で修正した。ネスト特殊化マトリクス（逆順・3型引数・逆ネスト・関数戻り値・チェーン読み）の回帰をjit/native O0〜O3/wasm/jsで追加した。設計文書: [nested-generic-type-arg-string.md](../archive/v0.17.0/type-system/nested-generic-type-arg-string.md)
- **for-inイテレータプロトコルの検査（Q1)**: `iter()`発見時にイテレータ型へ`bool has_next()`と要素型を直接返す`next()`の実装を検査し、欠如・bool以外の`has_next`戻り値・`Option<T>`返し`next()`を診断エラーにした（従来はhas_next欠如が未解決シンボルのリンクエラー、Option返しはループ変数が`Option<T>`のまま的外れな型エラーになっていた）。Option返し`next()`はプロトコル外と仕様決定し、チュートリアルへ`iter()`プロトコルの節を新設した。設計文書: [forin-iterator-protocol-checks.md](../archive/v0.17.0/syntax-parse/forin-iterator-protocol-checks.md)
- **ポインタ・配列引数からの型パラメータ推論（R3)**: `<T> void swap(T* a, T* b)`や`<T> T first(T[] xs)`のように型パラメータがポインタ・配列の内側に現れる引数で、`T`が推論されず型未解決のままcodegenへ落ちて全経路SIGSEGVしていた。型推論を宣言型と実引数型の構造再帰マッチへ置換し（`T*`↔`int*`・`T[]`↔`int[]`・多段`T**`・ネストしたジェネリック構造体を一様に扱う）、あわせてLLVM codegenのプリミティブimplメソッド用selfコピー最適化が特殊化名（`deref__int`）の`T*`引数を誤ってselfと判定していた条件（第0引数名が`self`のときのみ適用）も修正した。設計文書: [generic-pointer-param-inference.md](../archive/v0.17.0/type-system/generic-pointer-param-inference.md)
- **確定代入・return網羅の検査（H6/L4)**: 分岐fork/joinの初期化追跡とreturn漏れ警告を導入し、`--strict`でエラーへ昇格した。
- **const集約の段階的強制（M3)**: constフィールドへの深い代入・const値への非constポインタ取得をcheck/lint警告にした（エラー化は将来バージョン）。
- **マングリング衝突検出（C16)**: 単一シンボルテーブルで同名縮退をコンパイルエラーにし、マングル規則を`base/mangle.hpp`へ集約した。

### バグ修正: 混合数値二項演算の暗黙昇格（Y4）

### バグ修正: 型検査のエラー検出漏れ3件（Z4）

エラーパターンテスト整備で発覚した検出漏れを診断化した。
- スライスpush引数の型不一致（`int[]`へ`"s"`）が無検査でエラー型が下流へ漏れ内部エラーになっていたのを、要素型との互換検査（ユニオン要素への変種値pushは互換）と専用診断で拒否

- ループ外の`break`/`continue`が黙って消えていたのを、ループ深度追跡で診断（Cmのswitchは自動breakのため明示break/continueはループ専用）

### バグ修正確認: 構造体内ユニオンフィールドのタグ読みwasm分裂（Z3）

`string[2]`等を含む構造体のユニオンフィールドで`is`判定がnative/jit=true・wasm=falseに分裂していた事象は、コミット単位のバイセクトによりY1〜Y3（ユニオン構築の消費サイト統一）で解消されたことを確認した。

フィールド位置（先頭/中間/末尾）×前置フィールド型（string配列・int・構造体）×is/asペイロード/再代入のマトリクス回帰テスト（union_field_tag_layout）をnative/jit/wasm/jsの4系一致で追加した。

### バグ修正: スライスof固定長配列（T[N][]）の格納表現統一（Y6）

要素型が固定長配列のスライスで、pushがヘッダ格納（push_slice）・読みがblob仮定と表現が食い違い、要素が全経路でゴミ値になっていた。

wasm32では固定長string配列要素のelem_sizeがスロット規約（8固定）と実レイアウト（ポインタ4）で不一致になるため、固定長要素は配列実ストライドのN倍で計算する。
