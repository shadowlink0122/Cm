# Cm v0.17.0 リリースノート（開発中）

**前バージョン:** v0.16.2

## 🎯 テーマ: JS/TSエコシステム連携（npmパッケージ・React/Nodeへの道）

### 標準ライブラリ: 平衡二分探索木マップ（std::collections::TreeMap）

- **`TreeMap<K, V>` を追加**: 自己平衡二分探索木（AVL木）による順序付き連想コンテナ。探索・挿入が **O(log n)** で、線形探索の連想配列より要素数増加に強い。木はインデックス参照のノードアリーナ（パラレルな動的配列）で表現し、ノード参照はポインタでなくindexで持つため全バックエンド（jit/native/wasm/js/ts）で同じ動作をする
- キー型 K は順序比較（`<`・`==`）が必要（int/string等は組み込み、構造体は `with Ord, Eq`）。値型 V は任意。API: `put`/`get`/`contains`/`size`。挿入ごとにAVL回転で平衡化し、ソート済みキーでも高さが対数に収まる（100件ソート挿入で高さ約7）
- ノードアリーナは動的配列（スライス）で、`put` のたびに容量が足りなければGoのスライスと同様に容量が2倍ずつ自動拡張される。要素数に固定上限は無く、固定長配列を使わないので native の AOT 最適化コンパイル時間も要素数に依存しない（treemap_testの -O2 コンパイルは約0.7s）
- あわせて動的配列（スライス）まわりのコンパイラ・ランタイムバグを修正:
  - **implメソッド内の `self.slice_field.push(x)` 等が黙って捨てられていた問題を修正**: メンバスライスの場所を解決する `get_member_place` が、implメソッドの `self`（`*Struct` ポインタ）を土台にできず false を返していたため、`self.items.push(...)` のような文がMIRから丸ごと欠落していた。ポインタ土台のときは Deref を挟んで pointee 構造体からフィールドを辿るよう修正。構造体フィールドの動的配列が全バックエンドで正しく in-place 更新される
  - **ジェネリックなスライスフィールドの要素サイズが誤っていた問題を修正**: 型置換 `substitute_type_in_type` に配列（`Array`）ケースが無く、`K[]` の要素型が未解決（`K`）のまま残っていた。要素サイズ計算がこれをblob扱いして `int` を12バイトとみなし、push（4バイト書き込み）とindexアクセスの stride が食い違っていた（バッファに余裕のないwasmで木構造が壊れた）。`Array` の element_type を再帰置換するよう修正
  - **WASMのバンプアロケータがプール枯渇時に生きている割り当てを上書きしていた問題を修正**: 64KB固定プールを使い切ると先頭へ巻き戻して既存データを踏み潰していたため、スライスを多用する処理が一定サイズで構造体フィールドやスライスヘッダを壊していた。巻き戻しをやめ、枯渇後は `memory.grow` で線形メモリを拡張して新領域から配るようにした。あわせてWASMの `cm_slice_grow` が旧ブロックサイズ超えでコピーしていた点と、`cm_free` がWASMランタイムに未定義だった点を修正
  - **ジェネリックのモノモーフ化を不動点まで反復するよう修正**: メソッドチェーン `A()->B()->C()...` で、内部からのみ呼ばれる特殊化（3段目以降）が生成されずリンクエラーになっていた（パス上限が2固定だった）。上限を上げて新規特殊化が尽きるまで反復する。ジェネリックなコレクション実装（TreeMapの内部ヘルパ・AVL回転等）が動くようになった
  - **コード生成の複雑度ガードの誤検出を修正**: `estimateMaxLoopDepth`（PHI数ヒューリスティック）でループ深度を掛けて複雑度を過大評価し、多数の関数を持つ正当なコード（ジェネリック展開等）を「無限ループ/過剰複雑度」と誤判定していた。ループ実行回数はコード生成コストと無関係なため乗算を撤去し、しきい値を調整（真の暴走はコード生成の30秒タイムアウトで捕捉）

### 標準ライブラリ: 純粋なCmで書いたJSONパーサ（std::json）

- **`std::json` を追加**: JSON文字列のパース・アクセス・直列化を純粋なCmで実装。再帰的なJSONツリーを固定容量のアリーナ（ノード配列＋インデックス）で表現し、再帰型やポインタを使わないため全バックエンド（jit/native/wasm/js/ts）で同じ動作をする
- API: `json_parse(text) -> int`（ルートノードindex、失敗で-1）、`json_kind`/`json_bool`/`json_number`/`json_int`/`json_string`/`json_is_null`、配列は `json_array_len`/`json_array_get`、オブジェクトは `json_object_get`/`json_object_has`、`json_stringify` でコンパクト直列化
- 文字列エスケープ（`\" \\ \/ \n \t \r \b \f`）・数値（符号・小数・指数）・ネスト・空白に対応
- 容量は既定1024ノード（グローバルなノード配列の固定長。必要ならソースで拡張可）

### libsの単体テスト基盤（#[test] を使った *_test.cm と test-libs ランナー）

- **ライブラリ自身のテストを、テスト対象と同じディレクトリの `*_test.cm`（`#[test]` 属性付き関数）に置けるようにした**: コンパイラのテスト（`tests/`）とは分離し、`libs/web/html_test.cm`・`libs/std/json/mod_test.cm` のようにlib同梱でテストを書く
- **`make test-libs`（ランナー `tests/libs/run.sh`）を追加**: `libs/**/*_test.cm` を再帰的に discover し `cm test`（JITフロー）で実行する。既存の全体テスト（`make test`）にも組み込み
- `#[test]` 属性と `cm test` 自体は既存機能。今回はlib向けの配置規約とランナーを整備した

### バグ修正: 名前解決・JSコード生成

- **ローカル変数・引数がimportした引数なし関数と同名のとき、native/jitで不正な結果になる問題を修正**: 例えば `web::html` の `title()` と同名の引数 `title` を `text(title)` に渡すと、HIR loweringがローカルスコープを持たず `func_defs_` の有無だけで関数参照と判定していたため、MIR loweringが `resolve_variable` より前に関数参照へ倒していた。ローカルが解決できる場合は関数参照より優先するよう修正（js/tsはJSのスコープで偶然正しく、native/jitのみ壊れていた）
- **構造体フィールドが構造体配列のとき、JS出力で各要素が `undefined` になり要素代入で落ちる問題を修正**: `Array.from({length: N}, () => {})` はアロー本体の空ブロックと解釈され `undefined` を返していた。要素を括弧で包んで（`() => ({...})`）オブジェクトを返すよう修正。インメモリのアリーナ・ストア構造がjs/tsで正しく動くようになった
- **`string + char` の連結がJSで `cm_char_to_string is not defined` で落ちる問題を修正**: loweringが挿入する組み込み `cm_char_to_string` をJSバックエンドが未対応だった。`String.fromCharCode` へ写像した（JSではcharは数値表現）
- **構造体の配列フィールドへの要素アクセスで配列全体をコピーしていた問題を修正（LLVM最適化スケーリング）**: `struct.arrayField[i]` の読み出しを、MIRが「配列フィールド全体を一時変数へコピー→インデックス」に分解していたため、固定長配列 `[N x T]` の巨大なload/storeが生成され、SROA→InstCombineが配列サイズに対し超線形（実測でO(N²)）に膨張していた（native/jitで大きな配列だとコンパイルが極端に遅くなるか複雑度ガードで中断）。MIR loweringを修正し、メンバアクセスの場所（MirPlace）を土台にIndexプロジェクションを積んで要素だけをコピーするようにした。これによりコンパイル時間が配列サイズに依存しなくなり（arena[16384]でも約0.3s）、生成コードも配列全体コピーが消えて高速化する。`std::json` のアリーナ容量を48→1024へ引き上げられた

## ✨ 改善

### import/export: 配列戻り値型のexport関数がimport時に抽出漏れする問題を修正

- **`export Point[] all()` のような配列・構造体配列を戻り値型に持つexport関数が、選択的import（`import ./mod::{all}`）で抽出されず関数シグネチャ行が落ちる問題を修正**: プリプロセッサのexport抽出（`filter_exports`）の型名パーサが後置配列サフィックス `[]` / `[N]` を扱えず、`export <型>[] 名()` を未マッチのまま破棄していた（`export` を含むためパススルーもされず消えていた）。型パーサへ配列サフィックスのスキップを追加
- **FFIブロック（`use "pkg" { ... }`）を含むモジュールのexport抽出を修正**: `use` ブロックが行単位でしかスキップされずブロック本体・閉じ括弧が誤処理されてブレース深度がずれ、後続のexport定義が壊れていた。`use` ブロックをstruct/impl同様にブロック全体スキップへ変更
- **externFFI宣言の引数に配列型（`T[]` / `T[N]`）を書けるようにした**: `use "react" { string renderList(Item[] items); }` のように構造体配列をFFI境界で渡せる（externパーサへ後置配列型を追加）
- これらにより、構造体を共有する多ファイルモジュール構成（models/db/view/server 等）でWebアプリを組める。回帰テスト `tests/js/modules/array_export_import` を追加
- 既知の問題: import経由で**ローカル配列をスライスとして返す**関数はnative/jitでライフタイム（ダングリング）により失敗する（JS/TSはGCのため動作）。返す配列はヒープ確保するか呼び出し側で確保する

### TypeScriptバックエンド（--target=ts）: 型注釈付き出力とフロントエンド連携

- **`cm compile --target=ts` でTypeScriptを出力できるようになった**: Cmは静的型付け言語のため型情報を保ったTS出力を第一級サポートする。`--target=js` と同一のコード生成に加え、関数シグネチャ・ローカル・構造体フィールドへ型注釈を付与し、`struct` を `export interface` として出力する
- **型写像**: 数値→`number`、`string`→`string`、`bool`→`boolean`、配列→`T[]`、関数型→`(a: T)=>R`、async戻り値→`Promise<T>`。ポインタ/参照・タグ付きユニオン（Result/Option）・ジェネリック・interfaceはランタイム表現が定まらないため `any`。素の構造体のみ interface 名を型として使う
- **型検査を通る出力**: `@types/node` へ依存せず `require`/`process`/`module`/`console` をambient宣言。生成TSは `tsc --noEmit --lib es2020` で型エラーなく通る
- **実行**: `cm run --target=ts` は型注釈除去のJSツイン（生成JSと同一）を生成してNode実行（Node v23.6未満でも動作）
- **フロントエンド連携**: `use` 宣言の引数に固定長配列 `T[N]` / スライス `T[]` を書けるようになり（extern型パーサへ後置配列型を追加）、構造体配列をJSのオブジェクト配列としてReact等へ渡せる。JS関数が返す `undefined` もCm側で受け取れる
- **TS型検査ゲートが検出した既存バグを修正**: (1) `with Css` の `to_css` 戻り値のvoid誤判定 (2) `char` の既定値が `""`（数値表現と不一致）だったのを `0` に (3) fat pointerの間接参照・書き込みをインライン展開から `__cm_deref`/`__cm_deref_set` ランタイムヘルパーへ集約 (4) panic/exitのIIFEが値を返さずvoid型不一致になっていたのを修正。いずれもJS出力にも潜在していた
- **テスト**: `tests/ts/`（`make test-ts`）を新設。焦点テスト（型注釈・tsc型検査・実行。React/Node fixtureのFFI・構造体配列・undefinedを含む）に加え、`tests/common` + `tests/js` の全コーパス（JS受理の410プログラム）を `--target=ts` でコンパイルし全て有効なTSを生成することを保証する広域ゲート。CIのToolingジョブへ組込み
- チュートリアル `docs/tutorials/{ja,en}/compiler/js/index.md`（TypeScript出力の節）・`npm-interop.md`（フロントエンド開発の節）を追加
- **`//! platform: ts` ディレクティブに対応**: TSバックエンド向けファイルに `//! platform: ts` を書ける（tsとjsは同一のNode実行系のため相互に等価なプラットフォームとして扱う）

### Cmだけで完結するWeb開発（vendor JS・手書きグルー不要）

- **`web::html` ライブラリを追加**: 構造体ベースのHTMLビルダーを `libs/web/html.cm` に集約。文字列連結ではなく `div().class("card").add(h1().add(text(title)))` のようにHtml構造体を積んでHTMLを組み立てる。ビルダーメソッドはselfを変更せず新しいHtmlを返す純粋設計のため、値セマンティクス（native/wasm/jit）と参照セマンティクス（js/ts）で同一の出力になる。テキスト・属性は自動でHTMLエスケープする
- **FFIオブジェクトのクローン破壊を修正（js/ts）**: 関数型フィールドを持つ構造体（＝JSメソッドを束ねた外部オブジェクト。`http.Server` 等）を変数へ代入するとき深いクローン（`__cm_clone`）していたため、プロトタイプ上のメソッドが失われ `this` 束縛も壊れていた。関数型フィールドを持つ構造体は参照コピーへ変更し、`use "http" { Server createServer(...); }` で得たNodeサーバの `.listen()` が正しく呼べるようになった
- **透過的インポート（別モジュール経由のlib取り込み）を修正**: モジュールAが `import web::html::*` し、そのAを別モジュールBが `import ./A::{f}` と選択的インポートすると、透過的に取り込んだ `web::html` のexport関数・impl・structが `filter_exports` に「未指定のexport」とみなされ落ちていた。(1) インポート展開マーカー内は選択フィルタの対象外として素通しする (2) impl は対象型が出力に残るなら一緒に残す、の2点を修正。多ファイル構成でlibを間接利用できる。回帰テスト `tests/common/modules/transitive_lib_import` を追加
- **`examples/web-fullstack/` をvendor JSゼロのCm完結構成へ全面刷新**: HTTPサーバはNode組み込みの `http`（`require("http")` はNode標準でvendor不要）だけで立て、DBはCmのインメモリストア、HTML/CSS/ルーティング/レスポンス組み立てはすべてCmで書く。以前のReact/Express/pgのFFIラッパ（`vendor/*.js`）を撤廃し、外部JS・JSONを一切書かずに `cm compile --target=js src/server.cm -o server.js && node server.js` で動くタスク管理Webアプリになった。`struct Task` が全層を貫く型になる。モジュール依存はview（ストア/スタイル/HTMLビルダーのファサード）を頂点にした一本道で、diamond importによる重複を避ける
- **インメモリストアを固定長配列から可変長スライスへ置換**: `store.cm` の `Task[32] items`＋件数管理を `Task[] items`＋`push`/`len` に変更。TSバックエンドではスライスがJS配列に対応し、`push`・`len`・要素更新・`filter` 等がそのまま動く（固定容量の上限もなくなる）
- **旧 `examples/web-app` を削除**: `with Css` のデモは web-fullstack（`src/style.cm`）に集約したため撤去
- **構造体スライスのテストを追加**: `tests/common/array/struct_slice.cm`（全バックエンド共通の基本操作: push/len/添字/for-in/引数/戻り値/要素更新）、`tests/js/slice/struct_slice_methods.cm`（js/ts向けの高階メソッド filter/map/indexOf/includes/pop・構造体メンバスライス）、`tests/ts/cases/struct_slice.cm`（TS出力の型検査）。CIの `make test-ts`（tests/common+tests/js をTS化する広域ゲートを含む）で継続検証する
- 既知の問題: ローカル変数・引数が、インポートした引数なし関数（`web::html` の `title()` 等）と同名の場合、native/jitで名前解決を誤り不正な結果になることがある（js/tsは正しく解決する）。同名を避ける。またスライスの高階メソッド（filter/map/indexOf/includes/pop）や構造体メンバ・グローバルへのミューテーションはjs/tsで動作し、native/jitでは基本操作（push/len/添字/for-in）に限られる（スライスはTS/JS向け機能）

### JSバックエンド: npmパッケージ連携の確立と関数型フィールドの呼び出し対応

- **`use "パッケージ名" { 宣言 }` によるnpm/Node組み込みモジュール連携をテスト・ドキュメントで正式化**: 構造体はJSオブジェクトとしてフィールド名保持で相互に渡り（変換不要）、関数ポインタ・ラムダはJS関数としてそのまま渡せることを検証した
- **構造体の関数型フィールドをメソッド構文で呼び出せるようになった（`obj.field(args)`）**: JSオブジェクトのメソッド（関数値プロパティ）をCmから自然に起動できる。呼び出し先をメンバPlaceのまま保持して `obj.method(args)` を直接出力するため、**JSのthis束縛が保持される**。native/wasm/jitでも同様に動作する（HirCall::indirect_callee新設、型チェッカのフィールドフォールバック、文字列補間ミニパイプライン対応を含む）
- **LLVMコード生成のバグ修正**: 関数参照代入のSSAショートカットが投影を無視し、`ops.apply = f` のようなフィールド代入で構造体ローカルのスロットが関数値に上書きされてSEGVになっていた問題を修正（native/wasm/jitの関数型フィールドが動作するようになった）
- **JS FFIテスト基盤**: ローカルfixtureパッケージ（`tests/js/ffi/node_modules/cmtestpkg`、npm install不要）を新設し、テストランナーが `NODE_PATH` で解決する。構造体互換・コールバック・メソッドthis束縛・組み込みモジュールの4テストと全バックエンド共通の関数型フィールドテストを追加
- チュートリアル `docs/tutorials/{ja,en}/compiler/js/npm-interop.md` を新設。実装設計は `docs/archive/v0.17.0/01_js_npm_interop.md`、React/TS対応ロードマップは `docs/design/js_interop_roadmap.md`
