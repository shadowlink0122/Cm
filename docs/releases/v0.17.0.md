# Cm v0.17.0 リリースノート（開発中）

**前バージョン:** v0.16.2

## 🎯 ハイライト

- **TypeScript出力（`--target=ts`）とCm完結のWeb開発**: 型注釈付きTSを第一級サポートし、npm/Node連携・HTMLビルダー（`web::html`）・vendor JSゼロのフルスタックexampleを整備した。
- **js/tsのlong/ulongをBigInt化（H5）**: 2^53超の64bit値が全バックエンドで精度一致するようになった。
- **標準ライブラリの拡充**: TreeMap・JSONパーサ・StringBuilder・OS連携モジュール（env/process/path/bytes/fs/args）を追加した。
- **文字列基盤の刷新（H9全5段）**: `len()`のUTF-8コードポイント化・O(1)バイト長・埋め込みNUL対応・連結チェーンの単一バッファ化。
- **メモリ管理の完結（C12/C13）**: コンパイラ一時・ループ内RAII・文字列再代入・wasmアロケータまで、リークしていた全系統を解放するようになった。
- **モジュールシステムの構造化**: importのテキストインライン展開を廃止し、ファイル単位パースのモジュールグラフ+AST駆動の選択的包含へ全面移行した。
- **大規模開発ボトルネック監査（57所見）と構文網羅検証（36件）の全件対応**: 4ラウンドの検証で検出した誤コンパイル・クラッシュ・バックエンド分裂をすべて修正した。
- **コンパイラ基盤の大規模内部再編**: 層依存規律・診断エンジン・ランタイムレジストリ・型付きHIR・型駆動モノモーフ化など、設計文書10本超の構造的リファクタリングを完遂した。

実装の詳細・設計判断は `docs/archive/v0.17.0/` の各設計文書に記録している。

## 💥 破壊的変更・移行が必要な変更

- **文字列`len()`がUTF-8コードポイント数になった**: バイト数が必要な箇所は`byte_len()`へ移行する（ASCIIのみの文字列は挙動不変）。`substring`/`slice`/`indexOf`の添字もコードポイント単位へ統一した。
- **HashMap/TreeMapの`get`が`Option<V>`を返す**: 従来の`int v = m.get(k);`は`m.get_or(k, 0)`または`m.get(k).unwrap_or(0)`へ移行する（旧getは不在キーで未初期化メモリ等を返す危険な契約だったため）。
- **std独自の`CmResult`を撤去（M17）**: 組み込み`Result`/`Option`+`?`の1系統へ統合した。
- **非exportシンボルの選択importがエラーになった（H7）**: `import mod::{fn}`で非export関数は取り込めない（定義に`export`を付けるかexportリストへ追加する）。
- **マングリング名の衝突がコンパイルエラーになった（C16)**: 従来は同名縮退で片方が黙って上書きされていたため、実質的な破壊的変更ではない。
- **数値→stringの`as`キャストを型検査で拒否（C10）**: 従来はバックエンドによりSIGSEGV・空文字・正常と5分裂していた。
- **enumの複数ペイロード宣言（`R(int, int)`）を診断付きエラー化（N6)**: 設計上単一ペイロードのため（構造体で包む回避策を案内する）。
- **js/tsの構造体関数引数が値渡しになった（H3)**: LLVM系と意味論を統一した（implメソッドのself等は参照渡しを維持）。
- **キャプチャ付きクロージャのユーザー関数への引き渡しは診断付きエラー（V5〜V7)**: 従来はゴミ値・未解決シンボルの黙殺だった（ローカル束縛+直接呼び出し・組み込み高階関数は従来どおり動作）。

## 🚀 言語・構文

- **`var`を`auto`の別名キーワードに追加（L3)**: `var x = 42;`が型推論として動く。
- **`assert_eq`/`assert_ne`を`std::debug`へ追加（L6)**: 失敗時に期待値・実測値を表示して異常終了する（`<T: Eq>`ジェネリック）。
- **`std::env::args()`でコマンドライン引数を取得**: `cm run file.cm -- <args...>`にも対応した（`int main()`の言語仕様は不変）。
- **シフト量の仕様を「型幅でmod」に確定（V8)**: `1 << 32`が全バックエンド・全最適化レベルで一致する。
- **privateフィールド・メソッドの可視性を確定（X2/X6)**: 外部からのprivateフィールドアクセスは診断付きで拒否され、可視性は構造体単位（C++のprivate相当）。
- **ジェネリックのインスタンス化診断（H15/L8)**: 型引数なし使用・未定義型引数・明示型引数の個数不一致をエラー化し、境界未宣言の比較演算子使用を警告する。
- **文字列補間のネスト誤パースを修正（L2)**: プレースホルダ内の構造体リテラル波括弧・引用符を正しく扱う。
- **縮小キャストの切り捨て警告（M4)**・**パーサの固定上限撤廃（M5)**。

## 📚 標準ライブラリ

- **`std::collections::TreeMap<K, V>`**: AVL木の順序付き連想コンテナ（探索・挿入O(log n)）。ノードアリーナ方式で全バックエンド同一動作、容量は自動拡張する。
- **HashMapの容量自動拡張（Q7)**: 従来はresize未実装で初期容量16を超えるinsertが黙って喪失していた（`get`がNone・データ喪失）。負荷率50%で容量を2倍へ拡張し全エントリを再ハッシュする`grow()`を実装した。設計文書: [hashmap-resize-loses-entries.md](../archive/v0.17.0/hashmap-resize-loses-entries.md)
- **`std::json`**: 純粋Cm実装のJSONパーサ・アクセサ・直列化（アリーナ方式・全バックエンド同一動作）。
- **`std::strings::StringBuilder`（H9)**: 償却O(1)追記でループ連結のO(n²)を解消する。`split`/`lines`/`from_bytes`も追加した。
- **OS連携モジュール（セルフホスト準備）**: `std::env`（get/set/args/current_exe）・`std::process`（run/output）・`std::path`・`std::bytes`（エンディアン指定バイト詰め）・`std::fs`拡張（create_dir/read_dir/read_bytes/write_bytes。バイナリ安全I/O）。CLIツールの一巡を`examples/07_selfhost_drill/`でCI検証する。
- **ioのパース関数をOption返しへ（M17)**: `parse_int`等が失敗を0で握り潰さず`None`を返す。
- **アロケータ差し替えのCm到達可能化（M14)**: `std::mem::set_allocator_fns`/`reset_allocator`で`std::mem`経由の全確保に反映される。
- **libsの単体テスト基盤**: lib同梱の`*_test.cm`（`#[test]`）と`make test-libs`ランナーを整備した。

## 🧵 文字列（H9全5段完結）

- **`len()`をUTF-8コードポイント数へ変更し、`byte_len()`・`codepoint_at()`・`chars()`を追加**: バックエンド間の意味分裂（native=バイト・js=UTF-16）を解消した。
- **長さヘッダ付き文字列（SDS方式）**: char*完全互換の隠しヘッダで`byte_len()`がO(1)になり、埋め込みNUL（0x00）を保持する。FFIへはNUL終端char*のままゼロコストで渡せる。
- **連結チェーンの単一バッファ化**: `a + b + c + d`を1回の確保に集約し、チェーン再代入ループで約2倍高速化した。
- 設計文書: [strings-utf8-and-stringbuilder.md](../archive/v0.17.0/strings-utf8-and-stringbuilder.md)

## 🗂 モジュールシステム

- **構造化importへの全面移行**: テキストインライン展開（約2,800行）を削除し、ファイル単位パースのモジュールグラフ+AST駆動の選択的包含が唯一の実装経路になった。選択import・項目エイリアス・モジュール形import（namespace）・階層再export・ディレクトリワイルドカードを型・AST情報で解決し、診断はファイル直参照の座標で表示される。設計文書: [module-system-structural-imports.md](../archive/v0.17.0/module-system-structural-imports.md)
- **同名シンボルの多重importを診断エラー化（M2)**: 先勝ちの黙殺をやめ、エイリアスか修飾名を案内する。
- **選択importの重複排除と型名itemの解決（M7)**: `import std::collections::Vector;`のDuplicate method失敗・プラットフォーム依存の誤解決を修正した。
- **非export関数のカプセル化を強制（H7全4段)**: 選択importはエラー、複製ヘルパーの非修飾公開は`__cm_priv_`遮断で抑止する。
- **import抽出の修正**: 配列戻り値型export関数の抽出漏れ・FFIブロック混在・透過的インポート（lib間接利用）を修正した。

## 🧠 型システム・型検査

- **ジェネリック特殊化の型同一性を構造化（C7/C8/C9)**: フラット名の再パースを排除し`hir::Type`ツリーを唯一の真実にした。ネスト型引数のフィールド読み書き・ユーザー定義`Box__int`との共存・`T[N]`フィールドのstrideが正しくなった。可逆型キーの`typekey`モジュールを追加した。
- **型付きHIRの単一情報源化**: 「型検査後のHIRは全式が非null・非error型」の不変条件を型監査ウォーカー+regression常時検証で確立し、checkerが走査しない式（演算子impl本体・for-in脱糖・switchパターン・ジェネリックメソッド引数等）の6クラスを上流修正した。設計文書: [typed-hir-single-source.md](../archive/v0.17.0/typed-hir-single-source.md)
- **集約に入るインターフェイス値（H1/H2)**: 構造体フィールド・配列・スライスへの格納でfat pointerが正しく構築され、ポリモーフィックコレクションが使えるようになった。
- **インターフェース戻り値のペイロードboxing（Q3)**: `Shape make() { return Rect{...}; }`のfat pointerが呼び出し先スタックを指したまま返りダングリングになっていた（O0のみ偶然動作・O2でゴミ値・wasmで誤値）。upcast時のペイロードをヒープboxing化して全経路を修正し、jsの転送引数の再ラップ（vtable未定義参照）も解消した。設計文書: [interface-return-fat-pointer.md](../archive/v0.17.0/interface-return-fat-pointer.md)
- **ネストしたジェネリック型引数のstringフィールド読みが無言死（Q2)**: `Pair<Box<int>, Box<string>>`のstring側フィールド読みでrc=0のまま無言終了していた（全バックエンド・checker無診断）。真因は2系統で、特殊化シンボルキーの曖昧フラット名（`Pair__Box__int__Box__string`の誤逆算でフィールドがint 4バイトにレイアウトされる）を複数引数基底×特殊化引数のとき`$`エンコードへ退避し、内側リテラルの型注釈がフィールド宣言型のジェネリックパラメータ名`A`で上書きされ裸の`Box`のままlowerされる問題（stringポインタの指す先を4バイト整数として書き込む）をchecker伝播の上書き抑止+実引数置換で修正した。ネスト特殊化マトリクス（逆順・3型引数・逆ネスト・関数戻り値・チェーン読み）の回帰をjit/native O0〜O3/wasm/jsで追加した。設計文書: [nested-generic-type-arg-string.md](../archive/v0.17.0/nested-generic-type-arg-string.md)
- **for-inイテレータプロトコルの検査（Q1)**: `iter()`発見時にイテレータ型へ`bool has_next()`と要素型を直接返す`next()`の実装を検査し、欠如・bool以外の`has_next`戻り値・`Option<T>`返し`next()`を診断エラーにした（従来はhas_next欠如が未解決シンボルのリンクエラー、Option返しはループ変数が`Option<T>`のまま的外れな型エラーになっていた）。Option返し`next()`はプロトコル外と仕様決定し、チュートリアルへ`iter()`プロトコルの節を新設した。設計文書: [forin-iterator-protocol-checks.md](../archive/v0.17.0/forin-iterator-protocol-checks.md)
- **確定代入・return網羅の検査（H6/L4)**: 分岐fork/joinの初期化追跡とreturn漏れ警告を導入し、`--strict`でエラーへ昇格した。
- **const集約の段階的強制（M3)**: constフィールドへの深い代入・const値への非constポインタ取得をcheck/lint警告にした（エラー化は将来バージョン）。
- **マングリング衝突検出（C16)**: 単一シンボルテーブルで同名縮退をコンパイルエラーにし、マングル規則を`base/mangle.hpp`へ集約した。
- **数値変換の暗黙/明示の境界を確定（Z5)**: 変換分類（拡大=暗黙・縮小/符号変化=要as）を`classify_numeric_conversion`へ一元化し、let/代入/returnの縮小・符号変化を警告（`--strict`でエラー）にした。適合リテラルと`uint/usize→int`（len/sizeofイディオム）は無診断。受理された`double→int`等の変換命令欠落（ゴミ値・LLVM検証エラー・js素通しの3様分裂）を全文脈で修正し、CANONICAL_SPEC 10.3に変換表を明文化した。設計文書: [implicit-explicit-cast-design.md](../archive/v0.17.0/implicit-explicit-cast-design.md)

## 🧹 メモリ管理（C12/C13完結）

- **コンパイラ一時のdropパス（C12全系統)**: 文字列一時・スライス一時（map/filter中間）・条件腕内一時・三項結果一時・文字列再代入の旧バッファを、エスケープ解析つきで全最適化レベル解放するようにした。代表実測: 一時連結の100万回ループでRSS 97.8MB→1.4MB。
- **ループ本体のRAII（C13)**: while/for本体・break/continue経路でデストラクタが毎周期実行される。ネストジェネリックのデストラクタ連鎖（M15）・move済み変数の二重解放も修正した。
- **wasmアロケータの解放対応（H11)**: 単調バンプをフリーリスト+`memory.grow`へ置き換え、`free`/`realloc`が実際にブロックを返却・再利用する。
- **move後使用の診断強化（H12の一部)**: フィールド経由move・補間内のmove後使用を検出する。
- 設計文書: [memory-drop-and-lifetime.md](../archive/v0.17.0/memory-drop-and-lifetime.md)・[allocator-and-temp-pool.md](../archive/v0.17.0/allocator-and-temp-pool.md)

## ⚡ コンパイル時間・生成物サイズ

- **大構造体のsret化とmemcpy化（C14全Phase)**: `int[16384]`フィールド構造体の戻り値がO2で60秒超→0.6秒、代入が24秒→約0.2秒になった。値渡し引数の隔離バグも修正した。
- **モジュール別キャッシュと並列コード生成（H14・実験的)**: `CM_MODULE_CODEGEN=1`でMIR内容ハッシュの.oキャッシュ+ワーカ並列コンパイルになる（ウォームで全コード生成スキップ）。
- **コード生成タイムアウトのプロセス分離（M6)**: fork+SIGKILLで暴走LLVMの計算資源を確実に回収する（`CM_CODEGEN_TIMEOUT`で上書き可能）。
- **ジェネリック特殊化の同一コード折り畳み（M10)**: O2以上でLLVM MergeFunctionsを有効化した（符号性で命令が異なる本体は対象外のため意味論不変）。
- **構造体配列フィールドのアクセス爆発を解消**: 要素読み出しの配列全体コピーをやめ、コンパイル時間が配列サイズに依存しなくなった。
- **リンク長時間化の切り分け警告**: セキュリティソフトによるリンカブロックを10秒超で警告する。

## 🎯 バックエンド統一・数値意味論

- **double出力の最短round-trip化とfloat→intキャストの飽和（M8/M9)**: 3分裂していた数値出力・キャスト結果を全バックエンドで統一した（`1e20 as int`は`2147483647`）。
- **整数拡張の符号規則を統一**: 等値比較・混合幅算術・シフトの拡張が「拡張されるオペランド自身の符号」基準になり、`ushort(60000) + 1`等のバックエンド分裂を解消した（sitofp誤用・三項腕の型昇格・代入の拡大変換も同基準へ）。
- **jsの整数キャスト・ビット演算のラップ統一**: `-1 as uint`等がLLVM系の2の補数ラップと一致する。
- **浮動小数の特殊値表記（inf/nan）・大文字小文字変換（ASCII限定）・long/ulongの文字列連結幅**を統一した。
- **スライス境界チェックの全バックエンド統一（M1)**: `--sanitize=bounds`がスライスにも効き、同一メッセージ・終了コードでトラップする。

### バグ修正: 混合数値二項演算の暗黙昇格（Y4）

`double a = d + i;` のような浮動小数×整数の混合二項演算で整数オペランドへのsitofp昇格が挿入されず、形によりLLVMモジュール検証エラー（`fadd i32, double`）または無出力のSIGBUSになっていた（checkerは受理、既存テストはリテラル畳み込み・明示キャストのみで未露見）。
型検査の`infer_binary`が算術・比較の混合オペランドへ昇格Castノードを挿入し（複合代入は宛先型へ右辺を揃える）、MIR loweringに混合到達を診断で停止する防衛層を追加した。
昇格規則はCANONICAL_SPEC.md 10.2に明文化し、回帰テスト（tests/common/types/mixed_numeric_promotion.cm）が全バックエンドで値一致を検証する。

### バグ修正: ユニオン構築（タグ書き込み）の消費サイト統一（Y1〜Y3）

構造体リテラルのユニオンフィールド・ユニオン戻り値のreturn・スライスpush/スライスリテラル要素・デフォルト引数で、変種値がタグ未構築のままペイロード直書きされ、is判定が全変種false・asダウンキャストが実行時パニック（invalid union cast）になっていた。
LoweringContextへ共通ヘルパcoerce_to_union（宛先型がユニオンで値が変種型ならユニオン構築Cast経由の一時を返す）を追加し、return・構造体リテラルフィールド・push引数・スライスリテラル要素・呼び出し引数/デフォルト引数補完の各サイトへ適用した（let初期化・単純代入の既存直接Castは意味論同一のため維持）。
全消費サイトのマトリクス回帰テスト（tests/common/types/union_construction_sites.cm）を追加し、native/jit/wasmで値一致を確認した。
混在変種の三項/match腕（`c ? 1 : 2.5`）は腕の型が先に統一されてからユニオン構築されるため誤変種になる残課題があり、checkerの腕への期待型伝播として別途扱う。

### バグ修正: 配列検索ビルトインの要素型ディスパッチ（Z1）

indexOf/includes/containsが要素型を無視して一律_i32変種を呼び、stringはポインタ切り詰め比較でjit/native/wasmが3様に分裂、short/tiny/longは誤値、float/doubleは不正IRでコンパイル不能だった。

### バグ修正: 固定長配列→スライス変換の要素サイズ統一（Z2）

impl T[]メソッドを固定長配列から呼ぶ際のcm_array_to_slice変換で、HIR脱糖の手書きswitchが要素サイズをshort/tiny=4扱い・構造体/ユニオン=4・ポインタ/文字列=8固定と誤っており、wasm32では文字列要素の読みが1つ飛びに崩れていた（layout-query-unificationの取り残し）。

### バグ修正: 固定長配列→スライス引数の暗黙変換（Y5）

固定長配列をスライス型（T[]）パラメータへ渡すと、checkerは受理するがC流のarray decayで生ポインタが渡り、呼び出し先がCmSlice*として誤読してlen()・要素読みがゴミ値になっていた（メソッドレシーバ経路には変換実装済みで、関数引数経路だけが欠けていた）。
LoweringContextへcoerce_fixed_array_to_slice（宛先がスライスで値が固定長配列ならcm_array_to_sliceでヒープ実体化。要素ストライドはlayout API）を追加し、呼び出し引数・デフォルト引数へ適用した。パラメータ型解決を名前付き関数（HIR定義）に加えて間接呼び出し・関数ポインタ（関数型注釈）へ拡張し、既存のarray decayはパラメータがスライス型の場合に抑止する。

### バグ修正: 型検査のエラー検出漏れ3件（Z4）

エラーパターンテスト整備で発覚した検出漏れを診断化した。
- スライスpush引数の型不一致（`int[]`へ`"s"`）が無検査でエラー型が下流へ漏れ内部エラーになっていたのを、要素型との互換検査（ユニオン要素への変種値pushは互換）と専用診断で拒否
- ユニオンの非変種型への`as`ダウンキャスト（`v as double`）が無診断でペイロードのビット再解釈ゴミ値になっていたのを、`is`と同じ変種集合検査で静的に拒否（同一ユニオンへの恒等キャストは許可）
- ループ外の`break`/`continue`が黙って消えていたのを、ループ深度追跡で診断（Cmのswitchは自動breakのため明示break/continueはループ専用）
エラーテスト4本（push型不一致・非変種as・ループ外break/continue）をtests/common/errorsへ追加した。

### バグ修正確認: 構造体内ユニオンフィールドのタグ読みwasm分裂（Z3）

`string[2]`等を含む構造体のユニオンフィールドで`is`判定がnative/jit=true・wasm=falseに分裂していた事象は、コミット単位のバイセクトによりY1〜Y3（ユニオン構築の消費サイト統一）で解消されたことを確認した。
真因はオフセット計算のポインタ幅仮定ではなく、構造体リテラルのフィールド初期化がタグ未構築のままペイロードを直書きしていたことで、nativeはメモリレイアウトの偶然でタグ一致に見えていた（wasmは実レイアウト差で不一致）。coerce_to_unionによるターゲット非依存のタグ書き込みへ統一されたことで全バックエンド一致となった。
フィールド位置（先頭/中間/末尾）×前置フィールド型（string配列・int・構造体）×is/asペイロード/再代入のマトリクス回帰テスト（union_field_tag_layout）をnative/jit/wasm/jsの4系一致で追加した。

### バグ修正: スライスof固定長配列（T[N][]）の格納表現統一（Y6）

要素型が固定長配列のスライスで、pushがヘッダ格納（push_slice）・読みがblob仮定と表現が食い違い、要素が全経路でゴミ値になっていた。
格納表現を「N×要素実ストライドのインラインblob」に仕様確定し、slice_elem_dispatchをTypePtr受けへ変更して固定長Array要素をBlobクラス（アドレス渡しのblob push/pop）へ分類、layoutのelem_size・codegenのIndex投影（内側スライス判定の可変長限定化、Deref後の固定長配列への添字を要素ストライドGEP化）・let.cppのスライスリテラル経路（表引き化と固定長要素の変換抑止）を同一表現へ揃えた。
wasm32では固定長string配列要素のelem_sizeがスロット規約（8固定）と実レイアウト（ポインタ4）で不一致になるため、固定長要素は配列実ストライドのN倍で計算する。
回帰テスト（slice_of_fixed_array: int/string/long要素×push/読み/書き/pop/リテラル初期化）をnative/jit/wasm一致で追加した。jsバックエンドはblob意味論（element_ptr/pop_blob）が未実装のため既知制限としてスキップし、将来課題に記録した。
