# Cm v0.17.0 リリースノート（開発中）

**前バージョン:** v0.16.2

## 🎯 テーマ: JS/TSエコシステム連携（npmパッケージ・React/Nodeへの道）

## ✨ 改善

### import/export: 配列戻り値型のexport関数がimport時に抽出漏れする問題を修正

- **`export Point[] all()` のような配列・構造体配列を戻り値型に持つexport関数が、選択的import（`import ./mod::{all}`）で抽出されず関数シグネチャ行が落ちる問題を修正**: プリプロセッサのexport抽出（`filter_exports`）の型名パーサが後置配列サフィックス `[]` / `[N]` を扱えず、`export <型>[] 名()` を未マッチのまま破棄していた（`export` を含むためパススルーもされず消えていた）。型パーサへ配列サフィックスのスキップを追加
- **FFIブロック（`use "pkg" { ... }`）を含むモジュールのexport抽出を修正**: `use` ブロックが行単位でしかスキップされずブロック本体・閉じ括弧が誤処理されてブレース深度がずれ、後続のexport定義が壊れていた。`use` ブロックをstruct/impl同様にブロック全体スキップへ変更
- **externFFI宣言の引数に配列型（`T[]` / `T[N]`）を書けるようにした**: `use "react" { string renderList(Item[] items); }` のように構造体配列をFFI境界で渡せる（externパーサへ後置配列型を追加）
- これらにより、構造体を共有する多ファイルモジュール構成（models/db/view/server 等）でWebアプリを組める。回帰テスト `tests/js/modules/array_export_import` を追加
- 既知の問題: import経由で**ローカル配列をスライスとして返す**関数はnative/jitでライフタイム（ダングリング）により失敗する（JS/TSはGCのため動作）。返す配列はヒープ確保するか呼び出し側で確保する

### TypeScriptバックエンド（--target=ts）: 型注釈付き出力とフロントエンド連携

- **`cm compile --target=ts` でTypeScriptを出力できるようになった**: Cmは静的型付け言語のため型情報を保ったTS出力を第一級サポートする。`--target=js` と同一のコード生成に加え、関数シグネチャ・ローカル・構造体フィールドへ型注釈を付与し、`struct` を `export interface` として出力する
- **型写像**: 数値→`number`、`string`→`string`、`bool`→`boolean`、配列→`T[]`、関数型→`(a: T)=>R`、async戻り値→`Promise<T>`。ポインタ/参照・タグ付きユニオン（Result/Option）・ジェネリック・interfaceはランタイム表現が定まらないため `any`。素の構造体のみ interface 名を型として使う
- **型検査を通る出力**: `@types/node` へ依存せず `require`/`process`/`module`/`console` をambient宣言。生成TSは `tsc --noEmit --lib es2020` で型エラーなく通る
- **実行**: `cm run --target=ts` は型注釈除去のJSツイン（生成JSと同一）を生成してNode実行（Node v23.6未満でも動作）
- **フロントエンド連携**: `use` 宣言の引数に固定長配列 `T[N]` / スライス `T[]` を書けるようになり（extern型パーサへ後置配列型を追加）、構造体配列をJSのオブジェクト配列としてReact等へ渡せる。JS関数が返す `undefined` もCm側で受け取れる
- **TS型検査ゲートが検出した既存バグを修正**: (1) `with Css` の `to_css` 戻り値のvoid誤判定 (2) `char` の既定値が `""`（数値表現と不一致）だったのを `0` に (3) fat pointerの間接参照・書き込みをインライン展開から `__cm_deref`/`__cm_deref_set` ランタイムヘルパーへ集約 (4) panic/exitのIIFEが値を返さずvoid型不一致になっていたのを修正。いずれもJS出力にも潜在していた
- **テスト**: `tests/ts/`（`make test-ts`）を新設。焦点テスト（型注釈・tsc型検査・実行。React/Node fixtureのFFI・構造体配列・undefinedを含む）に加え、`tests/common` + `tests/js` の全コーパス（JS受理の410プログラム）を `--target=ts` でコンパイルし全て有効なTSを生成することを保証する広域ゲート。CIのToolingジョブへ組込み
- チュートリアル `docs/tutorials/{ja,en}/compiler/js/index.md`（TypeScript出力の節）・`npm-interop.md`（フロントエンド開発の節）を追加
- **`//! platform: ts` ディレクティブに対応**: TSバックエンド向けファイルに `//! platform: ts` を書ける（tsとjsは同一のNode実行系のため相互に等価なプラットフォームとして扱う）
- **フルスタックWebサンプルを追加**: `examples/web-fullstack/` にReact SSR（`react`/`react-dom/server`）+ Express + Postgres（`pg`）でタスク管理アプリを実装。1つの `struct Task` がDB行・APIレスポンス・Reactのpropsすべての型になり、`cm run --target=ts` で実行・`tsc` で型検査が通る（npm install不要のfixtureを同梱）

### JSバックエンド: npmパッケージ連携の確立と関数型フィールドの呼び出し対応

- **`use "パッケージ名" { 宣言 }` によるnpm/Node組み込みモジュール連携をテスト・ドキュメントで正式化**: 構造体はJSオブジェクトとしてフィールド名保持で相互に渡り（変換不要）、関数ポインタ・ラムダはJS関数としてそのまま渡せることを検証した
- **構造体の関数型フィールドをメソッド構文で呼び出せるようになった（`obj.field(args)`）**: JSオブジェクトのメソッド（関数値プロパティ）をCmから自然に起動できる。呼び出し先をメンバPlaceのまま保持して `obj.method(args)` を直接出力するため、**JSのthis束縛が保持される**。native/wasm/jitでも同様に動作する（HirCall::indirect_callee新設、型チェッカのフィールドフォールバック、文字列補間ミニパイプライン対応を含む）
- **LLVMコード生成のバグ修正**: 関数参照代入のSSAショートカットが投影を無視し、`ops.apply = f` のようなフィールド代入で構造体ローカルのスロットが関数値に上書きされてSEGVになっていた問題を修正（native/wasm/jitの関数型フィールドが動作するようになった）
- **JS FFIテスト基盤**: ローカルfixtureパッケージ（`tests/js/ffi/node_modules/cmtestpkg`、npm install不要）を新設し、テストランナーが `NODE_PATH` で解決する。構造体互換・コールバック・メソッドthis束縛・組み込みモジュールの4テストと全バックエンド共通の関数型フィールドテストを追加
- チュートリアル `docs/tutorials/{ja,en}/compiler/js/npm-interop.md` を新設。実装設計は `docs/archive/v0.17.0/01_js_npm_interop.md`、React/TS対応ロードマップは `docs/design/js_interop_roadmap.md`
