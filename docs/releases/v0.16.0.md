# Cm v0.16.0 リリースノート（開発中）

**前バージョン:** v0.15.1

## 🎯 テーマ: SystemVerilogバックエンドの機能充実

### 実装済み機能（サマリー）

言語・エラーハンドリング:

- ✅ **Rust準拠の組み込み `Result<T, E>` / `Option<T>`**（構築・match束縛・`is_ok`/`unwrap`/`expect` 等のメソッド・`?` 演算子によるエラー伝播・未使用Resultの `[must_use]` 静的チェック。実装設計13）
- ✅ **ユニオン型の実行時型判別**: `is` 演算子と match型パターン（`int i => ...`）。JSバックエンドもタグ付き表現へ移行し、構造体同士の変種判別を含め全バックエンドで同一意味論（実装設計12）
- ✅ **std::fs**（ファイルシステム操作。基本API + Result API。Native/JIT）
- ✅ **ランタイムエラーの安全API**: `std::math::checked_div / checked_mod`・配列/スライスの `get(i)` → `Option<T>`。パニック経路と安全APIの対応表をチュートリアルに整備（日英）
- ✅ **式形式match（値を返すmatch）**: 全アームが式本体のmatchを値を返す式として使用可能。関数呼び出しをscrutineeに直接書いても単一評価を保証（一時変数退避プリパス）
- ✅ **文字列補間の静的検査と修正**: スコープ外変数参照のコンパイルエラー化・補間内のResult/Optionメソッド・メソッド/関数呼び出しのゴミ値解消
- ✅ `#[derive(...)]` 属性による自動実装（`with` と等価な別記法・非破壊追加）と自動実装の複雑フィールド型対応（ネスト構造体Hash・配列Eq/Hash）
- ✅ ユニオン型スライスの修正一式（push/読み出しのクラッシュ解消・格納表現の統一）
- ✅ 既知問題の修正一式（WASMのポインタ幅レイアウト統一・ジェネリック複合型sizeof・複数行exportリスト・ペイロード付きenumの関数返却・matchパターン束縛の関数スコープ漏れ・JSの組み込みと同名のユーザー関数（find/map等） ほか）

### 変更履歴

#### CI/CDワークフローの処理を実行可能シェルスクリプトへ分割

- **`.github/workflows/` の全インライン処理を `scripts/ci/` の実行可能シェルスクリプト16本へ分割**: ワークフローYAMLは手順の宣言に徹し、ロジック（LLVM/wasmtime/SVツールのインストール・ビルド・検証・テスト実行+Annotation出力・バージョン整合チェック・配布物構築）はスクリプトに集約。`GITHUB_PATH`等はローカル実行時に/dev/nullへフォールバックし、CIと同じ処理をローカルで再現可能（一覧は scripts/ci/README.md）
- **5ジョブに重複していたLLVMインストールブロックを install_llvm.sh へ統一**（Linux/macOS両対応・--minimalオプション）
- **CIで顕在化したmacosのwasmtimeインストール失敗を修正**: 下記「WASMテストの静かスキップを撲滅」で追加した検証ステップがインストール失敗を正しく検出してジョブを失敗させた。原因は公式install.shがGitHubリリース取得時に共有ランナーのAPIレート制限へ当たること。macOSはbrewでのインストールへ変更し、それでも失敗した場合はnodeのWASIラッパーフォールバックを警告付きで許可（ランナー側の欠落時FAIL化により無検証の緑にはならない）
- ローカル検証: バージョン整合チェック群・ビルド検証・C++フォーマット検査・ベンチマーク（4/4）・バックエンドテスト実行（SVスイート112/112、FAIL Annotation動作確認）をスクリプト経由で実行し全て成功

#### WASMテストの「No WASM runtime」静かスキップを撲滅（CIで391件が無検証だった事故の修正）

- **CIのmacos-15 WASMジョブでwasmtimeインストールが失敗し、391テストが「No WASM runtime」スキップ・合格41件のままジョブが緑で素通りしていた事故を修正**: 並列実行パスがwasmtime専用で、直列パスにのみあったnodeフォールバックが無かったことが原因（起動時チェックはnode存在で通過してしまう）
- **並列パスにnode WASIラッパーのフォールバックを追加**: 共有ラッパーを起動時に一度生成し、wasmtime→node→wasmerの順で実行。wasmtime無し環境でもフルスイート432/436合格（wasmtime実行と同一結果）を確認し、フォールバック時は警告を表示
- **ランタイム欠落の残存経路を全てSKIPからFAILへ変更**（wasm直列/並列・js直列/並列）: 起動時チェック通過後にランタイムが消えた異常事態が無検証の緑になることを構造的に排除
- **CIにwasmtimeインストール検証ステップを追加**: `wasmtime --version` で失敗を即時可視化

#### namespace内の非修飾名解決とfloatリテラル引数のLLVM検証エラーを修正

- **namespace内で定義した構造体・関数を同namespace内から非修飾で参照できない既知の問題を修正**: 型チェッカに現在の名前空間を追跡させ、非修飾の型名（引数/戻り値型・構造体リテラル・ローカル宣言）と関数呼び出しを「現在の名前空間::名前」として内側から外側へ解決する。解決時に型名・呼び出し名を修飾名へ書き換え、HIR/コード生成が一貫した名前を見るようにした（resolve_typedefへの一元化で宣言型と式型の食い違いも防止）
- **floatパラメータへの浮動小数リテラル渡しがLLVM検証エラーになる問題を修正**: `half(3.0)` のdoubleリテラルがfloatへ変換されず "Call parameter type does not match" で実行不能だった。LLVM呼び出し引数の型合わせにfp幅変換（FPTrunc/FPExt）と整数→浮動小数点（SIToFP）を追加
- import_featuresのskip理由を更新: 残る未対応は「exportリスト型モジュールの選択的import抽出」（`import ./mod::{A, f}` のトップレベルエイリアス生成・export選択コピー時の非公開依存関数の同伴）のみで、プリプロセッサのモジュール機能として次バージョン以降
- テスト追加: advanced_modules/namespace_struct_resolution・basic/float_literal_arg（native/JS/WASM確認）

#### 謎スキップの棚卸し — JSポインタ2バグ修正・26テスト有効化・ランタイム欠落のfail-fast化

- **JSバックエンドの構造体フィールドポインタ（`&p.x`）を修正**: Refのフィールド射影が落ちてオブジェクト全体が返り、デリファレンスが `undefined` になっていた。`{__arr: 親オブジェクト, __idx: "フィールド名"}`（文字列キー）で表現し、配列要素ポインタと同一のデリファレンス経路で読み書きできるようにした（ネストフィールド・ポインタ経由も型を辿って対応）
- **JSバックエンドのboxedポインタのデリファレンス欠落を修正**: `int** pp = &p; *pp = &b;` の後の `*p` が「[0]でアンボックス済み」を理由にポインタ解決を省略し、ポインタオブジェクトがそのまま読まれていた（`[object Object]` 出力）。ボックス解除とデリファレンスを区別し、boxed/非boxedとも同じポインタ解決を適用
- **カテゴリ一括skipの棚卸しで26テストを有効化**: pointer/memory/collections/std/allocatorの5カテゴリが理由コメント無しでJS一括skipされており、実測の結果ポインタ15件全て・memory 4件・impl_ptr系4件・asm_no_inline・array_pointer・std_io_import が合格（上記2修正含む）。スキップはvoid*/malloc依存（JSはvoid*を明示エラー）と53bit精度・ptr⇔intキャストの個別テストへ縮小し、全skipファイルに理由を記録（JSスイート: 377→403合格・61→35スキップ・0失敗）
- **テストランナーのランタイム欠落をfail-fast化**: wasmtime等が無い環境でllvm-wasmスイートを実行すると全テストが「No WASM runtime」で静かにスキップされ緑のまま素通りしていた（CIでwasmtimeインストールが失敗した場合に無検証で成功する事故の温床）。suite開始時に必須ランタイム（llvm-wasm: wasmtime/node/wasmer、js: node）を検査し、欠落時は明示エラーで失敗させる
- js/ffi/js_extern_package の期待値欠落スキップに理由（外部パッケージ依存の参考テスト）を記録

#### テスト体系の3層化（unit / regression / integration）とMIRパス単体テストのunit移行

- **テスト分類を3層構成へ再定義**: unit（`tests/unit/`）は単一ビルドオブジェクト（特定の.cpp/.hpp）の単体検証、regression（旧`tests/integration/`→`tests/regression/`へ改名）はプロセス内でコンパイルパイプラインの段階を通すgtest回帰、integrationはリリースビルドされたcmバイナリに対する機能テスト（unified_test_runnerのバックエンドスイート）。CLAUDE.mdのテスト規約・Makefile（`test-regression`、旧`test-integration`はエイリアス）・CIジョブ名（cpp-regression-test）を更新
- **MIR最適化パスの単体テストをunitへ移行**: Cmソースをパイプラインに通す方式から、手組みMIR（フロントエンド・lowering非依存）で各パスの.cppを単体検証する `tests/unit/mir_pass_test.cpp`（19テスト）へ書き換え。パイプライン非依存になったことで、コピー伝播の引数除外に隠れていたGVNの検証も直接可能になった。regression側は最適化パイプライン全体（複数パスの組み合わせ・収束反復）の検証3テストに整理
- **単体テストで判明した実装上の契約を追加記録**: LICMはループヘッダブロック内の不変式のみ巻き上げる（本体ブロックは対象外）、定数ループ展開は「switch [1→本体], otherwise 出口」形のヘッダのみ受理、SimplifyControlFlowはGoto連鎖をブロックマージで完全に潰す（README参照）

#### 最適化パスの単体テスト網羅とインライン化パスの休眠状態の発見

- **全最適化パスの単体テストを整備**: 従来テストが無かったSCCP・GVN・DSE・LICM・定数ループ展開・末尾呼び出し・インライン化・ProgramDCEに単体テストを追加し、既存分（定数畳み込み・DCE・コピー伝播・CFG簡約・パイプライン）とあわせて全パスをカバー（計21テスト）。パス⇔テスト対応表を tests/regression/cases/mir_optimization/README.md に単一情報源として整備
- **インライン化パスが実運用で一度も作動していないことを発見・記録**: 呼び出し先オペランドを旧形式の `Constant(文字列)` として期待するが、現行のMIR loweringは `FunctionRef` を発行するため全呼び出しが対象外（休眠状態）。FunctionRefを認識させる有効化実験では perform_inlining の潜在バグ（デストラクタ実行順序の破壊・メソッドチェーンの誤結果・アロケータのSIGSEGV等）がインタプリタスイートで広範に露出したため差し戻し、休眠状態を固定するテストと既知の問題（マトリクス・README・実装コメント）として記録。native/JIT/WASMの最終コードはLLVM側のインライナが担うため影響は限定的
- **単体テスト対象外のパスは理由を明記**: array_base_extraction（パイプライン未接続の実験的パス）・no_std_checker（検証パス。UEFI/baremetalのエラーテストで統合カバー）・収束管理（インフラ。Fixpointテストで間接カバー）
- テストで確認された実装上の性質も記録: コピー伝播・畳み込みは関数引数を保守的に除外（GVNは単一代入ローカル経由の式のみ対象）、LICMは文移動で削除しない、展開後の旧ループブロックは未到達で残りDCEが除去する

#### バックエンド出力の監査とMIR最適化の強化（恒等式簡約・SV定数畳み込み）

- **バックエンド出力の監査**: native/baremetal（x86）はO3でMIR+LLVM最適化が適用され最適なコード（恒等式除去・定数畳み込み・DCE・mem2reg）を確認。SVの式出力は冗長な全体括弧（`((a+b))`→`a+b`）を除去しつつ、意味論上必要な括弧（`(a+b)*c`・`a-(b-c)`・`(a&256)==0`・`~(a|b)`）を正しく保持することを確認
- **ConstantFoldingに代数的恒等式の簡約を追加**: `x*1`/`1*x`/`x+0`/`0+x`/`x-0`/`x/1`/`x%1`/`x*0`/`x>>0`/`x<<0`/`x|0`/`x^0`/`x&0` をUse/定数へ書き換え（整数型のみ。浮動小数点はNaN・-0.0の意味論があるため対象外。`0/x` はゼロ除算検査を消すため対象外）。O1以上の全バックエンドのMIRレベルで適用される（LLVMを通らないSV/JS/インタプリタにも効く）
- **SVターゲットでO1以上の定数畳み込みを有効化**: 従来はDCE等がHWロジックを消す懸念から全MIR最適化をスキップしており、`2*3+4` のような定数式や `x*1` が生成SVにそのまま残っていた。文数・CFG形状を変えない書き換えのみ行う `fold_terminators=false` モードのConstantFoldingを新設して適用（`c = 32'sd2 * 32'sd3 + 32'sd4` → `c = 32'd10`。O0は従来どおり無変換で後方互換）。DCE/CopyProp等の文除去系パスは引き続き実行しない
- **UEFIの最適化制限を明文化**: UEFIターゲットはBug#13（v0.14.1）回避策としてLLVM最適化パスをスキップしMIR最適化のみ適用されることをバックエンド対応マトリクスの既知の問題に記録
- テスト追加: mir_optimization_test（恒等式13種の網羅・文数/CFG形状保存の契約・浮動小数点の非簡約）、sv_codegen_test（畳み込み適用時の生成SV検証・デフォルト無変換の後方互換）

#### テストランナーの並列実行の競合修正とCI診断改善

- **並列実行時のJS/UEFI/ベアメタルの一時ファイル名衝突を修正**: `js_テスト名_$$.js` はカテゴリ非修飾かつ `$$` が全ワーカー共通の親PIDのため、同名テスト（`basic`・`enum`・`impl_methods` 等11組）が並列実行時に同じファイルを取り合い、他テストのコードを実行して誤ったOutput mismatchになり得た（llvm/wasm/svは修飾済みでjs系のみ取り残されていた）。カテゴリ・`$BASHPID`・`$RANDOM` で修飾して解消
- **並列モードのOutput mismatchで差分を保存・表示**: 従来は出力を破棄して1行のFAILのみで、CIログから原因を特定できなかった（js O0のoperator_compound_assignの単発失敗が調査不能だった教訓）。期待値との `diff -u` を集計時に表示する
- コンパイル成功なのに生成JSが無いケースを空出力のmismatchと区別して明示的なFAILにする防御を追加
- LLVM 18で削除された包括ヘッダ `llvm/Transforms/Vectorize.h` を `__has_include` ガードに変更（LLVM 17は従来どおり）

#### 補間内のスコープ外変数参照をコンパイルエラー化

- **補間プレースホルダ内でスコープ外の変数を参照するとゴミ値（JSではnull）が出力される問題を修正**: 型チェッカが補間内容を検査していなかったため、ブロックを抜けた変数の `{b}` 参照が素通りしていた。プレースホルダの式をパースして識別子参照を現在のスコープで検査し、未定義・スコープ外なら `Undefined variable 'b' in interpolation placeholder '{b}'` のコンパイルエラーを出す（enum名・構造体名・関数名・`Color::Red` 等のパスは対象外、パース不能な内容は従来どおりMIR側に委ねる）
- テスト追加: errors/interp_out_of_scope_var

#### 式形式matchの呼び出しscrutinee誤動作と補間内Result/Optionメソッド未解決を修正

- **式形式matchのscrutineeに関数呼び出しを直接書くと誤った値（ダミー0）を返す問題を修正**: HIRは式形式matchを三項演算子チェーンへ脱糖しscrutineeをアームごとにクローンするが、関数呼び出しはクローン不能でダミー値へフォールバックしていた。型チェック前のASTプリパス（match_hoist）を新設し、呼び出しを含むscrutineeを文直前の一時変数（auto推論）へ退避して単一評価を保証（副作用のある呼び出しも1回だけ評価される）
- 退避は評価回数・タイミングが変わらない位置に限定: while/for条件・`&&`/`||`右辺・三項分岐・matchアーム式本体/ガード・defer/ラムダ本体からは持ち出さない（アーム式本体内のネストmatchは既知の問題として記録し、ブロック形式アームで回避）
- **補間プレースホルダ内のResult/Optionメソッド呼び出し（`{o.unwrap_or(-1)}` 等）が未解決シンボルになる問題を修正**: 補間ミニパイプラインではオブジェクト型がMIRローカル型名（`__TaggedUnion_Option` 等）で渡りHIRメソッド脱糖の判定を素通りしていた。基底enum名への正規化と、prelude宣言を持たないミニパイプラインでも成立する `enum_values_` タグキーによる判定へ変更。あわせてMIRのlet型変換で失われていた型引数を保持し、`unwrap_or` はフォールバック引数の型からペイロード型を復元

- **構造体同士のユニオン（`typedef Shape = Circle | Rect`）のミスコンパイルを修正**: 構築時に構造体のポインタがペイロードへ格納されゴミ値になっていた。原因は2点: (1) typedefユニオンは変種を `UnionType::variants` に保持するが構築コードは `type_args` のみ参照しタグ判定が全滅、(2) 構造体値はLLVMレベルでポインタで届くためLLVM型での変種照合が不可能。HIR型（kind+構造体名）での照合と、ポインタ経由memcpyでのペイロード格納を実装

- **`as` にタグ検査を追加**: ユニオンから誤った型で取り出すと「invalid union cast: active variant does not match target type」の実行時パニックで停止する（従来はタグ検査なしでSIGSEGV）
- **固定長構造体配列→スライス変換（`Point[] s = arr;`）のSIGBUSを修正 + スライス要素の補間直接参照 `{s[i].x}` のゴミ値を修正**: 構造体スライスの格納表現を「要素ポインタ」から「blob（値のインラインコピー）」へ統一（ユニオンと同方式）。push後に元変数を変更してもスライス内容が変わらない値セマンティクスになった
- **スライスへのインデックス書き込み（`xs[1] = v`）のSIGBUSを修正**: CmSlice*への直接GEPになっていた書き込みを要素ポインタ経由のデリファレンス格納へ正規化（テスト空白地帯だった）
- **構造体メンバのスライス修正**: メンバ経由のユニオン/構造体スライスでpush関数の誤選択・`h.vs = []` の要素型がint既定に落ちる問題・構造体フィールドのスライス自動初期化の要素サイズ誤りを修正
- スライス要素サイズの計算を `layout_size`（LLVMのDataLayoutと一致するCレイアウト計算）へ統一（MIR 4箇所 + LLVM codegen 2箇所）
- JSバックエンド: blob pushの参照形式を両対応に修正（ユニオン等のboxed値は `{__arr, __idx}`、構造体ローカルの `&` はオブジェクト直接参照で届くため）。JSのユニオンはタグを持たないため `as` のタグ検査はLLVM系のみ（union_cast_mismatch はjsをskip・理由記録済み）
- テスト追加14件: slice_index_write / slice_elem_types（double/string/long/bool/char） / slice_struct_blob / slice_from_struct_array / slice_member_types / union_of_structs / union_println_interp / typedef_alias_slice / errors/union_cast_mismatch ほか
- deriveテストの整理: 組み込みインターフェース（Eq/Ord等）は暗黙的に利用可能なため、テスト内の冗長なinterface宣言を削除
