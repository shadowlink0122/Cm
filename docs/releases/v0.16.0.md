### 変更履歴

#### 2026-07-13: Rust準拠のResult/Optionエラーハンドリングを実装（実装設計13）

- **`Result<T, E>` / `Option<T>` を言語組み込み型に**: preludeとして実enum宣言をプログラムへ注入し、TypeChecker専用の疑似登録を廃止。構築（`Result::Ok(v)`/`Option::None`等）・関数返却・match（ペイロード束縛）・引数渡しが全パイプラインで動作する（ユーザーが同名enumを定義した場合はそちらが優先）
- **Rust準拠メソッドを実装**: `is_ok/is_err/is_some/is_none/unwrap/unwrap_or/unwrap_err/expect`。HIRでタグ比較・ペイロード取り出し・panicへ脱糖。`unwrap()` はErr/Noneで「panic: <メッセージ>」を出力して異常終了（全バックエンド共通）
- **`?` 演算子（エラー伝播）を実装**: `expr?` はOk/Someならペイロード、Err/Noneなら現在の関数からそのまま早期return。MIRレベルの降下のためJIT/native/JS/WASMで共通動作。三項演算子とは先読みで区別。Result/Option以外への適用・戻り値型不一致はコンパイルエラー
- **must_use静的チェックを追加**: Result値を文として捨てると `[must_use]` 警告（Rustのunused_must_use相当）。あわせて警告の表示ラベルがソースマップ経由で常に「error:」になっていた問題を修正
- **根本バグ修正3件**: (1) ペイロード付き非ジェネリックenumが一律int解決され関数返却でペイロード喪失（enum/multi_field_extractが正常動作になり正常系テストへ変換）、(2) モノモーフィズドenum名（`Result__int__string`）が同レイアウト別ID構造体へフォールバックし型分裂、(3) `match (f())` のようなクローン不能scrutineeの直接matchが誤マッチ・ダミー値になる問題（一時変数束縛で修正）
- **panicランタイム整備**: 呼び出しを `__cm_panic` へ正規化（wasmのsignature mismatch防止）、WASMランタイムに `panic` 追加、JSにpanicビルトイン追加
- テスト追加: types/result_option_basic・types/result_try_operator（JIT/native/JS/WASM確認）、errors/result_try_non_result
- チュートリアル: types/enums（日英）のResult/Option節を組み込み型・メソッド・`?`・must_useに全面改訂。設計doc13を作成

#### 2026-07-12: ユニオン型の実行時型判別（`is` 演算子・match型パターン）を実装（実装設計12）

- **`is` 演算子を追加**: `expr is Type` はユニオン値のアクティブな変種が `Type` かどうかをboolで返す（LLVM系はタグ比較、JSはtypeof判定）。非ユニオン値への適用・変種にない型の指定はコンパイルエラー
- **matchの型パターンを追加**: `match (v) { int i => ..., string s => ... }` の `型名 束縛名` パターンで実行時タグを判別し、ペイロードを束縛名に束縛する（`is` 検査 + `as` 取り出しへの脱糖。式形式・ブロック形式・名前付き構造体型に対応）
- **ユニオン変数の初期化・再代入がタグを書かない問題を修正**: `Value v = 42;` や `v = "str";` が生の値storeになりタグ未設定だった（O3の定数畳み込みで隠れており、O0では `as` がパニック・`is` が誤判定・`{v}` 補間が `<?>` になっていた）。let初期化・代入式の両方でユニオン構築Cast（タグ+ペイロード書き込み）を経由するよう修正
- **MIRレベルの実装**: `HirCast`/`MirRvalue::CastData` に `check_only` を追加し、`is` をタグ比較のboolとして降下。`ptr[i]` 補間テンポラリのポインタ型誤導出（wasm32で4バイトallocaへの8バイトstoreというUB）も修正
- テスト追加: types/union_is・types/union_match_type（JIT/native/JS/WASMで確認）、errors/union_is_non_union・errors/union_is_invalid_variant
- チュートリアル: typedef（日英）に「実行時型判別」節を追加。VSCode拡張に `is` キーワードを追加

#### 2026-07-12: 既知問題の修正（WASMレイアウト・複数行export・ジェネリックsizeof）

- **WASMのネストVec（`Vector<Vector<int>>`）のlen()破壊を修正**: 原因は2点: (1) LLVMコード生成のポインタ演算要素サイズが構造体名パターンのハードコード推定（Vector→16等）でwasm32の実レイアウト（ポインタ4バイト）とずれていた → DataLayoutの実サイズ（`getTypeAllocSize`）に統一、(2) HIR/MIR/モノモーフィゼーションの型サイズ計算がポインタ=8バイト固定 → ターゲット依存のポインタ幅（`target_pointer_size`、wasm32/baremetal-armは4）を導入。common/collections/nested_vector_lifecycle_test のskipを解除
- **ジェネリック複合型の `__sizeof__(QueueNode<T>)` がHIR時点の推定値で定数化される問題を修正**: T=longや構造体Tで実レイアウトを下回るmalloc（下回り確保→隣接ヒープ破壊）になっていた。複合ジェネリック型のsizeofもマーカー化し、モノモーフィゼーション時に置換後フィールドの自然アライメントレイアウトで確定させる方式に変更。あわせてモノ特殊化のサイズ計算（従来はフィールド数×8）も自然アライメントレイアウトに修正
- **WASMのO3で配列ポインタキャスト後の読み出しが0になる問題が上記レイアウト統一で解消**: common/memory/array_ptr_cast のO3 skipを解除（O0・ネイティブ・WASM全レベルで期待値一致）
- **複数行の `export { A,\n B };` ブロックがパーサに生のexportとして届き構文エラーになる問題を修正**: 行単位のexport処理4関数（process_export_syntax / filter_exports / extract_reexports / extract_exported_blocks）の入口で複数行ブロックを1行へ正規化。あわせてexportリスト再配置の2バグ（移動した複数行定義の本体重複出力・構造体定義の開始行誤記録による欠落/切詰め）を修正し、リスト掲載定義に `export` を付与して名前空間外からの参照を可能にした
- **大文字の名前空間エイリアス（`import ./mod as M; M::f()`）のシンボル不一致を修正**: 大文字始まり=構造体静的メソッドの一律変換をやめ、既知の構造体/enum名のときのみ `M::f` → `M__f` 変換するよう判定を修正
- **wasm32のsizeof出力**: `sizeof(int*)` 等がwasm32で4になるため、common/types/sizeof・typeof にwasm用サイドカーexpectを追加
- 回帰テスト追加: advanced_modules/multiline_export（複数行exportリスト・複数行選択的import・大文字エイリアス、全バックエンド）
- import_features のskip理由を実態（名前空間内構造体型の解決・exportリスト型モジュールの選択的抽出の未対応）に更新し、バックエンド対応マトリクスの既知の問題を整理

#### 2026-07-12: 補間内メソッド/関数呼び出しのゴミ値を修正（ミニパイプライン戻り型解決）

- **補間内の関数引数付きメソッド呼び出し（`{xs.some(fn)}` 等）のゴミ値を修正**: 従来は未対応パターン扱いで未初期化テンポラリが渡されていた。呼び出しを含む補間内容を本物の式パーサ（Lexer→Parser→HirLowering）で降下する経路に接続し、関数名を関数参照として解決するようにした（固定長配列・スライス共通。JIT/native/JS/WASMの4系統で確認）
- **文字列/float返却メソッドの補間直接呼び出し（`{r.label(n)}` `{r.ratio(3)}`）のゴミ値を修正**: 非ジェネリックなimplメソッドが `hir_functions` に未登録のため補間ミニパイプラインの戻り型解決が失敗し、int扱いで文字列ポインタやfloatビットパターンが数値表示されていた。implメソッドをマングル名（`Type__method`）で関数loweringの事前パスに登録し、戻り型の末尾一致探索をマングル境界（`__`・`::`）必須に強化した（`budget` が `get` に誤マッチする類の防止）
- 自動実装メソッド（`{p.debug()}` 等）は従来どおり専用経路で整形される（ネスト構造体の再帰展開を含む挙動を維持）
- チュートリアルの「変数に受けてから補間する」注意書きを撤去（日英4ページ）、バックエンド対応マトリクスの既知の問題から削除
- 回帰テスト追加: tests/common/basic/interp_method_call（スライス/固定長×関数引数付きメソッド、ネスト関数呼び出し、文字列/float返却メソッド）

#### 2026-07-12: 配列/スライスメソッドの網羅監査（sortBy/forEach修正・チュートリアル全面改訂・網羅テスト）

- **メソッド実装の監査**: 公開APIとして案内している全メソッド（size/len/length・dim・indexOf・includes/contains・find・findIndex・some・every・map・filter・reduce・forEach・sort・sortBy・reverse・first/last・部分スライス、スライス専用のpush/pop/remove/delete/clear/cap/capacity）が固定長配列・スライスの両受け手で動作することを4バックエンド（JIT/native/JS/WASM）で確認
- **`sortBy` のスライス対応**: 固定長専用ゲートにより意味不明なJITシンボルエラーになっていた（サイズ-1番兵方式で共通化）
- **`forEach` の修正**: HIRが無サフィックス名（`__builtin_array_forEach`）を発行しランタイムに存在せず、全バックエンドでシンボルエラーだった（テスト空白による未発覚。i32/i64サフィックス選択を追加、JSバックエンドにもマッピング追加）
- **チュートリアル全面改訂（日英4ページ）**: basics/arrays と advanced/slices を現行実装準拠に書き直し。メソッド一覧表を新設し、旧構文（`|x|` ラムダ・`println("{}", x)`・`{1,2,3}` 波括弧初期化・`Point(1,2)` コンストラクタ形式）を実構文へ修正。slices側は破損していたコード例（受け手行の欠落）を復元し、作成・書き込み・スライス専用メソッド・ユニオンスライスの節を追加
- **網羅テスト追加**: array/array_methods_matrix（固定長×全メソッド）・dynamic_array/slice_methods_matrix（スライス×全メソッド+部分スライス）。JSは容量セマンティクス差分（capacity非保持）のため slice側に `.expect.js` サイドカーを使用
- 既知の制限の明確化: 補間内のメソッド直接呼び出し（`{xs.some(fn)}` や同一文字列内の複数メソッド呼び出し）はミニパイプライン制限のため変数経由を案内（チュートリアルにも記載）

#### 2026-07-12: 可変長スライスの高階関数対応・run --targetディスパッチ・JSユニオン検査

- **可変長スライスへの高階関数（map/filter/reduce/some/every/find/findIndex/indexOf/includes/forEach）を修正**: 従来はHIRが `array_size.value_or(0)` でサイズ0を埋め込み、サイレントに空結果を返していた。スライスはデータ引数にCmSlice*そのもの+サイズ-1（番兵）を渡し、ランタイム側で展開する方式に変更（HIR 15箇所を共通ヘルパー化、native/wasmランタイム計37+32関数に展開処理を追加）。JIT/native/JS/WASMの4系統で同一結果を確認
- **ビルド依存の修正**: `cm_runtime.o` の依存が `runtime.c` のみで、includeされる実体（runtime_slice.c等）の変更が再ビルドされない問題をCMakeのDEPENDS追加で修正（ランタイム修正が反映されない原因だった）
- **`cm run` の `--target` ディスパッチを実装**: 従来は--targetを無視して常にJIT実行していた（`--target=js` でもネイティブ意味論で実行され誤解を招く）。js/webはJS生成+Node.js実行、wasm/svは実行手順を案内する明示エラーに変更
- **JSバックエンド: ユニオンからの `as` 取り出しにtypeof検査を追加**: 誤った型での取り出しは「invalid union cast」メッセージ+exit(1)で停止（LLVM系のタグ検査と同等の失敗動作）。union_cast_mismatch のjsスキップを解除。構造体同士など同typeofの変種は判別不能のため無検査（既知の問題に記録）
- テスト追加: dynamic_array/slice_higher_order（スライスHOF 9種+long要素、全バックエンド）
- 既知の問題の整理: 補間内の関数引数付きメソッド呼び出し（`{xs.some(fn)}`）のゴミ値は固定長配列でも発生する補間ミニパイプラインの既存制限と判明（スライス起因ではない。`{p.debug()}` 系課題として記録）

#### 2026-07-12: ユニオン・構造体スライスの既知問題5件の修正とタグ検査付きas

- **構造体同士のユニオン（`typedef Shape = Circle | Rect`）のミスコンパイルを修正**: 構築時に構造体のポインタがペイロードへ格納されゴミ値になっていた。原因は2点: (1) typedefユニオンは変種を `UnionType::variants` に保持するが構築コードは `type_args` のみ参照しタグ判定が全滅、(2) 構造体値はLLVMレベルでポインタで届くためLLVM型での変種照合が不可能。HIR型（kind+構造体名）での照合と、ポインタ経由memcpyでのペイロード格納を実装
- **ユニオン値のprintln補間が空になる問題を修正**: `{v}` は実行時タグで分岐し、有効なバリアントの値として整形される（`v=42` / `v=hello`）。構造体バリアントは `<struct>`、不正タグは `<?>` を表示
- **`as` にタグ検査を追加**: ユニオンから誤った型で取り出すと「invalid union cast: active variant does not match target type」の実行時パニックで停止する（従来はタグ検査なしでSIGSEGV）
- **固定長構造体配列→スライス変換（`Point[] s = arr;`）のSIGBUSを修正 + スライス要素の補間直接参照 `{s[i].x}` のゴミ値を修正**: 構造体スライスの格納表現を「要素ポインタ」から「blob（値のインラインコピー）」へ統一（ユニオンと同方式）。push後に元変数を変更してもスライス内容が変わらない値セマンティクスになった
- **スライスへのインデックス書き込み（`xs[1] = v`）のSIGBUSを修正**: CmSlice*への直接GEPになっていた書き込みを要素ポインタ経由のデリファレンス格納へ正規化（テスト空白地帯だった）
- **構造体メンバのスライス修正**: メンバ経由のユニオン/構造体スライスでpush関数の誤選択・`h.vs = []` の要素型がint既定に落ちる問題・構造体フィールドのスライス自動初期化の要素サイズ誤りを修正
- スライス要素サイズの計算を `layout_size`（LLVMのDataLayoutと一致するCレイアウト計算）へ統一（MIR 4箇所 + LLVM codegen 2箇所）
- JSバックエンド: blob pushの参照形式を両対応に修正（ユニオン等のboxed値は `{__arr, __idx}`、構造体ローカルの `&` はオブジェクト直接参照で届くため）。JSのユニオンはタグを持たないため `as` のタグ検査はLLVM系のみ（union_cast_mismatch はjsをskip・理由記録済み）
- テスト追加14件: slice_index_write / slice_elem_types（double/string/long/bool/char） / slice_struct_blob / slice_from_struct_array / slice_member_types / union_of_structs / union_println_interp / typedef_alias_slice / errors/union_cast_mismatch ほか
- deriveテストの整理: 組み込みインターフェース（Eq/Ord等）は暗黙的に利用可能なため、テスト内の冗長なinterface宣言を削除
- **既知の問題（未修正・根本原因特定済み）**: 固定長配列以外（可変長スライス）への高階関数（map/filter/reduce/some/every等）はサイレントに空結果を返す。原因はHIR loweringが `array_size.value_or(0)` でサイズ0を埋め込むため。修正案（サイズ引数-1番兵+ランタイム側でのCmSlice*展開）を設計済み。あわせてチュートリアルのreduce引数順（正: `.reduce(fn, init)`）とラムダ引数の型注釈必須も要修正

#### 2026-07-11: `#[derive]` 属性・自動実装の複雑フィールド対応・ユニオン型スライス修正（実装設計10）

- **`#[derive(INTERFACE, ...)]` 属性を追加**: `struct Point with Eq` と `#[derive(Eq)] struct Point` は完全に同一の機能（記法のみの違い）。複数derive属性のマージ・withとの併用（union）に対応。既存の `with` は無変更で有効（破壊的変更なし）
- **検証の強化（with / derive共通）**: 導出可能セットは組み込み8種（Eq/Ord/Copy/Clone/Hash/Debug/Display/Css）に限定し、未知の名前・セット外のユーザー定義interface・重複指定・enumへの付与・引数なし `#[derive]` を明示エラー化。従来はセット外のinterfaceを `with` に書くとメソッド合成なしに「実装済み」扱いになる穴があった
- **自動実装ジェネレータの複雑フィールド型対応**: Hash×ネスト構造体（`Field__hash` の再帰呼び出し）、Eq×固定長1次元配列（要素ごと比較）、Hash×整数系1次元配列（要素混合）を実装。従来は不正なLLVM IR（集約への icmp / xor 等）を生成しJIT実行時に失敗していた
- **未対応の組み合わせを明示エラー化**: Hash×string/float/ポインタ、Ord/Debug/Display×配列、多次元配列・動的スライス・ユニオン型フィールド等は「不正なコード生成」ではなくコンパイルエラーになる（対応表は設計10参照）
- **ユニオン型スライスのバグ修正一式**:
  - `cm_slice_push_blob` のLLVM宣言が到達不能で `void()` シグネチャになりABIが壊れていた（pushで即クラッシュ）
