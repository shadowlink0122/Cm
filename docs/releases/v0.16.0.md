# Cm v0.16.0 リリースノート（開発中）

**前バージョン:** v0.15.1

## 🎯 テーマ: SystemVerilogバックエンドの機能充実

計画の詳細は [v0.16.0 SVバックエンド拡充ロードマップ](../design/v0.16.0/roadmap.html) を参照。

### 実装済み機能（サマリー）

- ✅ モジュールパラメータ `#[sv::parameter]`（`#(parameter WIDTH=8)`・記号幅
  `[WIDTH-1:0]`・階層でのstructリテラル上書き `#(.WIDTH(16))`）
- ✅ `#[sv::pin]` + `--emit-constraints`（Gowin .cst / .tcl の自動生成、
  `//! sv: device/option` ディレクティブ）
- ✅ トライステート `#[sv::tri]`（inout tri + 'z駆動）と
  CDC同期 `#[sv::sync]`（async_reg付き2FF）
- ✅ ビットスライス `x[hi:lo]` / `x[base +: w]`（読み書き、全バックエンド同一意味論）
- ✅ don't careビットマッチ `0b1?00`（matchパターン）と SVの `unique case` 出力
- ✅ 非サポート機能の明示エラー化（浮動小数点 SV004・動的配列 SV006 を追加。
  従来は静かに壊れたSVを出力していた）
- ✅ 回路検証フレームワーク Layer 1（`#[sv::testbench]` サイクル精度TB関数・
  `step`/`assert`/`SIM_FAIL_EXPECTED`。Layer 2 のJITゴールデン照合は設計済み）

### 未実装（次バージョン以降・ロードマップ参照）

- インスタンス配列 / パラメータ幅メモリ `bit[W][D]` / デュアルポートBRAM推論（A5/A6）
- WIDTH系lint警告の解消と `--sv-strict-lint` のデフォルト化（B4）
- casezの直接出力（現状はif-else脱糖で意味論同等）・SVA `assert property`

### 変更履歴

#### 2026-07-08: レビュー指摘5件の修正

- **スカラーbitのビットスライス幅検査**: `bit x;` への `x[3:0]` が
  型エラーにならなかった。スカラーbitは幅1として扱い `[0:0]` のみ許可
  （パートセレクトも幅1のみ）。エラーテスト追加
- **診断ルールID抽出の誤爆修正**: メッセージ中の任意の `[...]`
  （`[0:0]` や配列型表記等）がlintルールIDと誤認され、エラーが警告へ
  降格されていた。抽出を「メッセージ末尾の英字1-3字+数字2-4桁」に限定
- **.tclのadd_file引用**: 出力パスに空白が含まれるとGowinのTclが
  解釈に失敗するため、`add_file {path}` とbracesで囲むよう修正
  （空白入りパスで生成確認済み）
- **step(n)の引数型検査**: `step("x")` 等の非整数引数を型エラーに
- **JSバックエンドの64bitビット演算**: `>> << & | ^` がJSの32bit
  ビット演算子で壊れていた（シフト量が mod 32 になる等。-O0 の
  common/basic/bitslice で顕在化）。long/ulong型のビット演算を
  BigInt（`BigInt.asIntN/asUintN(64, ...)`）で行うよう修正。
  精度はNumberの53bitに制限される点は従来どおり
- **types.mdの注記修正（en）**: `#[sv::parameter] const` で module
  parameter が生成されるようになったため「parameter is never
  generated」の記述を更新し、余分な括弧を除去

#### 2026-07-08: -D 条件付きコンパイル定義とバージョン整合

- **`-D <NAME>` / `-DNAME` / `--define=NAME`**: `#ifdef` 用のユーザ定義を
  CLIから追加可能に（check/lint系と run/compile系の両経路）。
  実回路のテスト（`#ifdef SIM` によるクロック注入・タイミング短縮）を
  想定した機能で、CmCPUの全6回路テスト（`make test`）で実証済み
- VSCode拡張のバージョンを 0.16.0 に同期
- チュートリアル: sv/state-sim に「実回路のテストパターン（-D SIM）」を追加（日英）

#### 2026-07-07: don't careビットマッチと unique case（実装設計04・4.2）

- **`0b1?00` don't careリテラル**: matchパターン専用のマスク付き2進リテラル。
  `?` のビットは比較されない（命令デコーダ等のビットパターン分岐）。
  `(op & mask) == value` のif-elseチェーンに脱糖され全バックエンド同一意味論
- **SVの `unique case` 出力**: match（網羅性検査済み）/switch（default生成）の
  case出力を `unique case` に変更。シミュレーション時の重複ヒット検出が
  無償で得られる（iverilogは無視・verilator対応）
- 付随修正: 文字列補間内の関数引数で `0b` 2進リテラルが0と解釈される
  既存バグを修正
- テスト: common/match/masked_pattern（全実行系）+
  sv/control/masked_match（4ケースのシミュレーション）。SVスイート99件
- チュートリアル: sv/control-flow に節を追加（日英）
- VSCode拡張: 2進リテラルの `?` をハイライトに追加
- 設計04の残り（casezの直接出力）は将来最適化として記録
  （現状のif-else脱糖でも意味論・合成とも正しい）

#### 2026-07-07: ビットスライス構文（実装設計04・4.1）

- **`x[hi:lo]`**（SV流・降順・両端含む定数範囲）と **`x[base +: width]`**
  （インデックスドパートセレクト、基点は任意の整数式）の読み書きに対応
- 対象は `bit[N]` と整数型。結果型は `bit[w]`（整数との相互代入可）。
  書き込みは read-modify-write（`x = (x & ~(mask<<lo)) | ((v&mask)<<lo)`）に脱糖
- **全バックエンド共通のシフト+マスク脱糖**（HIRレベル）のため、
  JIT/native/WASM/JS/SV すべてで同一意味論（SVへの `[hi:lo]` 直接出力は
  将来最適化として設計文書に記録）
- 制限（v0.16.0時点）: 範囲・幅は整数リテラル、最大64ビット
- lexer: `+:` トークン追加。checker: bit[N]⇔整数の代入互換を追加
- テスト: common/basic/bitslice（全実行系で5ケース）+
  sv/basic/bitslice（シミュレーション）。SVスイート98件
- チュートリアル: sv/data と basics/operators に節を追加（日英）
- VSCode拡張: `+:` 演算子ハイライトを追加
- 未実装（設計04の残り）: `0b1?00` don't careリテラルと casez / unique case 写像

- パーサ: 型サイズの識別子参照（`bit[WIDTH]`）をグローバル宣言の

#### 2026-07-07: 実機I/O機能（実装設計02・03）

- **`#[sv::pin]` 属性と `--emit-constraints`**: 物理ピン割り当てをポート宣言に
  同居させ、Gowin向け `.cst`（IO_LOC/IO_PORT）と `.tcl`（プロジェクトスクリプト）を
  生成。`//! sv: device:` / `//! sv: option:` ディレクティブでデバイス型番と
  合成オプションを指定。未知の `key: value` は大文字化して素通し
  （ツール固有属性対応）。ピン未指定ポートの警告つき。生成はオプトイン
- **`#[sv::tri(oe:, out:)]`**: トライステート駆動の生成
  （`inout tri` ポート + `assign ... : 1'bz`）。I2C等の双方向バス対応
- **`#[sv::sync(clk:, src:, stages:)]`**: CDC 2FF同期段の宣言的生成
  （`(* async_reg = "true" *)` 属性付き、段数指定可）
- パーサ: 属性の名前付き引数（`key: value`）と整数リテラル引数に対応
- テスト: sv_codegen_test に Tristate / CdcSync を追加（計87件）
- チュートリアル: [実機I/O](../tutorials/ja/compiler/sv/board-io.html) を新設（日英）
- VSCode拡張: 変更なし（`#[sv::pin]` 等は既存の属性ルールでハイライト済み）
