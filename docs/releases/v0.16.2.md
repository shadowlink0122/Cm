# Cm v0.16.2 リリースノート（開発中）

**前バージョン:** v0.16.1

## 🎯 テーマ: v0.16.1のバグ修正

## ✨ 改善

### cm fmt: 最大行幅を超える宣言・式の折り返し

- **100桁（C++側 .clang-format の ColumnLimit と同じ）を超える行を自動で折り返す**: カンマ位置（配列リテラル・引数リスト等）を優先し、なければ二項演算子の直前で折り返す（継続行が演算子で始まる既存の手書きスタイルに一致）
- **括弧グループ内の要素で折り返す場合は全要素を1行ずつに展開する**: importリスト（`{}`）・配列リテラル（`[]`）・関数の引数/パラメータリスト（`()`）は開き括弧で改行・1要素1行・閉じ括弧を独立行にし、中途半端な貪欲詰めにしない
- **折り返し位置はより浅い括弧深さの候補を優先する**: 深い位置のカンマで呼び出しの途中を折るより、浅い演算子位置で折る（同深さならカンマ優先）
- 折り返しは配列や構造体に限らず、長い式・宣言全般が対象。継続行のインデントはインデント正規化と同じ規則（1段深く）で整える
- コメントだけで幅超過する行・文字列リテラル内・複数行文字列（バッククォート）は折り返さない
- 回帰テスト追加: `tests/regression/cases/formatter/wrap/`（配列・式の折り返し、コメント超過・文字列リテラルの非対象、冪等性）

### SVモジュールIOの明示的構造体宣言（IOインスタンス）

- **モジュールのIOをC/C++スタイルの構造体宣言とそのインスタンスで定義できるようになった**: `struct AluIo { #[input] uint a; #[output] uint result = 0; }; AluIo io;` — フィールドがそのままモジュールポートへ展開され、個別のポート宣言は不要になる
- モジュール内のアクセスは `io.field` で行い、SV出力ではポート名へフラット化される。`#[output]` フィールドの既定値はポートの電源投入時初期値になる
- 構造体宣言のC/C++スタイル末尾セミコロン（`};`）を許容し、IOフィールドの `= 既定値` を許可（従来はextern structのみ）
- `//! sv: hierarchy` のポート抽出はIOインスタンスと直接ポート宣言の両方に対応。IO構造体はデータ型（`typedef struct packed`）としては出力しない
- 個別ポート宣言のみの既存モジュールは従来どおり動作する（後方互換）。実装設計は `docs/design/v0.16.2/01_sv_explicit_io_contract.md`
- `#[test]` 関数内でも `io.field` で参照・駆動でき、テストベンチ生成時にポート名へフラット化される（代入先の入力/出力/内部信号検証も `io.field` 経由で機能）
- 親側のインスタンス接続で `io.field` を値として指定できる（`hier_alu { a: io.x, ... }` → `.a(x)`）
- IOインスタンスのフィールドに付与した `#[sv::pin]` / `iostandard` 属性はピン制約（.cst/.xdc）へ反映される
- テスト追加: `tests/sv/basic/io_instance`（組み合わせ）・`io_instance_clocked`（クロック併用・出力既定値）・`tests/sv/hierarchy/hier_alu`/`hier_top`/`param_shifter` のIOインスタンス移行・回帰テスト `IoInstanceExpandsPortsAndFlattensAccess`

### check/lint --strict: 宣言の命名規則チェック（L001）

- **`cm check --strict` / `cm lint --strict` で全ての宣言の命名規則を検査できるようになった**: 型宣言（struct/enum/interface/typedef）はPascalCase、関数・変数・パラメータ・フィールド・モジュール名はsnake_case、グローバル定数はUPPER_SNAKE_CASE、enumバリアントはPascalCase/UPPER_SNAKE_CASE、camelCaseは全宣言で不許容（世界標準のC/C++/Rust準拠）
- ローカル定数はsnake_case/UPPER_SNAKE_CASEの両方を許容し、先頭アンダースコアは判定前に除去する（`_unused` 許容）
- `extern struct`（ベンダプリミティブ）・`extern "C"` 関数・`self()`/`~self()`・`main`・importでインライン展開される標準ライブラリ名前空間は対象外
- 診断は既存の `L001` naming-convention を使用し、`.cmconfig.yml` の `L001: disabled` や `@cm-disable-next-line L001` で抑止できる。`cm fmt` は整形専任のまま変更なし
- ケース判定を `src/frontend/types/naming_rules.hpp` に分離し、unitテスト（`naming_rules_test`）とlinterスイート（`make test-lint`、--strict有無の検証を含む）を追加。実装設計は `docs/design/v0.16.2/02_naming_convention_check.md`

## 🐛 バグ修正

### JSバックエンド: 定数畳み込みされたchar値の出力が空になる問題を修正

- **`const char c = 'A'` のように定数畳み込みされたchar値の出力で、文字列リテラル `"A"` を `String.fromCharCode()`（数値前提）に渡してNaN→空文字になっていた問題を修正**: 畳み込み済みの文字列リテラルはそのまま使用する

### 定数畳み込み: unsigned型の右シフト・除算・剰余が符号付きで畳み込まれていた問題を修正

- **MIR lowering時の定数畳み込み（try_const_eval）が型を見ずに符号付き演算で畳み込み、`const ulong x = 0x8000000000000000; x >> 63` が 1 ではなく全ビット1になっていた問題を修正**: folding.cppと同じ規則で符号なし型は論理シフト・符号なし除算/剰余を使う。TypeChecker側の型情報を持たない畳み込みは、負に見える値（unsigned定数の可能性）では畳み込みを断念して実行時計算に委ねる

### lint: 追跡の精度改善（誤検出の解消）

- **代入の左辺（`x = 1` / `arr[i] = v` / `p.field = v` / `word[11:4] = v`）を「使用前の未初期化」と誤検出しない**: 書き込み位置の基底変数を初期化済み・変更ありとしてマークする（ビットスライス代入のSliceExprにも対応）
- **`&x`（アドレス取得）はポインタ経由の書き込みがあり得るため変更あり扱いにし、const推奨の誤提案を防止**（二項ビット積との区別あり）
- **`__asm__` の `${制約:変数}` 参照を使用・変更・初期化として追跡**: `=r`/`+r` 制約でasmが書き込む変数への const 推奨・W001 誤検出を解消
- **メソッド呼び出しの受け手を保守的に変更あり・初期化済み扱いに**: selfを変更するメソッドを静的に判別しないため（`v.push(1)` 後の `v` へのconst推奨等を防止）
- **ポインタ型変数はconst推奨の対象外に**: `const T*` はpointee-constを意味し、束縛のconst化を表せないため
- **文字列補間 `{x}` 内の変数参照を使用としてマーク**: W001未使用の大量誤検出を解消
- **for-inループ変数・ラムダパラメータ・グローバル変数を初期化済み扱いに**: 未初期化使用警告の誤検出を解消
- **`cm check/lint -r` の再帰走査から `.tmp` と隠しディレクトリを除外**

### TypeChecker: switch/defer/mustブロック本体が型チェックされていなかった問題を修正

- **switch文のcase本体・defer文・must {} ブロックの中身がTypeCheckerで走査されず、型エラーが素通りし、Lintの使用・変更・初期化追跡からも漏れていた問題を修正**: case内の変数使用が「未使用」、case内で代入される変数が「未変更」と誤判定される原因だった
- 回帰テスト追加: `tests/common/errors/switch_body_type_error`（case内の型エラー検出）

### lint: 未初期化使用警告がグローバル変数へ誤発火していた問題を修正

- **「使用前に初期化されていない可能性」警告が、宣言時に初期化されるグローバル変数・定数（SVの信号・IOインスタンスを含む）に一律発火していた問題を修正**: 初期化追跡は関数境界でリセットされるため、グローバルは対象外にしてローカル変数のフローのみを見るようにした

### lint: 型名L103警告の削除（L001へ一本化）

- **宣言登録時の型名PascalCase警告（L103）を削除**: 名前空間修飾後の名前（`hdmi_out::pll::PLL` 等）やextern struct（ベンダプリミティブ）にも誤発火しており、ルールIDもカタログ上のL103（prefer-iterator）と衝突していた。命名規則チェックは `--strict` のL001に一本化

### check/lint: Lint警告（W001等）が複数ファイルフローで有効になっていなかった問題を修正

- **`cm check` / `cm lint` の実行時に未使用変数警告（W001）等のLint警告フラグが設定されていなかった問題を修正**: linterテストスイート（`make test-lint`）で検出

### get_version: バージョンフォールバックを廃止しCM_VERSION未定義をビルドエラーに変更

- **`get_version()` がCM_VERSION未定義時に古い固定値（0.15.1）へフォールバックしていたのを廃止**: 未定義は `#error` でビルド失敗にし、CMake側でもVERSIONファイルが空の場合は `FATAL_ERROR` で構成を停止する（実バージョンとの乖離を防止）

### プリプロセッサ: export再宣言が行末コメントの ; で切り詰められる問題を修正

- **exportされた複数行宣言（配列初期化子等）の終端検出が、行末コメントや文字列リテラル内の `;` `{` `}` も走査していた問題を修正**: アセンブリ風コメント（`; i = 1` 等）や `"a; b"` のような文字列要素を含むexport配列が先頭行で切り詰められ、import側で構文エラーになっていた（コメント除去に加えて文字列/文字リテラルの中身を空白にマスクして走査する）
- 回帰テスト追加: `tests/sv/import/multiline_export_array.cm`（コメントに `;` `{` を含む複数行export配列のimportと値検証）・`multiline_export_string.cm`（文字列要素に `;` `{` `}` を含むケース）
- あわせて既知の問題に「グローバル配列初期化子がソフトウェア系バックエンドで反映されない」を記録（SVターゲットはinitialブロックとして機能する。バックエンド対応マトリクス参照）

### SVバックエンド: import先モジュール内のextern structインスタンスを修正

- **importされたモジュール内で宣言されたextern structインスタンスが、`hdmi_out::PLL pll_inst (...)` のような名前空間修飾付きの不正なSVを出力していた問題を修正**: 型名の照合と出力の両方で名前空間修飾を除去する
- 発見経緯: CmCPUリポジトリのHDMI回路の汎用モジュール化（Gowinプリミティブのインスタンスを機能トップからimport先の集約モジュールへ移動）で顕在化した
- 回帰テスト追加: `tests/regression/cases/sv/module/namespaced_extern_instance.cm`

### SVバックエンド: 生成コードのインデント崩れを修正

- **`end else if` 行のインデント崩れを修正**: else if正規化（`end else begin` + `if` の結合）がネスト2段目以降の結合行にインデント調整を適用せず、チェーンの2番目以降の `end else if` が1段深くずれていた（例: SimpleCPUの命令ディスパッチ・HDMIテキストのステートマシン）
- **`initial` ブロックのインデント統一**: 配列初期化・`$readmemh` の `initial` ブロックがモジュールインデントなしの0桁で出力されていた。ビルダーを無インデント生成に統一し、出力時にモジュールインデントを一律付与する
- 回帰テスト追加: `tests/regression/cases/sv/control/else_if_chain_indent.cm`（チェーン全行が先頭 `if` と同一インデントであることを検証）
