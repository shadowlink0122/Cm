# Cm v0.16.2 リリースノート（開発中）

**前バージョン:** v0.16.1

## 🎯 テーマ: v0.16.1のバグ修正

## ✨ 改善

### cm fmt: 最大行幅を超える宣言・式の折り返し

- **100桁（C++側 .clang-format の ColumnLimit と同じ）を超える行を自動で折り返す**: カンマ位置（配列リテラル・引数リスト等）を優先し、なければ二項演算子の直前で折り返す（継続行が演算子で始まる既存の手書きスタイルに一致）
- **括弧グループ内の要素で折り返す場合は全要素を1行ずつに展開する**: importリスト（`{}`）・配列リテラル（`[]`）・関数の引数/パラメータリスト（`()`）は開き括弧で改行・1要素1行・閉じ括弧を独立行にし、中途半端な貪欲詰めにしない
- **折り返し位置はより浅い括弧深さの候補を優先する**: 深い位置のカンマで呼び出しの途中を折るより、浅い演算子位置で折る（同深さならカンマ優先）
- 折り返しは配列や構造体に限らず、長い式・宣言全般が対象。継続行のインデントはインデント正規化と同じ規則（1段深く）で整える
- コメントだけで幅超過する行・文字列リテラル内・複数行文字列（バッククォート）は折り返さない
- 回帰テスト追加: `tests/regression/cases/formatter/wrap/`（配列・式の折り返し、コメント超過・文字列リテラルの非対象、冪等性）

### SVモジュールIOの明示的構造体宣言（IOインスタンス）

- **モジュールのIOをC/C++スタイルの構造体宣言とそのインスタンスで定義できるようになった**: `struct AluIo { #[input] uint a; #[output] uint result = 0; }; AluIo io;` — フィールドがそのままモジュールポートへ展開され、個別のポート宣言は不要になる
- モジュール内のアクセスは `io.field` で行い、SV出力ではポート名へフラット化される。`#[output]` フィールドの既定値はポートの電源投入時初期値になる
- 構造体宣言のC/C++スタイル末尾セミコロン（`};`）を許容し、IOフィールドの `= 既定値` を許可（従来はextern structのみ）
- `//! sv: hierarchy` のポート抽出はIOインスタンスと直接ポート宣言の両方に対応。IO構造体はデータ型（`typedef struct packed`）としては出力しない
- 個別ポート宣言のみの既存モジュールは従来どおり動作する（後方互換）。実装設計は `docs/design/v0.16.2/01_sv_explicit_io_contract.md`
- `#[test]` 関数内でも `io.field` で参照・駆動でき、テストベンチ生成時にポート名へフラット化される（代入先の入力/出力/内部信号検証も `io.field` 経由で機能）
- 親側のインスタンス接続で `io.field` を値として指定できる（`hier_alu { a: io.x, ... }` → `.a(x)`）
- IOインスタンスのフィールドに付与した `#[sv::pin]` / `iostandard` 属性はピン制約（.cst/.xdc）へ反映される
- テスト追加: `tests/sv/basic/io_instance`（組み合わせ）・`io_instance_clocked`（クロック併用・出力既定値）・`tests/sv/hierarchy/hier_alu`/`hier_top`/`param_shifter` のIOインスタンス移行・回帰テスト `IoInstanceExpandsPortsAndFlattensAccess`

### コンパイラメッセージの英語デフォルト化と日本語カタログ（i18n）

- **cm CLIの全ユーザー向けメッセージ（help・進捗・診断枠組み・lintルール文言）をデフォルト英語に統一し、日本語もカタログ切替で選択できるようにした**: 従来の英日混在を解消。言語は `--lang=en|ja` > `CM_LANG` 環境変数 > `.cmconfig.yml` の `language:` > 既定en の優先順位で決定する
- `cm help` は英語・日本語の全文を用意し、言語設定に応じて出力する
- 実装はメッセージID方式（enum + string のC++側集約管理）: `src/internal/base/messages/` の `message_ids.hpp`（`enum class MsgId` / `Lang`）と `messages.hpp`（2次元テーブル `kMessages[メッセージ][言語]`、1メッセージ=1行に全言語が並ぶ）に全文面を集約し、`i18n::msg(MsgId)` / `msgf(MsgId, args...)`（`{0}` プレースホルダ置換）で取得する。IDのタイプミスはコンパイルエラー、行の過不足・英語未定義はstatic_assertで検出、訳が無い言語は英語へフォールバックする。help本文のみ `src/cmd/cm/help_{en,ja}.txt` で管理しビルド時に埋め込む。デバッグログ（`-d` 出力）は対象外
- 診断カタログ（E/W/L系テンプレート）・命名規則（L001）・no_stdチェッカー（B001）・SV/JSコード生成の検証メッセージも同カタログへ集約（診断定義はテンプレート本文を持たず `MsgId` を参照する）。文字列連結による断片メッセージは全廃し、語順が異なる言語へも翻訳可能なプレースホルダ形式へ統一
- 既定言語の変更に伴い、ベアメタルエラーテストの期待値（`tests/baremetal/errors/*.error`）を英語メッセージへ更新（**メッセージ文字列に依存する外部スクリプトは追従が必要**）
- 実装設計は `docs/design/v0.16.2/04_message_i18n.md`

### SVモジュール階層化のexport struct + 修飾名方式への移行（//! sv: hierarchy 廃止）

- **相対import先がexportされたIO構造体（方向属性フィールドを持つ `export struct`）を宣言している場合に、そのimportを自動で階層化（別モジュールとしてインスタンス化）するようになった**: `//! sv: hierarchy` ディレクティブは廃止（記述されていても単なるコメントとして無視され、exportされたIO構造体を持たない相対importは従来どおりフラット化される）
- **親モジュールは `<モジュール名>::<IO構造体名>` の修飾名でインスタンス化する**: `alu::AluIo alu0 = alu::AluIo { a: x, ... };` — 型が通常のモジュールシステムで解決されるため、`cm check` / `cm lint` が特別扱いなしで通り、`.cmconfig.yml` の `tests/sv/hierarchy/` 除外を撤廃した
- インターフェース契約として、IO構造体に `#[sv::param]` フィールド（`#[sv::param] uint WIDTH = 8;`）を宣言でき、インスタンス側からの `WIDTH: 16` 上書きが型検査される（`#[sv::parameter] const` からのパラメータ抽出も併用し名前で重複排除）。通常のstructフィールドでも `#[sv::param]` 属性付きなら初期値を許可し、命名規則（L001）はパラメータフィールドにUPPER_SNAKE_CASEを許容する
- **名前空間内グローバル変数の名前衝突を修正**: importされたモジュールのグローバル変数が素の名前で登録され、親側の同名グローバル（`io` 等）と衝突していた問題を修正。名前空間内のグローバルは修飾名（`alu::io`）で登録・降下し、名前空間内の非修飾参照は「現在の名前空間::名前」を優先して解決する（ローカル変数・パラメータは従来どおり最優先）。名前空間外へ複製されたexport関数のヘルパーがモジュール内グローバルを参照する場合は、いずれかの名前空間に一意に一致するグローバルへフォールバック解決する
- **型のみexportするモジュールで非export関数が名前空間外へ複製される問題を修正**: 内部ヘルパー複製（Bug#15対応）はexport関数が存在する場合のみに限定し、モジュール内グローバル変数を参照する関数の複製が名前空間外で解決できず壊れるのを防止
- グローバル変数宣言の型に名前空間修飾型（`mod::Type`）を許可
- テスト移行: `tests/sv/hierarchy/hier_alu`/`hier_top`/`param_shifter`/`param_top` を新方式へ移行（挙動・期待値は不変）。実装設計は `docs/design/v0.16.2/03_sv_hierarchy_export_struct.md`

### check/lint --strict: 宣言の命名規則チェック（L001）

- **`cm check --strict` / `cm lint --strict` で全ての宣言の命名規則を検査できるようになった**: 型宣言（struct/enum/interface/typedef）はPascalCase、関数・変数・パラメータ・フィールド・モジュール名はsnake_case、グローバル定数はUPPER_SNAKE_CASE、enumバリアントはPascalCase/UPPER_SNAKE_CASE、camelCaseは全宣言で不許容（世界標準のC/C++/Rust準拠）
- ローカル定数はsnake_case/UPPER_SNAKE_CASEの両方を許容し、先頭アンダースコアは判定前に除去する（`_unused` 許容）
- `extern struct`（ベンダプリミティブ）・`extern "C"` 関数・`self()`/`~self()`・`main`・importでインライン展開される標準ライブラリ名前空間は対象外
- 診断は既存の `L001` naming-convention を使用し、`.cmconfig.yml` の `L001: disabled` や `@cm-disable-next-line L001` で抑止できる。`cm fmt` は整形専任のまま変更なし
- ケース判定を `src/internal/types/naming_rules.hpp` に分離し、unitテスト（`naming_rules_test`）とlinterスイート（`make test-lint`、--strict有無の検証を含む）を追加。実装設計は `docs/design/v0.16.2/02_naming_convention_check.md`

### lint: .cmconfig.yml の exclude 設定（ディレクトリ走査からの除外）

- **`.cmconfig.yml` の `lint: exclude:` にパスパターンを列挙すると、`cm check/lint -r` のディレクトリ走査から除外できるようになった**: コンパイラのテストコーパス（意図的な違反を含む）やimport専用のモジュール集約dialectを走査対象から外し、`cm lint --strict -r .` を実プロジェクトコードの検査として運用できる
- 明示的なファイル指定・除外パターン配下のディレクトリを直接指定した場合は除外を適用しない（ユーザーの意図を優先。linterフィクスチャの直接検査等はそのまま動く）
- 設定ファイルの読み込みをファイル収集前へ移動

### 型宣言でのSV範囲表記 [msb:lsb] に明確な診断を追加

- **`bit[3:0] x;` のようなSVの範囲表記による型宣言が「Expected ']'」という不親切なパースエラーになっていたのを、要素数表記への誘導メッセージに変更**: スライス式 `x[3:0]` と紛らわしいため型はCmの要素数表記（`bit[4]` → 生成SVは `logic [3:0]`）に統一する設計を明示する。エラーテスト `tests/sv/errors/type_range_notation` を追加

### module文のドット区切りパスを許可

- **`module std.core;` のようなドット区切りのモジュールパスがパースエラーになっていた問題を修正**: `::` と `.` の両方を区切りとして許可（標準ライブラリのモジュール集約ファイルの記法）

### lint: 初期化子のない宣言へのconst推奨を抑止

- **`V default_val;` のような初期化子なし宣言はconst化できないため、const推奨（never modified）の対象から除外**

### 既知の問題（未解決）

- **const string と文字列補間の非互換**: `const string msg = "{x}";` は補間が実行されず生文字列のままになる（非constでは補間される）。constの定数評価パスが補間より先に文字列を確定させるため。回避策: 補間を含むstringはconstにしない
- **ジェネリック構造体の型なしリテラル初期化**: `Pair<int> p = {first: 10};` は「expected Pair<int>, got Pair」で失敗する（フィールド代入方式は動作）。examplesのAVL系2件（priority_queue_generic / priority_queue_task）は実行時SEGFAULTがあり、いずれもv0.16.2以前からの既存問題

### JS: -O0で定数畳み込みされた値の出力が壊れる問題を修正（char・int幅ラップ）

- **MIR loweringの定数畳み込み（try_const_eval）が結果を型幅へ正規化せず、`const int w = INT_MAX + 1` が -2147483648 ではなく 2147483648 と出力されていた問題を修正**: folding.cppと同じ normalize_int を適用（O0では最適化パスの畳み込みが走らないため、lowering側の畳み込みが唯一の経路になり顕在化していた）
- **JSバックエンドのchar型定数が文字列（"A"）として出力され、数値前提の String.fromCharCode がNaNになる問題を修正**: char定数は文字コード（数値）で出力する（ランタイムのchar表現に一致）

### lint: 使用追跡のさらなる精度改善と対象範囲の適正化

- **走査対象の適正化**: `.error`（意図的に失敗するネガティブテスト）/`.skip`（環境依存）が並置された .cm はディレクトリ走査から自動スキップ。check/lintでもコンパイル同様に `#[test]` 宣言を除去し、テスト専用シンボル参照の誤検出を解消。除外はlint自身のテストデータ・gtest回帰ケース・モジュールシステムフィクスチャ等の検証入力のみに縮小
- **追跡漏れの解消**: 関数ポインタ/ラムダ変数経由の呼び出し・全文字列リテラルの補間参照・matchアーム束縛・`&arr[i]`/`&s.field` のアドレス取得基底・sizeof/typeof/__typename__ のメタ参照・コンストラクタ呼び出し宣言（RAII）を正しく使用・変更・初期化として扱う
- **const推奨の適正化**: `_` 始まり（意図的未使用・コンパイラ生成一時変数）と補間プレースホルダ入り文字列リテラル初期化子（const化すると補間されない既知問題）を対象外に
- これらによりテストコーパスを含む `cm lint --strict -r .` 全体（652ファイル）でエラー0・警告0を達成

## 🐛 バグ修正

### VSCode拡張: 文字列内プレースホルダのハイライトを修正

- **単独の `{` が文字列内でハイライトされていた問題を修正**: 従来は `{` から `}` までを式領域として着色していたため、閉じの無い `{` や任意の内容まで対象になっていた。フォーマットプレースホルダ（`{}` と `{:x}` / `{:.2f}` / `{:>10}` 等の書式指定付き）のみを着色するよう変更した（`{{` / `}}` エスケープの扱いは従来通り）

### CI（GCC13/libstdc++）でビルドが失敗する問題を修正

- **標準ヘッダのinclude欠落を全ソースで解消**: `std::vector` 等を使用しながら対応ヘッダをincludeしていない箇所がヘッダ64・cpp 143ファイルにあり、unity buildのTU構成変更で顕在化した。全ファイルを自己完結化し、GCC13での全ヘッダ単独コンパイル検査で確認した
- **静的リンク時のLLVMコンポーネントにARM(32bit)を追加**: ベアメタル（`--target=bm` のthumbv7m）に必須の `LLVMInitializeARM*` が `CM_LLVM_STATIC` / 共有ライブラリ無し環境で未解決になっていた

### Ord導出の <= / >= が等値・非等値で誤った結果になる問題を修正（全バックエンド）

- **`impl for Ord`（`operator <`）からの `<=` / `>=` 自動導出が壊れていた問題を修正**: MIRパスが文リストの `resize()` で破棄した文の中身への参照から演算子種別を読んでおり（use-after-free）、否定が適用されず `a <= b` が `a < b`、`a >= b` が `b < a` として評価されていた。演算子種別を破棄前に退避して修正
- **導出時の引数順も修正**: `a <= b` は `!(b < a)`、`a >= b` は `!(a < b)` が正しいが、否定時の引数入れ替えが逆（Le/Geで交差）だった。HIR→MIR loweringの構造体Ord経路にも同じ引数順の誤りがあり修正
- `tests/common/interface/operator_ord` の期待値を正しい6行（`a <= c: true` を含む）へ更新。従来の期待値は等値時に `<=` がfalseになる誤動作を記録していた

### JSバックエンド: 定数畳み込みされたchar値の出力が空になる問題を修正

### fmt: 長い行の折り返しロジック修正とlintとの走査対象統一

- **1行に詰め込まれた文ブロック（`if (...) { 文; 文; }` 等）が最大行幅を超える場合、演算子折り返しではなくブロック展開（`{` の後・`;` の後・`}` の前で改行）するよう修正**: 従来は `if (n\n != null)` のように条件式の途中で折れて可読性が崩れ、さらに `; }` を含む継続行が次回実行のセミコロン改行で再分割されてフォーマットが崩れていく（冪等でない）原因になっていた
- **展開後もなお長い文には、インデント正規化後の深さを見込んだ幅で演算子折り返しを再帰適用**: 1回の `cm fmt` で固定点に到達し、複数回実行しても結果が変化しないことを保証する
- **`cm fmt -r` のディレクトリ走査に `.cmconfig.yml` の除外設定を適用**: `cm check/lint -r` と走査対象が一致し、フォーマッタ期待値や意図的な部分コードを含むフィクスチャ（`tests/regression/cases/` 等）を書き換えなくなった（明示的なファイル指定は従来どおり除外の影響を受けない）
- 回帰テスト追加: `tests/regression/cases/formatter/wrap/inline_block`（ブロック展開）・`inline_block_else`（`} else {` を同一行に維持）・`inline_block_long_stmt`（展開後の長い文への再帰折り返しと冪等性）
